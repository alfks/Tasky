# Tasky

**감성 투두 · 일정 관리 데스크탑 웹앱.** 날짜 스트립에서 하루를 고르고, 색깔 있는 카테고리 아래
할 일을 적고, 체크할수록 달성률이 차오릅니다.

배포 주소는 **<https://tasky.millie020524.workers.dev/>** 입니다. 배포는 개발자가 로컬에서 수동으로
계속하고 있습니다(GitHub Actions 를 통한 자동 배포는 아직 한 번도 성공한 적이 없습니다). **Worker 는 그
주소에 붙어 있는 것이 확인됐습니다**(`GET /api/me` 가 401 JSON 을 돌려줍니다 — 2026-09-21 확인, 아래
[지금 상태](#지금-상태)) — 다만 지금 배포본이 정확히 어느 버전인지(#129 클라이언트까지 포함하는지)는
여전히 확인하지 못했습니다.

지금 main 에서 만드는 버전은 **구글 로그인이 필수입니다.** 로그인 전에는 로그인 화면만 뜨고, 로그인하면
여러분의 데이터는 서버(Cloudflare D1)에 원본으로 저장되고 브라우저(IndexedDB)에는 오프라인용 사본이
남습니다. 오프라인에서 그대로 쓸 수 있고 PWA 로 설치할 수 있습니다(휴대폰 홈 화면 포함). 어디까지
구현됐고 무엇이 저장되는지는 아래 [여러 기기에서 쓰기](#여러-기기에서-쓰기--동기화)·
[데이터와 프라이버시](#데이터와-프라이버시) 에 있습니다. **다만 지금 배포된 주소가 이 버전(로그인 화면
포함)을 서빙하는지는 [지금 상태](#지금-상태)가 적었듯 여전히 확인하지 못했습니다** — Worker 가 붙어 있는
것은 확인됐지만(`/api/me` 401), 그것이 어느 커밋의 화면을 서빙하는지는 별개입니다. 옛 배포본이 남아
있다면 로그인 없이 쓰던 버전일 수 있습니다.

## 무엇을 할 수 있나

- **날짜 스트립** — 한 주를 가로로 훑으며 하루를 고릅니다. 각 날짜 칸에 그날의 카테고리 색 점과
  전부 끝낸 날의 ✓ 가 붙습니다.
- **카테고리별 할 일** — 12가지 파스텔 색 중에 골라 묶습니다. 추가·수정·삭제·날짜 이동(드래그) 가능.
  카테고리 자체의 순서도 사이드바에서 드래그로 바꿉니다.
- **달성률** — 그날 완료 비율을 링과 숫자로. 카테고리별로도 나눠 봅니다.
- **집중 타이머** — 할 일 하나를 골라 집중 세션을 돌립니다.
- **반복 할 일(루틴)** — 매주·매달 반복을 등록합니다. 종료일 없이 "계속 반복"도 됩니다.
- **D-day 캘린더** — 기다리는 날을 등록하면 남은 날짜를 세어 줍니다.
- **하루 기록(다이어리)** — 그날의 기분을 이모지 하나와 짧은 글로 남깁니다.
- **기간 통계** — 주·월 단위 달성률, 연속 달성 일수, 활동 히트맵.
- **테마** — 라이트/다크 + 강조색. 첫 페인트부터 고른 테마로 뜹니다(깜빡임 없음).
- **커맨드 팔레트** — `Ctrl/⌘ K`. 검색해서 실행하고, 아무것도 안 걸리면 그 문장을 바로 오늘 할 일로 추가합니다.
- **백업 · 복원** — 전체 데이터를 파일로 내보내고 다시 불러옵니다. 로그인 여부와 무관하게 언제나 되는
  여러분의 이사·보험입니다(동기화가 켜진 뒤에도 내보내기는 그대로 남습니다).
- **키보드로 완주** — 추가·체크·수정·삭제·날짜 이동 전부 키보드만으로 됩니다. 한글 조합 중 `Enter` 도 정확히 처리합니다.

## 여러 기기에서 쓰기 — 동기화

> **어디까지 왔나(2026-09-21 기준).** 동기화의 **서버**(Cloudflare Worker + D1 — 구글 로그인, 세션, 변경
> 주고받기, 계정 삭제)와 앱 안쪽의 **저장·병합 규칙**, 그리고 **로그인 화면·사이드바 계정 표시·30초
> 폴링**까지 전부 구현이 끝나 main 에 들어 있습니다 — **main 에서 만든 빌드는 로그인 화면부터 뜹니다.**
> 구글 계정으로 실제로 왕복하는 것은 **아직 검증하지 않았습니다** — 아무도 로그인해 보지 않았습니다.
> 서버 배포 자체는 개발자가 로컬에서 수동으로 계속하고 있고(GitHub Actions 자동 배포는 한 번도 성공한
> 적이 없습니다), **Worker 는 배포 주소에 붙어 있는 것이 확인됐습니다**(`GET /api/me` → 401 JSON,
> 2026-09-21 확인). 다만 **정확히 이 동기화 버전(#129 클라이언트)까지 포함하는지는 여전히 확인하지
> 못했습니다**(아래 [지금 상태](#지금-상태)). 아래는 main 기준 동작이고, 설계는
> [docs/specs/sync.md](./docs/specs/sync.md) · [ADR-0015](./docs/decisions/ADR-0015-google-auth-and-realtime-sync.md) ·
> [ADR-0019](./docs/decisions/ADR-0019-worker-d1-auth.md) 에 있습니다. 배포와 구글 실왕복이 확인되면 이 상자를
> 지웁니다.

- **로그인이 필요합니다.** 동기화가 켜진 버전은 **로그인 화면이 먼저 뜨고**, 로그인 없이 쓰는 모드는 없습니다
  (ADR-0015 의 결정 — 로컬 전용 모드와 계정 모드를 둘 다 유지하지 않기로 했습니다). 구글에는 계정 식별자와
  이메일 주소만 요청합니다(이름·프로필 사진은 요청하지 않습니다). 로그인 전에 이 기기에 있던 데이터는
  말없이 버리지 않고 "올리기" / "내보내고 지우기" 중에 고르게 합니다.
- **무엇이 되나** — 여러 기기(집 컴퓨터, 회사 노트북)에서 같은 할 일을 봅니다. 한쪽에서 체크하면 다른 쪽도
  곧 따라옵니다 — 즉시는 아니고, 앱이 앞으로 나올 때·온라인이 될 때·보이는 동안 주기적으로 맞춥니다.
- **데이터가 어디 있나** — 서버(Cloudflare D1)가 원본이 되고, 브라우저의 IndexedDB 는 오프라인용 사본으로
  남습니다. 앱에서 지운 항목은 "삭제됨" 표시로 서버에 남아 다른 기기에 삭제를 전달합니다.
- **오프라인은 그대로** — 오프라인에서 읽고 씁니다. 쓴 것은 기기에 쌓였다가 온라인이 되면 올라가고, 아직
  서버에 없는 상태는 사이드바 계정 블록에 정직하게 표시합니다.
- **로그인 세션** — 로그아웃하지 않아도 쓰지 않은 채 30일이 지나면 만료됩니다(쓰는 동안은 연장). 쿠키는
  로그인용 하나뿐이고 스크립트가 읽을 수 없습니다.
- **끄는 법과 데이터 가져가기**
  - **내보내기** — 백업 · 복원의 내보내기. 로그인 여부와 무관하게 언제나 됩니다.
  - **로그아웃** — 이 기기의 데이터를 파일로 내보낸 뒤 지웁니다. 서버와 다른 기기의 데이터는 그대로입니다.
    로그인이 필수라 "동기화만 끄고 이 기기에서 계속 쓰기"는 main 기준으로는 없습니다.
  - **계정 삭제** — 서버의 계정 정보·앱 데이터·기기 표식을 한 번에 지웁니다(되돌릴 수 없습니다). 같은 구글
    계정으로 다시 로그인했을 때 지운 계정이 되살아나지 않도록 **계정 식별자와 삭제 시각**만 남깁니다.
    로그인돼 있던 다른 기기는 다음 접속 때 "이 계정은 삭제되었습니다" 안내를 본 뒤 자기 데이터를 내보내고
    지웁니다.
- 무엇을 저장하고 어디에 두는지는 [개인정보처리방침](./public/privacy.html)에 전부 적혀 있습니다
  (배포본: <https://tasky.millie020524.workers.dev/privacy.html>).

## 지금 상태

위 목록의 기능은 다 동작합니다(`pnpm dev` 또는 `pnpm build && pnpm start`). **배포는 개발자가 로컬에서
수동으로 계속하고 있습니다** — GitHub Actions 의 배포 워크플로는 지금까지 한 번도 성공한 적이 없으므로
(124회 전부 실패), 자동 배포는 없습니다. **사용자가 배포 주소에서 직접 확인했습니다(2026-09-21)**:
`GET /api/me` → `{"error":"unauthorized"}`(401 JSON) — Worker 가 붙어 있고 `/api/*` 라우팅이 실환경에서
동작합니다. Worker 는 #126 에서 처음 붙었으므로 배포본은 **#126 이후**입니다. 다만 **정확히 어느
커밋인지(#129 클라이언트까지 포함하는지)는 여전히 확인되지 않았습니다** — `/api/me` 401 은 Worker
존재만 말해 줍니다. 같은 확인에서 `GET /auth/stub-login?sub=x&email=x@y.z` → **not found(404)** —
개발용 로그인 우회(`AUTH_STUB`)가 프로덕션에서 닫혀 있는 것도 확인됐습니다(200/302 였다면 즉시
롤백해야 했습니다). **D1 테이블도 원격에 생성돼 있는 것이 확인됐습니다.** **여전히 미확인**: 구글 로그인
실왕복(아직 아무도 로그인해 보지 않았습니다), 배포본이 정확히 어느 커밋인지(#129 클라이언트까지
포함하는지). Worker 는 새것인데 화면이 옛것으로 보인다면 `scripts/deploy.sh` 가 산출물을 "있는지"만
보고 "최신인지"는 보지 않는 문제일 수 있습니다 — 진단·확인 명령은
[docs/development.md](./docs/development.md) "배포 확인" 절에 있습니다. **동기화는 서버·저장 계층에 이어 화면까지 main 에 들어
있습니다(#129)** — main 을 빌드하면 로그인 화면부터 뜹니다(위
[여러 기기에서 쓰기](#여러-기기에서-쓰기--동기화)). 아래 수치는 #129 머지 직후(2026-09-21) 실측입니다 —
`pnpm test`·`pnpm exec playwright test --list`·`pnpm build` 출력 그대로. **"첫 로드 JS" 의 계측 이름이
바뀌었습니다** — 예전엔 진입 청크(`index.js`) 하나만 쟀지만, 이제는 **진입 폐포(진입 + 정적 위성 청크)
합**을 잽니다 — 아래 값을 옛 "148,976 B / 150,000 B" 와 직접 비교하지 마세요.

| 항목              | 값                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------- |
| 단위 테스트       | **2,946건** (233 파일 — 브라우저 쪽과 Worker 쪽을 한 번에 돌립니다)                             |
| E2E               | Playwright **43건** / 12개 스펙(프로덕션 빌드를 띄워 실행)                                      |

## 직접 배포하기

Cloudflare Workers 의 정적 자산으로 나갑니다. 계정과 API 토큰만 있으면 됩니다.

```bash
pnpm install
cp .env.example .env     # CLOUDFLARE_ACCOUNT_ID · CLOUDFLARE_API_TOKEN 을 채웁니다
                         # 토큰 발급 방법은 .env.example 주석에 단계별로 있습니다

pnpm build
pnpm run deploy:dry-run  # 올라갈 파일 목록만 확인 (자격증명 없이도 됩니다)
pnpm run deploy          # 실제 배포
```

- **`pnpm deploy` 가 아니라 `pnpm run deploy`** 입니다. `deploy` 는 pnpm 내장 명령이라
  그냥 쓰면 이 레포의 배포 스크립트가 아니라 pnpm 의 워크스페이스 배포가 돕니다.
- `.env` 는 `.gitignore` 에 있어 커밋되지 않습니다. 자격증명이 없으면 스크립트가 **조용히 넘어가지 않고
  실패합니다** — "배포한 줄 알았는데 안 된" 상태를 만들지 않으려는 의도입니다.
- **동기화(#126) 이후 실제 배포에는 조건이 하나 늘었습니다(중요).** `pnpm run deploy` 는 (dry-run 이 아닌
  경우) 배포 직전에 `wrangler secret list` 로 Cloudflare Worker 시크릿 `GOOGLE_CLIENT_SECRET`·
  `SESSION_SECRET` 이 이미 올라가 있는지 확인하고, 하나라도 없으면 그 자리에서 멈춥니다. 아직 올리지
  않았다면 먼저 이렇게 올립니다.

  ```bash
  wrangler secret put GOOGLE_CLIENT_SECRET
  wrangler secret put SESSION_SECRET
  ```

  같은 자리에서 `wrangler d1 migrations apply tasky --remote` 도 매 배포마다 돕니다. `pnpm run
deploy:dry-run` 은 네트워크를 타지 않으므로 이 두 단계를 모두 건너뜁니다.

- GitHub Actions 로 배포하려면 같은 이름의 레포 Secrets(`CLOUDFLARE_*`)와 Variable(`DEPLOY_URL`)을 넣습니다.

## 로컬에서 실행

```bash
pnpm install
pnpm dev
```

빌드 결과물을 서비스워커까지 포함해 확인하려면 `pnpm build && pnpm start`.

## 기술 스택

Vite 8(React SPA, 라우터 없음) · React 19 · TypeScript strict · Tailwind CSS v4 · Zustand ·
Dexie(IndexedDB, 지연 로드) · Serwist(PWA) · Vitest · Playwright · pnpm ·
배포는 Cloudflare Workers(정적 자산 + 동기화 Worker, 데이터베이스는 D1).

로컬 우선 설계라 저장소는 인터페이스 뒤에 있습니다 — 동기화 저장소가 같은 인터페이스 뒤에 붙었고,
화면 코드는 그대로입니다.

## 데이터와 프라이버시

**지금 배포본 기준입니다:**

- 여러분이 적은 데이터는 **여러분 브라우저의 IndexedDB** 에 있습니다. 서버로 전송되지 않습니다.
- 추적 스크립트는 없습니다. 다만 앱 화면을 열 때마다(로그인 여부와 무관하게) **Cloudflare Web
  Analytics** 가 쿠키·기기 식별자 없이 익명 페이지뷰 신호(주소 경로·리퍼러·브라우저 종류·로딩 속도)를
  Cloudflare 로 보냅니다 — 방문 수와 속도를 보기 위해서이고, 할 일 내용이나 이메일 같은 개인 정보는
  담기지 않습니다. 자세한 항목은 [개인정보처리방침](./public/privacy.html) 2절, 결정 근거는
  [ADR-0021](./docs/decisions/ADR-0021-cloudflare-web-analytics.md).
- 브라우저 데이터를 지우면 할 일도 함께 사라집니다. **백업 기능으로 내보내 두는 것을 권합니다.**

**동기화가 켜지면 달라집니다.** 여러 기기 동기화를 위해 구글 로그인을 필수로 두고, 서버(Cloudflare D1)가
데이터의 원본이 됩니다 — IndexedDB는 캐시로 바뀝니다(결정 근거: [ADR-0015](./docs/decisions/ADR-0015-google-auth-and-realtime-sync.md),
동작은 위 [여러 기기에서 쓰기](#여러-기기에서-쓰기--동기화)). 그때 무엇을 저장하고 어떻게 지우는지는
**[개인정보처리방침](./public/privacy.html)** 이 단일 소스입니다 — 이 절은 그 페이지로 갈음하고 다시 늘리지 않습니다.
