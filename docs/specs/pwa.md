# PWA / 오프라인 스펙

- 상태: implemented · 관련 ADR: ADR-0001, ADR-0002 · 리서치 참조: reference-app-research.md §4(크로스 플랫폼), §9 과제 4·7

## 1. 목표

브라우저 탭이 아니라 **설치된 앱**처럼 느껴진다: 독에 아이콘이 있고, 네트워크가 없어도 똑같이 동작하며, 새 버전이 나오면 조용히 알려 준다. 데이터가 브라우저 안에만 있으므로 저장 공간이 임의로 지워지지 않도록 지속성을 요청한다.

## 2. 화면과 인터랙션

```
 업데이트 토스트(하단 중앙, 자동 닫힘 없음):  │ 새 버전이 준비됐어요  [새로고침]  ✕ │
 저장 공간 배너(상단, 1회):                 │ 이 브라우저가 저장 공간을 보장하지 않아요. 백업을 권해요 [백업하기] ✕ │
 설치: 브라우저 기본 설치 UI 사용(커스텀 배너 없음).
```

- 상태: **오프라인** 별도 표시 없음(모든 기능 동일). **로딩** 서비스워커 등록은 첫 페인트 뒤 비동기. **에러** 서비스워커 등록 실패는 조용히 무시(개발 모드 콘솔만).

## 3. 규칙

- R1. Lighthouse "Installable" 통과: `manifest`(name "Tasky", short_name "Tasky", `display: standalone`, `start_url: /`, `theme_color: #7CC6FF`, `background_color: #FAFAFC`, 아이콘 192/512 + maskable 512), HTTPS, 서비스워커.
- R1-a. 문서 아이콘: `index.html` 이 탭·북마크용 `<link rel="icon" type="image/png" sizes="192x192" href="/icon-192.png">`와 iOS 홈 화면용 `<link rel="apple-touch-icon" href="/icon-apple-touch-180.png">`를 내고, 둘 다 manifest와 같은 하프물범 아이콘 세트를 쓴다. iOS 는 manifest 의 아이콘보다 이 링크를 먼저 보고, 없으면 **페이지 스크린샷**을 아이콘으로 쓴다. iOS 용은 180×180 전용 크기로 만들고 **불투명 RGB**로 저장한다(투명 픽셀이 있으면 검게 합성될 수 있다). `scripts/check-dist.mjs` 가 매 빌드 크기·알파·문서 링크·프리캐시 포함을 확인한다.
- R2. 아이콘의 캐릭터는 **하프물범 마스코트 확정본**이고 현재 배포본의 크기별 원본은 `assets/seal-icon-master-{192,512,180}.png` 다. 세 원본은 서버에 배포되지 않으며 512 원본을 maskable 에도 쓴다. `assets/seal-sheet.png` 는 초기 일러스트 자료로 보존한다. 레퍼런스 앱의 마스코트·구름 형태를 쓰지 않는다.
- R2-a. **그림을 코드로 다시 그리지 않는다.** 현재 아이콘의 캐릭터 픽셀·비율·배치는 크기별 원본 그대로 유지한다. 배경색을 바꿀 때는 외곽에서 연결된 배경과 경계 혼합 픽셀만 바꾸고 물범 내부는 그대로 둔다.
- R2-b. **배치 계약**: 현재 물범의 크기와 위치를 유지하고, 네 아이콘 모두 균일한 밝은 중성 화이트 `#F7F7F7` 배경의 불투명 정사각 RGB 로 만든다. 512 와 maskable 512 는 동일한 이미지이고 192·180 은 각각의 크기별 원본 픽셀을 쓴다. 네 파일은 `scripts/make-icons.mjs` 하나로 재생성한다. `manifest.theme_color` 는 앱 브라우저 테마색 `#7CC6FF`로, 설치 아이콘의 배경색과 별개다.
- R3. 오프라인: 앱 셸(HTML·JS·CSS·폰트·아이콘)을 설치 시 프리캐시. 네트워크 없이 새로고침해도 홈이 뜨고 모든 스펙 기능이 동작한다. 데이터 요청이 없으므로 런타임 캐시 규칙은 없음.
- R4. 업데이트: 새 서비스워커가 `waiting`이 되면 토스트 표시. `[새로고침]` → `skipWaiting` + 리로드. 무시하면 다음 방문 시 자동 적용. 사용자 입력 중(편집 패널 열림)에는 토스트를 미룬다.
- R5. 서비스워커는 프로덕션 빌드에서만 등록한다. 개발 모드에서는 등록하지 않는다.
- R6. 저장소 지속성: 첫 투두 저장 직후 `navigator.storage.persist()`를 1회 요청. 결과 `false`이면 §2 배너를 1회 표시(기기별 기억 `tasky.pwa.v1`). 다시 묻지 않는다. 이 배너는 **✕로 닫을 수 있는 일회성 알림**이고, backup R14의 백업 경고 점(조건이 참인 동안 상시·끌 수 없음)과는 다른 것이다 — 둘을 같은 컴포넌트로 만들지 않는다.
- R7. 용량: `navigator.storage.estimate()` 사용률이 80%를 넘으면 백업 다이얼로그 상단에 경고 문구. 사용률 확인은 앱 시작 시 1회.
- R8. 다중 탭: 같은 브라우저에서 두 탭이 열려 있을 때, 다른 탭이 저장한 변경은 이 탭이 다시 활성화될 때(`visibilitychange`) 선택 날짜 목록을 재조회해 반영한다. 실시간 반영은 1.5.
- R9. `<html lang="ko">`, `theme-color` 메타는 현재 테마의 `--color-bg`를 따른다(라이트 `#FAFAFC`, 다크 `#141418`).
- R10. 프리캐시 총량 ≤ 2.5MB(폰트 ≤ 600KB 포함, theme.md R14·R15). 초과하면 빌드 검사에서 경고.

## 4. 데이터

- domain 타입 변경 없음. `persist()` 결과·배너 표시 여부는 기기별(localStorage), 저장소 데이터 아님.
- 레포지토리 메서드 없음.

## 5. 접근성

- 업데이트 토스트 `role="status"`, 버튼 2개 모두 Tab 도달. 배너 `role="alert"` 1회.
- 설치는 브라우저 UI에 위임(추가 접근성 요구 없음).

## 6. 범위 밖

- 푸시 알림, 백그라운드 동기화, 공유 타깃, 파일 핸들러, 앱 배지, 커스텀 설치 프롬프트, 데스크탑 위젯·트레이(리서치 §9 과제 7은 Phase 2 검토).

## 7. 완료 조건

- [ ] Lighthouse PWA installable 통과(리포트 첨부), 오프라인 새로고침 E2E 1개(R3).
- [ ] 업데이트 토스트가 `waiting` 워커에서만 뜨고 `[새로고침]` 후 새 버전이 적용된다(수동 확인 절차를 PR에 기재).
- [ ] `persist()` false 경로 배너가 1회만 뜬다(모킹 테스트, R6).
- [ ] 두 탭 시나리오에서 재활성화 시 목록이 갱신된다(E2E 또는 수동 절차 기재, R8).
- [ ] 아이콘 192/512/maskable 파일 존재, 개발 모드에서 서비스워커 미등록(R5).
- [ ] iOS 홈 화면 아이콘이 스크린샷이 아니라 앱 아이콘으로 뜨고 모서리가 검지 않다(R1-a, 실기기 또는 시뮬레이터 1회).
