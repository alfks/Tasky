# 카테고리 스펙

- 상태: approved · 관련 ADR: ADR-0002 · 리서치 참조: reference-app-research.md §1(색으로 꾸미는 성취감), §3-3, §6 팔레트, §7 Category

## 1. 목표

카테고리는 Tasky에서 **색을 고르는 유일한 곳**이다. 다 쓴 카테고리는 사용자가 **완료** 또는 **중단**으로 스스로 종료한다. 삭제할 때는 **완료한 할 일은 항상 기록으로 남고**, 아직 안 한 할 일은 사용자가 옮길지·새 카테고리를 만들지·함께 지울지 고른다.

## 2. 화면과 인터랙션

### 2-A. 사이드바 목록 (데스크탑) / 드로어 (< 1024px 동일 내용)
```
 카테고리
 │ ⠿ ● 📝 todo          2/3 ⋯ │   ← ⠿ 드래그 핸들(hover), ● 색 점 12px, n/m 선택 날짜 기준, ⋯ 메뉴
 │ ⠿ ● 📚 공부          1/2 ⋯ │
 + 카테고리 추가
 종료됨 (2) ▸                     ← 펼치면 흐린 목록: ✓ 운동(완료) · ⏸ 독서(중단), 각 행 ⋯: 재개 · 상태 바꾸기 · 삭제
```
- 행 클릭: 메인의 해당 그룹으로 스크롤 + 헤더 400ms 하이라이트(reduced-motion: 즉시 1회). `⋯`(활성): 수정 · 완료로 종료 · 중단으로 종료 · 삭제. 우클릭 동일. 드래그 순서 변경, 키보드 `Alt+↑/↓`.

### 2-B. 생성/수정 다이얼로그 (모달 400px, 좁은 화면 전폭 시트)
```
 ┌ 카테고리 만들기 ───────────── ✕ ┐   수정 모드: 제목 "카테고리 수정", 버튼 "저장",
 │ 이모지 [📝▾]  이름 [ todo       ] │   하단 좌측 [완료로 종료 ▾](완료/중단). 종료 상태면 [재개].
 │ 색상  ● ● ● ● ● ●  (12색 2줄×6) │
 │       ● ● ● ● ◉ ●  선택: 스카이  │
 │ 미리보기 ● 📝 todo  [취소][만들기] │
 └──────────────────────────────────┘
```
### 2-C. 삭제 대화상자 (`role=alertdialog`, 440px) — 상태 3가지
```
 [기본: 미완료 M>0, 옮길 활성 카테고리 있음]        [옮길 카테고리 없음: 선택지 2 비활성, 기본 = 3]
 ┌ '공부'를 삭제할까요? ─────────────── ✕ ┐        │ (○) 다른 카테고리로 옮기기 — 옮길 카테고리가 없어요 │
 │ 완료한 할 일 12개는 기록으로 남아요.       │        │ (●) 새 카테고리를 만들어 옮기기                  │
 │ 아직 안 한 할 일 3개는 어떻게 할까요?      │        │      이름 [            ]  색 ● ● ● ● ● ●         │
 │ (●) 다른 카테고리로 옮기기 [ 📝 todo ▾ ]  │        │ ( ) 함께 삭제                                    │
 │ ( ) 새 카테고리를 만들어 옮기기            │
 │ ( ) 함께 삭제                             │        [미완료 M=0: 축약]
 │ 💡 기록만 정리하려면 삭제 대신 [완료로 종료] │        │ 완료한 할 일 12개는 기록으로 남아요. [취소][삭제] │
 │                          [취소]  [삭제]  │        (N=0, M=0: "할 일이 없는 카테고리예요." [취소][삭제])
 └──────────────────────────────────────────┘
```
### 2-D. 상태
- **빈 상태**: "아직 카테고리가 없어요" + `[첫 카테고리 만들기]`. **로딩**: 스켈레톤 3행. **에러**: 저장 실패 → 다이얼로그 유지, 필드 아래 `role=alert` "저장하지 못했어요. 다시 시도해 주세요". 삭제 실패 → 대화상자 유지 + 같은 문구, 아무것도 바뀌지 않음(R13).
- **검증 오류**(생성·수정·즉석 생성 공통): 빈 이름 "이름을 입력해 주세요", 20자 초과 "20자까지 쓸 수 있어요", 중복 "같은 이름이 이미 있어요", 50개 초과 "카테고리는 50개까지 만들 수 있어요".

## 3. 규칙

- R1. 이름 앞뒤 공백 제거 후 1~20자, 줄바꿈 불가. R2. 삭제되지 않은 카테고리(종료 포함) 사이에서 대소문자 무시 유일. R3. 색은 `theme.md §3-C` 12색(HEX 대문자). R4. 이모지 0 또는 1 grapheme. R5. 새 카테고리 `order` = 활성 최대 + 1, 순서 변경은 활성 목록 0..n-1 재매김. R6. 삭제되지 않은 카테고리 최대 50개.
- R7. **상태 머신** `status ∈ active | completed | paused`. 전이: `active→completed`(완료로 종료) · `active→paused`(중단으로 종료) · `completed→active`, `paused→active`(재개) · `completed⇄paused`(상태 바꾸기). 활성을 떠날 때 `closedAt` 기록, 돌아오면 제거. 삭제는 모든 상태에서 가능. 자동 전이 없음.
- R8. 종료된 카테고리: 사이드바 "종료됨 (n)" 접힘 섹션에만(흐림 + ✓/⏸ 배지, `closedAt` 내림차순). 새 투두 대상·투두 카테고리 변경 선택지·삭제 대화상자 이동 대상·팔레트 "새 할 일"에서 제외. 날짜 화면에는 그날 투두가 있을 때만 그룹 표시(헤더 흐림 + 배지, `+ 할 일 추가` 없음, 활성 그룹 아래). 기존 투두의 체크·수정·삭제는 가능.
- R9. 재개: `status=active`, `closedAt` 제거, `order` = 활성 목록 끝.
- R10. **삭제 대화상자 선택지**(미완료 M>0): ① 다른 활성 카테고리로 옮기기(대상 = 자신을 제외한 활성 카테고리, `order` 순, 첫 항목 기본 선택) ② 새 카테고리를 만들어 옮기기(이름·색 즉석 입력, 이모지 없음) ③ 함께 삭제. **기본값 ①**, 대상이 없으면 ①은 비활성 + 사유 표시하고 **기본값 ②**. 근거: 파괴적 선택지가 기본이면 안 되고, "다른 곳으로 옮기기"가 가장 정보 손실이 적다.
- R11. **축약**: M=0이면 선택지·즉석 입력을 렌더하지 않고 문구 + `[취소][삭제]`만(투두 삭제와 같은 공용 확인 대화상자). N=0이면 첫 문장 생략, 둘 다 0이면 "할 일이 없는 카테고리예요."
- R12. 즉석 생성은 생성 다이얼로그와 **같은 검증 함수**(R1~R4·R6)를 쓰고 오류는 입력 아래 `role=alert`. 유효하지 않으면 `[삭제]`가 실행되지 않는다(비활성 아님, 클릭 시 오류 표시).
- R13. **원자성**: 삭제 + 미완료 이동 + (즉석 생성)은 저장소의 **단일 메서드·단일 트랜잭션**(`CategoryRepository.remove`, TECH_PLAN §6). 중간 실패 시 아무것도 바뀌지 않는다(생성만 되고 이동이 안 되는 상태 없음).
- R14. 실행 결과: 카테고리 소프트 삭제(tombstone) · **완료 투두는 그대로**(삭제된 카테고리를 계속 가리킴) · 미완료는 ①②면 `categoryId` 변경 + `order` = 대상 그룹 끝(날짜별), ③이면 같은 `deletedAt`으로 소프트 삭제. 물리 삭제 없음(ADR-0002).
- R15. **되돌리기 6초**(토스트 "'공부'를 삭제했어요 [되돌리기]"): 카테고리 복구 + ③으로 지운 투두 복구 + 옮긴 투두를 원래 카테고리·원래 `order`로 복귀 + 즉석 생성 카테고리 소프트 삭제 — 즉 실행 결과 전체를 단일 트랜잭션으로 되감는다(`undoRemove`). 확인을 거쳤어도 유지하는 근거: 여러 투두를 옮기거나 지우는 **복합 작업**이라 "대상을 잘못 고름"이 단일 항목 삭제보다 흔하고, 되감기 비용이 결과 객체 하나로 싸다. 단일 항목 삭제(todo R13)는 확인만.
- R16. **종료 제안**: N>0(남길 기록이 있음)이고 M>0인 경우에만 대화상자 하단에 한 줄 "기록만 정리하려면 삭제 대신 [완료로 종료]" 링크 버튼. 누르면 대화상자를 닫고 R7 `active→completed`. 근거: 기록이 걸린 상황에서만 "종료면 충분한데 삭제를 누르는" 혼동을 막고, 그 외에는 소음이라 숨긴다.
- R17. **삭제된 카테고리의 남은 투두**: 날짜 화면에서 그날 완료 투두가 있을 때만 맨 아래 "이름 (삭제됨)" 그룹(흐림, tombstone 색). 읽기 전용(체크 해제·편집·순서 불가), 메뉴 `다른 카테고리로 옮기기`·`삭제`. 사이드바·선택지·팔레트에 없음. 날짜 점·달성률에는 포함.
- R18. **첫 실행 시드**: 카테고리 테이블이 비어 있고 `seededAt`이 없으면 `📝 todo`(스카이 `#7CC6FF`, active) 1개 생성 후 `seededAt` 기록. 지워도 재생성 없음. 근거: 이름은 사용자 지정, 색은 기본 강조색과 같아 첫 화면이 한 톤이고 색 바꾸기가 곧 첫 꾸미기, 📝는 특정 활동을 전제하지 않음.
- R19. 사이드바 `n/m` = 선택 날짜 완료/전체(0개면 빈칸). R20. 색 변경은 재조회 없이 즉시 반영.

## 4. 데이터

- domain `Category = { id, name, color, emoji?, order, status, closedAt?, createdAt, updatedAt, deletedAt? }`(초안의 `archivedAt` 대체). 전이 검증·재매김·시드·삭제 계획(`CategoryRemovalPlan`)·되감기 계획은 순수 함수. `Settings.seededAt?`.
- 레포지토리: `CategoryRepository.list({ includeClosed, includeDeleted })`, `getById`, `upsert`, `bulkUpsert`, `softDelete`, `restore`, **`remove(id, at, plan) → CategoryRemovalResult`**, **`undoRemove(result, at)`**(둘 다 카테고리·투두 두 테이블 단일 트랜잭션); `TodoRepository.listByCategory`(N·M 계산). 시그니처 TECH_PLAN §6.

## 5. 접근성

- 목록 `ul > li`, 행 본체 `button`, 메뉴 `aria-label="공부 메뉴" aria-haspopup="menu"`. 종료 섹션 `aria-expanded`. 색 선택 `radiogroup`(이름 = 색 이름, 선택은 체크 아이콘). 드래그 대안 `Alt+↑/↓` + 낭독.
- 삭제 대화상자: app-shell R14 공통 규칙 + 선택지는 `radiogroup`(라벨 "아직 안 한 할 일 처리"), 초기 포커스 = 기본 선택 라디오. 라디오 ②를 고르면 이름 입력이 나타나고 포커스가 그리로 이동, 다른 라디오로 바꾸면 입력은 숨기되 값은 유지. 대상 카테고리 `select`는 라디오 ①에 연결(`aria-describedby`). `Enter`는 `[삭제]`/`[취소]`에 포커스가 있을 때만 실행(이름 입력의 Enter·IME 조합 Enter는 무시). `Esc` = 취소.
- 생성/수정 다이얼로그: 이름 입력 초기 포커스, `Esc` 닫기, `Enter` 제출(이모지 입력 제외). 배지(✓/⏸/삭제됨)는 텍스트 동반.

## 6. 범위 밖

- 커스텀 HEX(1.5), 휴지통·기간 지난 복구(Phase 2), 카테고리 설명·반복·하위 카테고리·통계(Phase 2), 자동 완료, 종료 카테고리로의 이동.

## 7. 완료 조건

- [ ] R1~R20 테스트. R7 전이 표 전부, R10·R11 대화상자 3상태, R13·R15 원자성(중간 실패 주입 → 변화 없음)은 memory·indexeddb 계약 테스트 모두.
- [ ] 생성 → 수정 → 정렬 → 종료/재개 → 삭제(①·②·③ 각각, 완료 투두 보존 확인) → 되돌리기가 키보드만으로 된다. 유일한 카테고리 삭제(대상 없음 경로) 포함.
- [ ] 12색 라이트/다크, 종료 섹션·삭제됨 그룹·삭제 대화상자 3상태 스크린샷.
- [ ] 첫 실행에 `📝 todo` 1개만, 삭제 후 새로고침해도 재생성 없음.
