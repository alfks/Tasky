# 프로필 스펙

- 상태: approved · 관련 ADR: [ADR-0023](../decisions/ADR-0023-profile-in-settings.md) · 혼합 버전 보존: [ADR-0026](../decisions/ADR-0026-legacy-profile-sync.md) · 리서치 참조: 없음(사용자 피드백 3번, 2026-09-29) · 구현 상태: 코드 머지(T-G) — `implemented` 는 §7 마지막 항목(Worker 재배포 + 실기기 두 대 확인) 뒤에

## 1. 목표

앱이 "내 것"으로 보이게 이름·사진·한 줄 소개를 달력 바로 위에 둔다. 셋 다 **나만 보는 값**이고 어디에도 공개되지 않는다 — 친구에게 보이는 별명은 [social.md](social.md)(Phase 3)가 따로 정하며, 이 프로필을 자동으로 복사해 공개하지 않는다. 구글에서 이름·사진을 받아오지 않는다(README·`public/privacy.html` 의 약속은 그대로다).

## 2. 화면과 인터랙션

달력 컬럼 상단(데스크톱)과 첫 스크롤 화면 상단(모바일) — 달력 바로 위(app-shell.md §2-A·R12 개정):

```
 채운 상태:                           빈 상태(로그인 직후):
 ┌ 프로필 ───────────────────── ✎ ┐   ┌ 프로필 ───────────────────── ✎ ┐
 │ (사진) 밀리                     │   │ ( 밀 ) millie                  │  ← 이메일 @ 앞부분 · 첫 글자 원
 │        오늘도 한 칸씩            │   │        한 줄 소개를 적어 보세요 │  ← muted 자리표시 문구
 └────────────────────────────────┘   └────────────────────────────────┘
```

편집 대화상자 "프로필 편집"(✎ 로만 연다, 폭 `max-w-[400px]`, 지연 로드):

```
 ┌ 프로필 편집 ─────────────────── ✕ ┐
 │ (미리보기 64px)  [사진 고르기] [사진 지우기]   ← 지우기는 사진 있을 때만
 │ 이름     [ 밀리                 ]  4 / 20      │
 │ 한 줄 소개 [ 오늘도 한 칸씩      ] 8 / 60      │
 │                            [취소] [저장]      │
 └──────────────────────────────────────────────┘
```

- **사진 고르기**: 파일 선택 → 즉시 미리보기(아직 저장 전). 오류는 파일 선택 줄 아래 `role=alert` 한 줄: 이미지 아님 "이미지 파일만 올릴 수 있어요" · 10MB 초과 "10MB 이하 이미지만 올릴 수 있어요" · 디코드 실패(HEIC 등 브라우저가 못 여는 형식 포함) "사진을 읽지 못했어요. 다른 사진을 골라 주세요" · 상한 초과(R6) "사진을 줄이지 못했어요. 다른 사진을 골라 주세요". 오류가 나도 이전 미리보기는 유지된다.
- **이름·소개 입력칸에는 `maxLength` 를 쓰지 않는다**(UTF-16 단위라 R1 의 코드 포인트 셈법과 이모지에서 어긋난다). `n / 20`·`n / 60` 은 다듬기 전 코드 포인트 수. 초과는 todo.md 제목과 같은 방식 — `[저장]` 은 활성으로 두고 **제출 시** R1·R2 문구를 보이며 저장하지 않는다.
- **저장**: 대화상자가 닫히고 카드가 즉시 바뀐다(성공 토스트 없음). 실패는 대화상자를 유지한 채 토스트 "저장하지 못했어요. 다시 시도해 주세요"(app-shell §2-C 문구). **취소·Esc·✕** 는 미리보기 포함 전부 버린다(확인 없음 — 되돌리기 쉬운 값).
- **빈 상태**는 결함이 아니라 기본값이다 — 이름 자리엔 로그인 이메일의 `@` 앞부분, 사진 자리엔 그 첫 글자 원, 소개 자리엔 자리표시 문구. **로딩 상태**: 설정 행은 마운트 뒤 비동기로 읽히므로(theme 스토어와 같다) 첫 페인트는 R14 의 미러로 그리고, 미러가 없으면 카드는 **높이만 예약**하고 텍스트·원을 그리지 않는다 — 폴백 문구는 저장소 읽기가 끝난 뒤에만 보인다(매 기동마다 폴백 → 실제 값으로 깜빡이는 것을 금지). 다른 기기의 변경은 다음 동기화 풀에서 카드에 반영된다(R15, sync.md R5 — 즉시가 아닐 수 있다).
- 카드에는 상시 카드 면을 쓴다(app-shell R16). 계정 블록(이메일·동기화 상태·로그아웃)은 **사이드바 맨 아래** — 세션 상태와 "나"의 표현을 섞지 않는다.

## 3. 규칙

- R1. **이름**: 줄바꿈(`\r`·`\n`·U+2028·U+2029)은 공백으로, 앞뒤 공백 제거, 연속 공백은 하나로. 다듬은 뒤 **1~20자**(자 수는 코드 포인트 — todo.md 제목과 같은 셈법). 비우면 **미설정**(필드 없음)이고 오류가 아니다. 20자 초과는 "이름은 20자까지 쓸 수 있어요".
- R2. **한 줄 소개**: R1 과 같은 다듬기, **0~60자**. 비우면 미설정. 초과는 "소개는 60자까지 쓸 수 있어요". 입력칸은 한 줄(`input`)이라 줄바꿈을 받지 않는다.
- R3. **사진 입력**: `image/*` 만 받고(형식을 모르는 파일은 디코드해 보고 판정) 원본 **≤ 10MB**. 애니메이션은 첫 프레임만. EXIF 회전 정보가 있으면 **사용자가 보는 방향**으로 돌린 결과를 쓴다(회전 6 픽스처로 검사). 투명 영역은 흰색으로 채운다(JPEG 폴백에서 검게 변하지 않게) — 다크 모드에서 투명 PNG 가 흰 원판으로 보이는 것은 감수한다.
- R4. **사진 결과**: 짧은 변을 기준으로 **정사각 가운데 크롭 → 96×96** 으로 줄인 뒤 **WebP(품질 0.82)** 로 인코딩한다. 브라우저가 WebP 인코딩을 지원하지 않으면(결과 MIME 이 `image/webp` 가 아니면) **JPEG(품질 0.80)** 으로 다시 인코딩한다. 저장 형식은 이 둘뿐이다.
- R5. **저장값**은 `data:image/webp;base64,…` 또는 `data:image/jpeg;base64,…` 문자열 **≤ 16,384자**(ADR-0023 — 이 하나가 상한이자 R6 의 하강 문턱이다). 접두·base64 문자 집합·길이 셋 다 검사한다. 원본 파일·원본 해상도는 저장하지 않는다.
- R6. 인코딩 결과가 R5 상한을 넘으면 품질을 **0.15 씩** 내려 다시 인코딩하고(0.82 → 0.67 → 0.52 → 0.37 → 0.22, **최대 5회**), 품질 **0.20 미만**으로 내려가야 하면 멈추고 오류(§2 문구)로 끝낸다 — 무한 루프 없음. 4000×4000 사진도 R5 안에 들어와야 한다(완료 조건).
- R7. **저장 경로**: 저장은 저장소에서 **새로 읽은** 설정 행 위에 세 필드만 바꿔 쓴다(ADR-0023 규칙 4). 값 자체를 다듬는(R1·R2) 유일한 자리가 이 클라이언트 쓰기 경로다. 사진 지우기·이름 비우기는 필드를 **제거**한다(`null`·빈 문자열을 저장하지 않는다). 세 필드는 설정 행과 함께 동기화·백업된다 — 별도 항목이 아니다.
- R8. **읽기 경로의 관용**(ADR-0023 규칙 3): 백업 복원·동기화 풀·Worker 푸시 **세 곳**(같은 `readSettings`)에서 `profileName`·`profileBio`·`profileAvatar` 가 R1·R2·R5 를 어기면 **그 필드만 버리고 행은 채택**한다(테마·강조색은 살아남는다). 검증은 **다듬은 값**으로 하되(다만 다듬기 전 원시 길이 1,000자 초과는 그 자체로 무효 — 공백으로 부풀린 값이 통과하지 않게) 저장은 **받은 값 그대로**(validate-rows 원칙·backup R2 왕복 동일성) — 앞뒤 공백이 있는 이름은 그대로 저장되고 카드가 표시할 때 R1 규칙으로 다듬어 보인다(공백만 있는 `profileBio`(" ")는 다듬으면 0자라 유효 → 그대로 저장 → 카드는 자리표시 문구). 이것은 backup.md R4 "하나라도 실패하면 아무것도 쓰지 않는다" 의 **의도된 예외**이며(backup R4 가 역참조한다), R5(알 수 없는 필드 무시)와는 다른 규칙이다 — 손으로 키운 사진 하나가 복원 전체를 막으면 안 된다.
- R9. **표시**: 아바타 원 40px(2배 화면에서 96px 원본이 선명해야 한다 — 40px 은 표시 크기일 뿐 원본을 더 줄이지 않는다). 사진이 없으면 표시 이름의 **첫 글자(첫 그래핌 — `Intl.Segmenter` 가 없으면 첫 코드 포인트)** 를 `--color-accent` 배경·`--color-on-accent` 글자 원에 넣는다. 이름은 `--text-base` 600, 소개는 `--text-sm` muted, 둘 다 **한 줄 말줄임**(드로어 폭 300 에서 60자 소개가 한 줄).
- R10. **표시 이름 폴백**: 이름 미설정이면 로그인 이메일의 `@` 앞부분(`SyncState.userEmail` — 계정 블록이 쓰는 동기화 스토어의 `email` 과 같은 출처). 그것도 없으면(이론상) "나". 소개 미설정이면 muted 자리표시 "한 줄 소개를 적어 보세요"(카드에만, 대화상자 입력칸의 placeholder 는 비운다).
- R11. **진입점은 프로필 카드의 ✎ 하나**다(app-shell R12-a 의 예외 조항). 팔레트·설정(⚙)·계정 블록에서 프로필 편집을 열지 않는다.
- R12. 프로필은 **어디에도 공개되지 않는다**: 소셜 프로필·공유 카드·초대 링크에 자동으로 실리지 않고(social.md R1·ADR-0022 3), 서버는 설정 행의 일부로 저장만 한다. 공개하려면 별도 스펙 + ADR(ADR-0023 재검토 트리거).
- R13. 로그아웃·계정 전환·계정 삭제 시 설정 행·R14 미러와 함께 로컬에서 지워진다(sync.md R1·§6 의 "내보내고 지우기" 경로 — 프로필만의 별도 처리 없음).
- R14. **첫 페인트 미러**: 프로필 스토어가 저장소에서 읽은(또는 저장에 성공한) 마지막 프로필 세 값을 localStorage `tasky.profile.v1` 에 둔다(theme R6·R8 과 같은 성격 — 캐시일 뿐이고 저장소 값이 우선한다, ≤ ~17 KB). 스토어 초기화는 미러가 있으면 **동기적으로** 그 값을 상태에 넣고(테마 스토어의 미러 읽기와 같은 모양), 저장소 읽기가 끝나면 저장소 값으로 바꾼다. 미러는 R13 의 로컬 삭제와 함께 지운다(이름·사진이 남는 공용 PC 흔적 방지 — 테마 미러와 다른 점). **삭제 지점은 하나다**: 저장소 계층의 `wipeLocal()` 은 localStorage 를 모르므로, 인증 액션(`auth-actions.ts`)에서 `wipeLocal()` 호출을 감싸는 헬퍼 하나(예: `wipeLocalAndMirrors`)가 프로필 미러를 함께 지우고, 다섯 경로(첫 로그인 "내보내고 지우기"·로그아웃·계정 전환·계정 삭제·삭제 안내 — 호출 여섯 곳) 전부 그 헬퍼만 탄다. 직접 `wipeLocal()` 호출이 남지 않는다(테스트로 고정).
- R15. **원격 변경 반영**: 동기화 풀이 설정 행을 채택하면 프로필 스토어도 저장소에서 다시 읽는다(테마 스토어가 같은 갈래에서 다시 읽는 것과 나란히). 일시적 읽기 오류가 나면 다음 정상 동기화 왕복에서 다시 읽는다. 초기 읽기와 원격 재조회가 겹쳐도 나중에 시작한 최신 읽기 결과가 카드와 첫 페인트 미러에 남는다. 폴링 간격 안에 카드가 바뀐다. 원격 변경을 받은 채 편집 창을 열어두었다면 사용자가 실제로 바꾼 필드만 최신 설정 행에 병합해 저장한다.

## 4. 데이터

- `Settings`(ARCHITECTURE.md §4)에 선택 필드 셋: `profileName?: string`(R1) · `profileBio?: string`(R2) · `profileAvatar?: string`(R5). 없음 = 미설정. 저장소 인터페이스·스키마 버전·동기화 벡터는 바뀌지 않는다. 혼합 버전의 프로필 누락은 Worker가 보존하며, 명시적 편집·삭제는 `profileVersion: 1`로 구분한다. 업데이트한 기기는 서버의 자기 설정도 다시 받는다(ADR-0026). **Worker 재배포가 출시 조건이다**(ADR-0023 규칙 6).
- 다듬기·검증·상한 상수·"설정 행에 프로필 세 필드를 쓰는" 순수 함수는 `domain` 에 두고 단위 테스트한다(§6 코드 원칙). 백업 복원·동기화 풀·Worker 푸시의 설정 행 검증이 같은 상수를 쓴다(ADR-0023 규칙 2).
- 사진 파이프라인(R3~R6)은 브라우저 API 를 쓰므로 feature 쪽에 두되, 크롭 좌표·품질 하강 루프는 인코더를 주입받는 순수 부분으로 떼어 단위 테스트하고 실변환은 e2e 로 본다.

## 5. 접근성

- 카드는 `section` + 접근 이름 "프로필". 사진 `img` 는 카드·대화상자 미리보기 둘 다 `alt=""`(이름 텍스트·이름 칸이 바로 옆에 있어 중복 낭독을 피한다), 첫 글자 원은 `aria-hidden`. ✎ 는 `IconButton` 접근 이름 "프로필 편집". `[사진 지우기]` 접근 이름은 "사진 지우기".
- 대화상자: app-shell 표준(포커스 트랩·`aria-labelledby` 제목·`Esc` 취소·닫힌 뒤 포커스는 ✎ 로 복귀). **초기 포커스는 이름 칸**. `Enter` 는 이름·소개 칸에서 저장(한 줄 입력이라 충돌 없음, IME 조합 중 Enter 제외 — app-shell R14 와 같은 판정).
- 파일 선택은 **실제 `input[type=file]`**(backup.md §5·백업 가져오기와 같은 구조)을 `sr-only` 로 **시각만** 숨기고 포커스 가능하게 둔다 — `display:none`·`hidden` 금지(Tab 으로 닿지 못한다). `label htmlFor`(버튼 모양, 접근 이름 "사진 고르기")는 input 의 `:focus-visible` 을 자기 위에 링으로 그린다(`:has(:focus-visible)` 또는 상태 클래스). 사진 오류는 `role=alert` 이고 그 id 는 **input 의 `aria-describedby`** 에 둔다(포커스가 input 에 있으므로 거기서만 낭독된다). 이름·소개 초과 문구도 같은 모양 — `role=alert` + 해당 입력의 `aria-describedby`(파일 오류와 대칭). 글자 수 표시(`4 / 20`)는 `aria-live` 없이 시각 보조만.
- 색만으로 상태를 전달하지 않는다(첫 글자 원의 `--color-on-accent` 대비는 theme.md 가 보장). 강제 색 모드·reduced-motion 을 따른다.

## 6. 범위 밖

- 구글 프로필 가져오기(스코프 확장 안 함, SYNC_CREDENTIALS_GUIDE §2-4) · 공개 프로필·친구에게 보이기(social.md) · 사진 편집(회전·확대) · 여러 프로필·계정 전환(ARCHITECTURE §5) · 커버 이미지·상태 메시지 이력 · 표시 이름을 문서 제목·알림에 넣기(app-shell R9 유지) · 이미 지워진 프로필의 자동 복구(ADR-0026 — 백업에서 복원하거나 다시 적는다).
- **공개 문서 갱신은 구현 티켓(T-G)의 완료 조건이다**: `public/privacy.html` 1절 "설정 —" 줄에 "프로필(이름·한 줄 소개·사진 — 앱 안에서 직접 적은 것)" 을, 3절 "받지 않는 것" 의 "이름, 프로필 사진" 항목에 "구글에서 받지 않는다는 뜻이며, 앱 안에서 직접 적은 프로필은 앱 데이터로 저장한다" 를 더한다(README 55행의 "이름·프로필 사진은 요청하지 않습니다" 는 그대로 참이다). CLAUDE.md 규칙대로 공개 글은 구현과 어긋나면 글을 고친다.
