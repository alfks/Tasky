# 데이터 백업/복원 스펙

- 상태: approved · 관련 ADR: ADR-0002 · 리서치 참조: reference-app-research.md §4(백업/동기화가 로그인 기반), §9 과제 4

## 1. 목표

계정이 없으므로 **내 데이터를 파일로 갖는 것**이 유일한 안전망이다. 클릭 두 번으로 JSON 하나를 받고, 다른 브라우저·기기에서 같은 파일로 되살린다. 실수로 지운 뒤에도 옛 백업을 "병합"하면 최신 상태를 해치지 않고 빈 곳만 채워진다.

## 2. 화면과 인터랙션

```
 사이드바 하단 "⇅ 백업/복원" → 다이얼로그(480px, 좁은 화면 전폭 시트)
 ┌ 백업/복원 ─────────────────────────────── ✕ ┐
 │ 내보내기                                     │
 │  카테고리 4개 · 할 일 312개                   │
 │  마지막 백업: 2026-09-01 (14일 전)   [JSON 내보내기] │
 │──────────────────────────────────────────────│
 │ 가져오기                                     │

 │  (●) 병합 — 같은 항목은 더 최근 것을 남겨요     │
 │  ( ) 교체 — 지금 데이터를 모두 지우고 파일로 바꿔요│

 결과 토스트: "카테고리 4개, 할 일 312개를 가져왔어요 (추가 20 · 갱신 3 · 유지 289)"
 경고 점: 사이드바 "백업/복원"에 작은 점 — 마지막 백업 30일 초과(또는 없음) 이면서 투두 ≥ 20개일 때
```

- 상태: **빈 상태** 데이터 0개면 내보내기 버튼 비활성 + "아직 내보낼 데이터가 없어요". **로딩** 가져오기 진행 중 버튼 스피너 + 다이얼로그 닫기 불가. **에러** 형식 오류 → 파일 아래 `role=alert` 문구(§3 R8), 저장 실패 → "가져오지 못했어요. 파일은 바뀌지 않았어요" (교체 모드는 전부 롤백).

## 3. 규칙

- R1. 내보내기 파일명 `tasky-backup-YYYY-MM-DD.json`(로컬 날짜), MIME `application/json`, UTF-8, 들여쓰기 2칸.
- R2. 파일 형식:
  ```json
  { "app": "tasky", "schemaVersion": 1, "exportedAt": "2026-09-15T09:00:00.000Z",
    "settings": { "theme": "system", "accentColor": "#7CC6FF", "updatedAt": "2026-09-15T08:59:00.000Z" },
    "categories": [ /* 삭제되지 않은 것 + 아래 todos/focusSessions가 가리키는 tombstone(deletedAt 유지) */ ],
    "todos": [ /* Todo 전체 필드, deletedAt 있는 것 제외 */ ],
    "focusSessions": [ /* FocusSession 전체 필드, timer.md */ ] }
  ```
- R3. `schemaVersion`은 저장소 스키마 버전(TECH_PLAN §5)과 같다. 파일 버전 < 현재면 가져오기 전에 순차 변환, 파일 버전 > 현재면 거부("더 새로운 버전의 Tasky에서 만든 파일이에요").
- R4. 검증: `app === "tasky"`, 배열 타입, 각 항목 필수 필드·타입, 카테고리 이름/색/투두 제목 길이(각 스펙 규칙), 투두의 `categoryId`가 파일 안 카테고리(tombstone 포함)에 존재, 세션의 `todoId`는 없어도 됨(없으면 `null`로 정규화). 하나라도 실패하면 아무것도 쓰지 않는다.
- R5. 알 수 없는 필드는 무시하고 보존하지 않는다(경고 없음).
- R6. **병합**(카테고리·투두·세션 공통): `id`가 같으면 `updatedAt`이 더 최근인 쪽을 남긴다(같으면 현재 데이터 유지). 소프트 삭제 상태도 같은 규칙(tombstone이 더 최근이면 삭제 유지). 파일에만 있는 항목은 추가. 설정은 파일 쪽이 더 최근일 때만 갱신. 파일에 `running/paused` 세션이 있으면 `canceled`로 바꿔 넣는다(실행 중 세션은 1개, R timer R5).
- R7. **교체**: 현재 카테고리·투두·세션을 전부 지우고(물리 삭제 허용 — 사용자 명시 요청) 파일 내용으로 채운 뒤 설정 갱신. 단일 트랜잭션, 실패 시 전부 롤백. 확인 체크박스 필수.
- R8. 형식 오류 문구: JSON 파싱 실패 "JSON 파일이 아니에요", `app` 불일치 "Tasky 백업 파일이 아니에요", 검증 실패 "파일 내용이 올바르지 않아요 (todos[12].title)"(첫 오류 경로 표시).
- R9. 파일 크기 ≤ 20MB. 초과 시 읽지 않고 "20MB 이하 파일만 가져올 수 있어요".
- R10. 내보내기 성공 시 `Settings.lastBackupAt` 갱신. 다이얼로그와 경고 점은 이 값을 사용.
- R11. 가져오기 완료 후 선택 날짜의 목록·주 요약·카테고리·달성률을 다시 조회한다. 페이지 새로고침 불필요.
- R12. 병합·교체 결과 토스트에 추가/갱신/유지 개수를 표시한다(R6·R7 계산 결과).
- R13. 1,000개 카테고리·50,000개 투두 파일(≈15MB) 가져오기가 10초 안에 끝나고 UI가 멈추지 않는다(청크 500개 단위 쓰기).

## 4. 데이터

- domain: 백업 문서 타입, `validateBackup(json) → ok | { path, code }`, `planMerge(local, incoming) → { add, update, keep }`(순수 함수), 버전 변환 체인. 엔티티 타입 변경 없음(`Settings.lastBackupAt?` 추가).
- 레포지토리: `TodoRepository.listAll()`, `bulkUpsert`, `replaceAll`; `CategoryRepository.list({ includeClosed: true, includeDeleted: true })`, `bulkUpsert`, `replaceAll`; `FocusSessionRepository.listAll`, `bulkUpsert`, `replaceAll`; `SettingsRepository.update`.

## 5. 접근성

- 파일 선택은 실제 `input[type=file]`(시각적 커스텀 가능) + 선택된 파일명 텍스트. 모드는 `radiogroup`.
- 진행 중 `aria-busy="true"`, 완료 토스트 `role=status`, 오류 `role=alert`.
- 교체 모드의 확인 체크박스가 꺼져 있으면 `[가져오기]`는 `aria-disabled` + 이유 툴팁("확인 체크가 필요해요").

## 6. 범위 밖

- 자동 주기 백업, 클라우드 저장(Phase 2 sync), CSV/엑셀, 부분(날짜 범위) 내보내기, 다른 앱 형식 가져오기, 암호화.

## 7. 완료 조건

- [ ] R2~R9, R13 단위·계약 테스트(병합 케이스: 파일이 최신 / 로컬이 최신 / 로컬 삭제됨 / 파일에만 있음 / 동일 시각).
- [ ] 내보낸 파일을 빈 브라우저 프로필에서 교체 가져오기 → 원본과 동일(세션·tombstone 포함, E2E 또는 계약 테스트로 왕복 검증).
- [ ] 잘못된 파일 3종(비JSON, 타 앱, 필드 오류)의 문구가 R8과 일치.
- [ ] 키보드만으로 내보내기·가져오기 완료.
