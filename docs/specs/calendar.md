# 캘린더 스펙

- 상태: draft · 관련 ADR: - · 리서치 참조: reference-app-research.md §2.2(캘린더 화면), §9 기회 1

## 1. 목표

**여러 달을 오가며 훑는 것은 이미 됐다.** date-strip.md R14~R18(상태 `approved`, 배포됨)이 월 보기(‹/›로 ±1달)와 `MonthJump`(월 표시를 누르면 네이티브 날짜 입력으로 어떤 날짜로도 바로 점프)를 이미 준다. 여러 달을 한 화면에 나란히 늘어놓는 그리드는 따로 만들지 않기로 정했다(§6 — P1·P2에 비해 값이 작다).

이 스펙이 남기는 것은 하나, **D-day**다 — 미리 정해 둔 날짜(생일·발표일 등)까지 며칠 남았는지 항상 보이는 자리에 두는 것. 새 그리드·새 연도 선택기·새 날짜 이동 로직을 만들지 않는다 — 날짜를 고르는 곳(폼)도, 그 날짜로 이동하는 것도 이미 있는 것을 그대로 쓴다.

## 2. 화면과 인터랙션

인사이트 패널 슬롯(280px, timer.md·completion-rate.md와 같은 자리 — 새 화면이 아니다):

```
 ┌ D-day ────────────────────────┐
 │ 🎂 생일           D-12         │   ← 임박순
 │ 📌 발표           D-1          │
 │ [+ D-day 추가]                  │
 │ ▸ 지난 날 (2)                   │   ← 접힘, 펼치면 최근순
 └─────────────────────────────────┘
```

- 항목 클릭: 날짜 스트립의 **선택 날짜**를 그 날로 옮긴다 — date-strip이 이미 제공하는 선택 함수(`onSelect`)를 그대로 부른다. 그 날이 다른 달이면 스트립이 알아서 그 달을 보여준다(date-strip R2의 `anchorDate` 갱신, 새 로직 없음).
- `[+ D-day 추가]`: 인라인 폼(제목 1줄 + 날짜 입력 — `MonthJump`와 같은 `input[type=date]`, 새 위젯이 아니다).
- 좁은 화면: 패널이 오버레이로 열릴 때 이 슬롯도 포함(app-shell §2-B와 동일 규약).

### 상태

- **빈 상태(D-day 없음)**: "다가오는 날을 기록해 보세요" + `[+ D-day 추가]`만.
- **로딩**: 목록 즉시(별도 스켈레톤 없음, 그리드 조회가 아니므로 가볍다).
- **에러**: D-day 저장 실패 시 폼 유지 + `role=alert`.

## 3. 규칙

- R1. D-day는 제목 1~30자 + 날짜(과거·미래 모두 허용). 최대 50개.
- R2. 정렬: 오늘 포함 미래(`date >= 오늘`)는 D-day 오름차순(가까운 순), 지난 항목은 접힌 "지난 날" 섹션에 최근순.
- R3. 표기: 오늘이면 `D-day`, 미래면 `D-n`, 과거면 `D+n`.
- R4. D-day는 카테고리·투두와 연결되지 않는 독립 이벤트다(할 일 자동 생성 없음). 반복 없음 — 매년 돌아오는 생일 같은 것은 routine.md의 확장 후보이지 여기서 다루지 않는다(§6).
- R5. 삭제는 확인 없이 즉시 + 6초 되돌리기 토스트(todo.md 삭제 패턴과 동일한 소프트 삭제).
- R6. **항목 클릭 시 날짜 이동은 date-strip이 이미 가진 선택 메커니즘을 그대로 부른다.** 이 스펙은 달력 그리드·연도 선택기·별도 날짜 이동 로직을 정의하지 않는다 — 전부 date-strip.md R1~R18에 이미 있다.

## 4. 데이터

- domain 신규 `Dday = Meta & { title, date: DateKey }`. D-n 계산은 `today`를 주입받는 순수 함수(timer.md R3와 같은 이유).
- 레포지토리 `DdayRepository.list()`·`upsert(Persistable<Dday>)`. 그 외 조회 없음 — 날짜 그리드·주간/월간 요약은 date-strip이 이미 하는 것을 손대지 않는다.

## 5. 접근성

- 목록은 `ul`, 각 행 "생일까지 12일"로 낭독.
- `[+ D-day 추가]` 폼: 제목 입력 초기 포커스, `Enter` 저장, `Esc` 취소.

## 6. 범위 밖

- **달력 그리드, 여러 달을 한 화면에 나란히 늘어놓는 레이아웃, 별도 연도 선택기** — date-strip.md R14~R18이 이미 구현했거나(월 보기·±1달 이동) 만들지 않기로 결정했다(멀티먼스 그리드, §1).
- 공휴일·음력, 다른 사람과 공유되는 일정, D-day 반복(생일 매년 — routine.md 확장 후보), 캘린더 위에 일정 겹쳐 보기(Tasky는 멀티데이 이벤트 모델이 없다).

## 7. 완료 조건

- [ ] R1~R6 테스트, D-n 계산 경계(오늘=D-day, 어제=D+1) 단위 테스트.
- [ ] 항목 클릭 → 메인 날짜 스트립의 선택 날짜·anchorDate 갱신 통합 테스트 1개(기존 date-strip 선택 로직을 그대로 호출하는지 확인).
- [ ] 키보드만으로 D-day 추가·삭제·되돌리기.
- [ ] 라이트/다크 스크린샷(D-day 0개/여러 개).
