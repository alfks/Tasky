# 캘린더 스펙

- 상태: implemented · 관련 ADR: - · 리서치 참조: reference-app-research.md §2.2(캘린더 화면), §9 기회 1

## 1. 목표

**여러 달을 오가며 훑는 것은 이미 됐다.** date-strip.md R14~R18(상태 `approved`, 배포됨)이 월 보기(‹/›로 ±1달)와 **년·월 피커**(월 표시를 누르면 연도 스테퍼 + 월 격자로 어떤 년·월로도 바로 이동, calendar-layout.md §3)를 이미 준다. 여러 달을 한 화면에 나란히 늘어놓는 그리드는 따로 만들지 않기로 정했다(§6 — P1·P2에 비해 값이 작다).

이 스펙이 남기는 것은 하나, **D-day**다 — 미리 정해 둔 날짜(생일·발표일 등)까지 며칠 남았는지 항상 보이는 자리에 두는 것. 새 그리드·새 날짜 이동 로직을 만들지 않는다 — 그 날짜로 이동하는 것은 이미 있는 것을 그대로 쓴다. **년·월 피커는 date-strip 소관**(calendar-layout.md §3)이고, **D-day 폼은 `input[type=date]` 를 그대로 쓴다** — 일 단위 입력이라 년·월 피커의 대상이 아니다.

## 2. 화면과 인터랙션

**카테고리쪽 사이드바 슬롯**(고정 컬럼·드로어 둘 다, 위치는 app-shell.md R6-a — 카테고리 목록 → **D-day** → 도구 줄. 사용자 결정으로 인사이트 패널에서 옮겨왔다 — 새 화면이 아니다):

```
 ┌ D-day ────────────────────────┐
 │ 🎂 생일           D-12      ✕  │   ← 임박순, ✕는 hover·포커스 시(포커스 시엔 항상)
 │ 📌 발표           D-1       ✕  │
 │ [+ D-day 추가]                  │
 │ ▸ 지난 날 (2)                   │   ← 접힘, 펼치면 최근순
 └─────────────────────────────────┘
```

- 항목 클릭: 날짜 스트립의 **선택 날짜**를 그 날로 옮긴다 — date-strip이 이미 제공하는 날짜 선택 동작을 그대로 부른다(새 이동 로직을 만들지 않는다). 그 날이 다른 달이면 스트립이 보여주는 달도 자연히 그 날의 달로 바뀐다(월 보기·주 보기 모두 선택 날짜를 따라간다는 것은 date-strip.md §2-A-2·§3-A가 이미 보장한다).
- 각 항목의 `✕`: 그 D-day를 지운다(R5).
- `[+ D-day 추가]`: 인라인 폼(제목 1줄 + 날짜 입력 — 일 단위 `input[type=date]`, 새 위젯이 아니다. 년·월만 고르는 date-strip 의 피커와는 대상이 다르다, calendar-layout.md §3).
- 좁은 화면: 사이드바가 드로어로 열릴 때 이 슬롯도 포함(app-shell §2-B와 동일 규약 — 이제 인사이트 오버레이가 아니라 카테고리 드로어 쪽이다).

### 상태

- **빈 상태(D-day 없음)**: "다가오는 날을 기록해 보세요" + `[+ D-day 추가]`만.
- **로딩**: 목록 즉시(별도 스켈레톤 없음, 그리드 조회가 아니므로 가볍다).
- **에러**: D-day 저장 실패 시 폼 유지 + `role=alert`.

## 3. 규칙

- R1. D-day는 제목 1~30자 + 날짜(과거·미래 모두 허용). 최대 50개.
- R2. 정렬: 오늘 포함 미래(`date >= 오늘`)는 D-day 오름차순(가까운 순), 지난 항목은 접힌 "지난 날" 섹션에 최근순.
- R3. 표기: 오늘이면 `D-day`, 미래면 `D-n`, 과거면 `D+n`.
- R4. D-day는 카테고리·투두와 연결되지 않는 독립 이벤트다(할 일 자동 생성 없음). 반복 없음 — 매년 돌아오는 생일 같은 것은 향후 검토 대상이다(routine.md는 현재 이를 다루지 않는다, §6).
- R5. 삭제는 각 항목의 `✕`(§2)로 확인 없이 즉시 실행 + 6초 되돌리기 토스트 — **UX는 todo.md R10·R20(이동)의 무확인·즉시·되돌리기 패턴과 같고**, 데이터를 남기는 방식(물리 삭제 없음)은 todo.md R13과 같은 소프트 삭제 메커니즘이다(todo.md R13 자체의 확인 대화상자 UX와는 다르다 — 항목 하나짜리 독립 이벤트라 파괴성이 낮다고 판단).
- R6. **항목 클릭 시 날짜 이동은 date-strip이 이미 가진 선택 메커니즘을 그대로 부른다.** 이 스펙은 달력 그리드·년·월 피커·별도 날짜 이동 로직을 정의하지 않는다 — 전부 date-strip.md R1~R18과 calendar-layout.md §3에 이미 있다.

## 4. 데이터

- domain 신규 `Dday = Meta & { title, date: DateKey }`. D-n 계산은 `today`를 주입받는 순수 함수(timer.md R3와 같은 이유).
- 레포지토리 `DdayRepository.list()`·`upsert(Persistable<Dday>)`. 그 외 조회 없음 — 날짜 그리드·주간/월간 요약은 date-strip이 이미 하는 것을 손대지 않는다.

## 5. 접근성

- 목록은 `ul`, 각 행 "생일까지 12일"로 낭독. `✕`는 `button aria-label="생일 삭제"`, 포커스 시 항상 보임(hover 전용 아님 — 키보드만으로도 도달·실행 가능).
- `[+ D-day 추가]` 폼: 제목 입력 초기 포커스, `Enter` 저장, `Esc` 취소.

## 6. 범위 밖

- **달력 그리드, 여러 달을 한 화면에 나란히 늘어놓는 레이아웃** — date-strip.md R14~R18이 이미 구현했거나(월 보기·±1달 이동) 만들지 않기로 결정했다(멀티먼스 그리드, §1). **년·월 피커는 date-strip 소관**(calendar-layout.md §3), **D-day 폼은 `input[type=date]` 유지**.
- 공휴일·음력, 다른 사람과 공유되는 일정, D-day 반복(생일 매년 — routine.md 확장 후보), 캘린더 위에 일정 겹쳐 보기(Tasky는 멀티데이 이벤트 모델이 없다).
