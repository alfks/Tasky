# 친구와 기록 공유 스펙

- 상태: approved · 관련 ADR: [ADR-0022](../decisions/ADR-0022-social-projection-and-authorization.md)·[ADR-0024](../decisions/ADR-0024-category-visibility.md) · 구현 상태: 예정

## 1. 목표

사용자가 고른 완료 기록 한 건을 친구에게 보여 주고 가볍게 응원받는다. 투두를 쓰는 기본 화면과 습관은 유지한다.
첫 출시는 초대받은 친구끼리 사용하는 작은 범위다. 소셜 참여는 선택이며 로그인만으로 프로필이나 게시물이 생기지 않는다. 게시문은 사용자가 작성한 기록이며 앱이 완료 사실을 인증한 표시를 붙이지 않는다.
카테고리 범위의 추가 계약은 [공개범위 설계](../category-visibility-design.md). 기존 기술 계약은 [상세 설계](../social-design.md), 순서와 출시 검증은 [구현 계획](../phase3-implementation-plan.md)이 단일 소스다.

## 2. 화면과 인터랙션

데스크탑: 사이드바 도구 영역의 `[친구]` → 본문을 친구 화면으로 전환한다. 달력·인사이트는 친구 화면에서 숨긴다. **진입점은 두 곳**이다 — 사이드바 `[친구]` 와 **프로필 카드 본문**(검색 입구 아래, 접근 이름 "친구 화면 열기", profile.md R11-a); 둘 다 같은 경로(지연 청크·포커스 복귀·오프라인 문구)를 타고, 돌아오면 포커스는 눌렀던 쪽으로 간다. 친구 화면이 보여 주는 것은 친구가 공유한 사본(피드)뿐이다(R1).
상단은 `[내 할 일로] 친구 [새로고침]`, 아래 `[피드] [친구 관리] [내 공유]`. 달력 선택 날짜와 스크롤은 돌아갈 때 복원한다.
피드는 시간순 한 열이고 카드에는 별명·공유 날짜·공유 문장·`[응원]`·`[더 보기]`가 있다. 페이지는 `[이전 기록] [다음 기록]`으로 바꾸며 한 페이지씩 보여 준다. 페이지 전환 시 맨 위로 이동하고 목록 제목에 포커스를 둔다. 이전 페이지도 새로 불러온다.
좁은 화면: 기존 사이드바 드로어에서 같은 항목을 열거나 프로필 카드 본문을 누른다. 탭과 본문은 한 열, 작성·확인 창은 화면 안에서 스크롤한다. 하단 투두 추가 버튼은 숨긴다.
친구 화면은 최초 앱 진입 화면이 되지 않으며 투두 단축키가 친구 화면의 입력을 가로채지 않는다.

첫 진입: `친구에게 보일 별명` 입력 → `[시작하기]`. 이메일·구글 이름·사진을 자동 공개하지 않는다.
`친구 관리 → 친구 초대 → 초대 만들기 → 링크 복사`로 사용자가 직접 전달한다. 화면은 만료 시점·사용 여부·`[초대 취소]`를 보여 준다.
초대 링크 열기 → 필요하면 로그인 → 별명 확인 → `[친구 요청 보내기]` → 보낸 요청 목록. 링크를 열기만 해서는 요청이 생기지 않는다.
복사 실패 시 선택 가능한 링크와 수동 복사 안내를 준다. 본인 초대는 요청할 수 없고, 이미 친구면 `[친구 피드로]`, 역방향 요청이 있으면 `[받은 요청 보기]`를 제공한다. 초대 도중 별명을 만들면 원래 초대 확인 화면으로 돌아온다.
받는 쪽은 `받은 요청 → [수락] 또는 [거절]`. 양쪽이 요청했어도 자동 친구가 되지 않는다.

공유: `내 공유 → 기록 공유 → 완료한 할 일 선택 → 공개 문장 미리보기·수정 → [친구에게 공유]`.
완료한 항목이 없으면 `완료한 할 일이 생기면 여기에서 골라 공유할 수 있어요`와 `[내 할 일로]`를 보여 준다.
선택 날짜를 바꾸어 과거 완료 기록도 고를 수 있다. 한 번에 한 건만 선택한다. 기본 선택은 없고 원본 메모·식별자는 전송하지 않는다. 공개 카테고리 metadata와 현재 범위는 미리보기에서 확인한다.
미리보기는 실제 카드와 같은 문장·기록 날짜·공개 카테고리·범위를 보여 준다. 친구만인 경우 다음 안내를 항상 붙인다. 모두 공개에서는 비로그인 방문자도 읽는다고 고지한다.
`현재 친구와 앞으로 추가할 친구가 볼 수 있어요. 원래 할 일을 수정하거나 지워도 이 공유는 남아요. 내 공유에서 따로 지울 수 있어요.`
친구만인 공유에 친구가 없으면 `친구를 추가하면 이 기록이 보여요`를 덧붙인다. 모두 공개에는 친구 유무 안내를 붙이지 않는다. 확인 버튼은 카테고리 범위에 맞는 명시적 `[공유하기]`이고 Enter만으로 제출하지 않는다. 나만 보기 카테고리는 별도 범위 변경 확인 없이 외부에 공유하지 않는다.
작성 중 Esc·뒤로·탭 변경은 미전송 문장이 있으면 `[계속 작성] [버리기]`를 확인한다. 같은 계정의 일시적 연결 실패에는 문장을 메모리에 보존하지만 새로고침하면 지워짐을 안내한다.
공유 성공 뒤 카드에 포커스를 옮기고 `친구에게 공유했어요` 또는 `모두 공개로 공유했어요`를 현재 범위에 맞게 알린다. 원본 수정은 공유 문장에 전파되지 않는다.
`내 공유 → 더 보기 → 공유 삭제 → 확인`하면 온라인 서버 성공 후 카드가 제거된다. 삭제한 공유는 복원하지 않는다.

## 3. 규칙

- R1. 개인 기록은 항상 개인 전용이다. 공유는 사용자가 문장을 확인하고 명시적으로 게시한 별도 사본에만 적용된다. 기존 자료의 일괄 공개·자동 공개는 없다.
- R2. 원본은 개인 전용이며 카테고리의 명시적 공유 사본은 `나만 보기`·`친구만`·`모두 공개`다. [공개범위 스펙](category-visibility.md)에 따라 카테고리 metadata와 직접 확인한 사본만 보여 준다. 기존 카테고리는 나만 보기, 기존 무카테고리 공유는 친구 범위를 유지한다.
- R3. 별명은 중복 가능하며 길이·내용 제한은 상세 설계의 입력 계약을 따른다. 이메일 검색·주소록 업로드·공개 사용자 검색은 없다.
- R4. 초대는 한 번만 사용하고 만료된다. 요청 수락 전에는 상대 별명과 요청 상태를 보고 친구 전용 기록은 읽지 못한다. 모두 공개 기록은 별도 공개 화면에서 볼 수 있다. 초대 발급자의 친구 수락을 별도로 요구한다.
- R5. 요청은 보낸 사람이 취소하고 받은 사람이 거절/수락한다. 친구 삭제는 어느 쪽이든 가능하고 양쪽 친구 전용 공유 접근을 끊는다. 모두 공개 자료의 공개 읽기는 유지된다. 확인 창은 현재 영향과 `[취소]`를 제공한다.
- R6. 차단은 친구·받은 요청·게시물 더 보기에서 가능하다. 차단 즉시 관계·양방향 요청을 끊고 이후 상대의 새 요청·인증된 공유 접근을 막는다. 모두 공개 기록은 로그아웃하면 읽을 수 있음을 안내한다. 상대에게 알림은 보내지 않는다. `친구 관리 → 차단한 사용자`에서 해제해도 친구·요청·응원은 복원되지 않는다.
- R7. 피드는 현재 친구와 자신의 공유를 게시 시각 내림차순으로 보여 준다. 새 친구에게 이전 공유도 보이며 공유 미리보기에서 이를 고지한다. 반응·수정으로 순서를 올리지 않는다.
- R8. 응원은 한 계정당 한 게시물에 한 개, 다시 누르면 취소한다. 작성자는 자기 글에 응원하지 못한다. 수와 내 선택만 표시하고 반응한 사람의 목록은 공개하지 않는다.
- R9. 공유 삭제는 해당 사본과 반응을 서버에서 지운다. 원본 삭제·완료 취소·백업 복원은 공유를 바꾸지 않는다. 자신의 공유 목록에서 모든 공유를 찾아 삭제할 수 있다.
- R10. 친구 삭제·차단·공유 삭제의 성공 안내는 서버 확인 뒤에만 한다. 온라인 다른 화면도 다음 검증 시 내용을 숨긴다. 이미 본 내용이나 캡처의 회수는 보장하지 않는다.
- R11. 공유 읽기·쓰기는 온라인 전용이다. 오프라인 작업을 쌓았다가 자동으로 공유·친구 수락하지 않는다. 연결 복귀 시 목록을 새로 확인한다.
- R12. 새 글은 읽는 위치를 밀지 않고 `[새 기록 보기]`로 알린다. 수동 새로고침·복귀는 최신 목록을 검증하며 페이지 전환은 누적 없이 새 페이지로 교체하고 중복을 제거한다. 화면이 보이는 동안 주기적 첫 페이지 확인으로 새 글 여부를 알아내고, `[새 기록 보기]`를 누르면 첫 페이지로 교체·스크롤을 맨 위로 이동·목록 제목에 포커스를 둔다.
- R13. 공유·차단·친구 삭제·요청 처리 중 해당 동작을 중복 실행할 수 없다. 응답이 사라지면 완료 여부를 확인하고 동일 요청으로 재시도한다. 오래된 화면의 변경은 최신 상태 안내 후 사용자가 다시 결정한다.
- R14. 계정 삭제는 자신의 프로필·공유·반응·관계·초대를 함께 제거한다. 동일 구글 계정으로 재가입해도 소셜 관계와 공유는 복원되지 않는다.
- R15. 친구 화면의 조작 상태·오류는 개인 동기화 상태와 구별한다. 소셜 장애가 할 일 읽기·쓰기나 개인 동기화를 막지 않는다.
- R16. 기능 제공 중단 시 공유 콘텐츠를 숨기되 기존 공유 삭제·친구 삭제·차단·계정 삭제에 접근할 관리 화면을 제공한다.

## 4. 데이터

공개 프로필·친구 관계·초대·공유 사본·응원은 개인 투두·다이어리·백업과 별도 계약이다. 공개 식별자는 구글 계정 식별자와 다르다.
도메인 타입·저장소 포트·API·보존 기간은 [상세 설계](../social-design.md)에 정의한다. 개인 백업으로 관계나 공유를 복원하지 않는다.

## 5. 접근성

탭·버튼·목록·카드 제목에 의미 있는 이름을 준다. 응원은 `aria-pressed`와 `응원 취소/응원하기`로 상태를 전달한다.
Tab 순서는 화면 제목 → 탭 → 주 행동 → 목록이다. 열기 직전 버튼을 기억하고 닫기 시 복귀한다. 삭제된 버튼이면 다음 카드 → 이전 카드 → 목록 제목 순으로 가능한 곳에 이동한다.
대화상자는 기존 app-shell R14(초기 비파괴 포커스·Esc 취소·IME 조합 Enter 제외)를 따른다. 공유 미리보기는 초기 포커스를 제목에 두고 명시적 버튼으로 제출한다.
오류는 입력 가까이 `aria-describedby`, 처리 결과는 `aria-live="polite"`로 한 번 알린다. 숫자만 변하는 폴링은 매번 읽지 않는다.
색·이모지만으로 상태를 전달하지 않는다. 테마 토큰·강제 색 모드·reduced-motion을 따른다. 좁은 화면과 확대에서 가로 스크롤 없이 주요 행동을 완료한다.

## 6. 범위 밖

사람 검색·팔로우·추천 피드·댓글·DM·멘션·그룹·이미지·외부 링크 미리보기·푸시·메일 초대 발송·인기 순위·일괄 공유·공유 자동 갱신·공유 편집.
서버 신고/중재 시스템은 제한된 초대 시범 운영의 후속이다. 공개 모집으로 확대하려면 신고·운영자 처리·정책을 먼저 설계한다.

## 7. 완료 조건

- [ ] 서로 다른 두 계정과 두 기기로 초대→요청→수락→명시적 공유→응원→삭제를 완료한다.
- [ ] 비친구·거절·삭제·차단·계정 삭제·재가입·만료 초대에서 공유 데이터가 새로 노출되지 않는다.
- [ ] 원본 수정/삭제·완료 취소·백업 복원이 공유 사본을 자동 공개·갱신·복원하지 않는다.
- [ ] 실패·중복·응답 소실·경합을 재현해 중복 글/관계/반응 없이 상태가 설명된다.
- [ ] 오프라인·백그라운드·로그아웃·계정 전환 시 공유가 가려지고 개인 할 일 사용은 유지된다.
- [ ] 키보드·스크린리더·좁은 화면으로 전체 흐름과 오류 복구를 완료한다.
- [ ] 출시 게이트는 구현 계획의 증거 목록으로 확인하며 스펙 승인만으로 구현 완료를 선언하지 않는다.
