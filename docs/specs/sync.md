# 동기화 스펙

- 상태: draft(진입 조건 미충족) · 관련 ADR: 없음 — **동기화 ADR 선행 필요**(product-overview.md §6 Phase 2 진입 조건) · 리서치 참조: reference-app-research.md §4(실시간 동기화, Firebase 추정), §7 User 모델, §9 과제

## 1. 목표

Tasky는 계정 없이도 완전히 동작하는 로컬 우선 앱이다(P5, 비목표 §7). 동기화는 그 원칙을 깨지 않고 **선택 가능한 기능**으로 더한다 — 로그인하지 않는 사용자는 지금과 똑같이 쓴다. 이 문서는 구현 규칙이 아니라 **ADR을 쓰기 전에 정해야 할 질문과 이미 정해진 제약**을 모은다.

## 2. 화면과 인터랙션 (방향만, 확정 아님)

설정 화면(마이페이지, 신규):

```
 계정(로그인 전)                          계정(로그인 후)
 │ 로그인하지 않음                    │   │ millie@example.com          [로그아웃] │
 │ [이메일로 로그인 / 계정 만들기]     │   │ 마지막 동기화: 방금 · 상태: ● 동기화됨  │
 │ 로그인하면 이 기기의 데이터를 다른  │   │ 충돌 발생 시: [충돌 N건 확인]           │
 │ 기기와 함께 볼 수 있어요.           │
```

## 3. 이미 정해진 것 (product-overview.md·ARCHITECTURE.md 기준, 되돌리지 않는다)

- R1. 로컬 IndexedDB가 **항상 진실의 원본**이다. 서버는 로컬 데이터의 복제·중계이지 유일한 저장소가 아니다(오프라인에서도 앱은 완전히 동작).
- R2. 계정은 **선택**이다. 로그인하지 않는 사용자에게는 지금(MVP)과 동일한 무계정 경험이 유지된다(비목표 §7 유지, 로그인 강제 없음).
- R3. 저장소 계층 확장은 `src/infra/sync/`(어댑터·충돌 정책) + `repositories/sync-repository.ts`(ARCHITECTURE.md "클라우드 동기화" 행)에만 붙는다. 기존 `CategoryRepository`·`TodoRepository` 등의 인터페이스는 바뀌지 않는다(구현이 로컬만 쓰다가 로컬+원격을 쓰도록 바뀔 뿐).
- R4. 동기화 대상은 소프트 삭제(tombstone) 포함 **전체 변경 이력**이다 — `listChangedSince(rev)` 형태로 ADR-0005·0007의 소프트 삭제·`touch` 규약을 원격에도 그대로 적용한다(물리 삭제가 없다는 원칙은 동기화에서도 유지).
- R5. 충돌 정책은 **필드 단위 최신 갱신 우선(LWW, `updatedAt` 비교)**을 기본값으로 가정한다(리서치에 근거 없음, Tasky 단독 결정) — 두 기기가 같은 항목을 동시에 고쳤을 때 사용자에게 병합 UI를 강요하지 않는다. 예외(카테고리 삭제 vs 투두 이동처럼 category.md R13류 원자적 쓰기)는 ADR에서 별도로 정한다.

## 4. ADR에서 정할 것 (여기서 확정하지 않는다)

- 인증 방식(이메일+비밀번호 / OAuth / 매직 링크)과 서버·백엔드 선택(Cloudflare Workers 생태계 유지 여부 — 배포가 이미 Cloudflare이므로 D1/KV 등이 후보).
- 동기화 트리거(실시간 웹소켓 vs 주기적 폴링 vs 수동 "지금 동기화") — 비목표 §7이 "실시간 동기화"를 MVP에서 제외한 것과 같은 이유(복잡도)로, Phase 2도 실시간을 기본값으로 가정하지 않는다.
- 다중 기기 동시 편집 시 R5 예외 목록과 사용자에게 보여줄 충돌 UI(리스트? 자동 해결 후 알림만?).
- 계정 삭제·데이터 이관(로그아웃 후 로컬 데이터를 지울지 남길지).
- 무료/프리미엄 여부(연구 §4는 레퍼런스 앱이 유료화했지만, Tasky가 결제를 들일지는 별도 결정 — P5·계정 없음 원칙과 충돌 가능성 있음).

## 5. 접근성

- (ADR 이후 확정) 로그인 폼·동기화 상태 표시기·충돌 확인 화면은 기존 다이얼로그·토스트 패턴(app-shell.md)을 재사용한다는 방향만 유지.

## 6. 범위 밖

- 실시간 협업 편집, SNS 연동(Phase 3 `social.md`, 동기화 서버가 있어야 성립), 다른 서비스 계정 연동(구글·애플 로그인)은 ADR에서 1차 범위 제외를 검토, 오프라인 우선 원칙을 흔드는 어떤 변경(R1)도 없음.
