# 루틴 스펙

- 상태: draft · 관련 ADR: - · 리서치 참조: reference-app-research.md §2.4(루틴 관리), §3-4, §7 데이터 모델(Routine)

## 1. 목표

**이 스펙은 새 기능이 아니라 `todo.md` R21의 확장이다.** R21은 이미 MVP에 있다 — 항목 메뉴 "루틴으로 등록"에서 시작~종료일과 반복 패턴을 고르면 그 범위 전체에 투두를 즉시 한 번에 만든다. 다만 "루틴 자체는 저장하지 않는다"(R21 본문) — 끝을 모르면(예: "매일 운동, 언제까지고") 쓸 수 없고, 반복 정의를 나중에 고치거나 멈추는 방법이 없다.

여기서 더하는 것은 하나뿐이다: **종료일을 몰라도(무기한) 계속 반복되게 하는 것.** 그러려면 이번엔 반복 규칙 자체를 저장해 두고, 날짜를 넘길 때마다 이어서 채운다. 진입점·문구·중복 방지·되돌리기는 R21 그대로 두고 그 위에 얹는다 — 사용자가 새로 배울 것은 "종료일을 비울 수 있다"는 것 하나뿐이다. **종료일을 채우는 지금 흐름(R21)은 한 글자도 바뀌지 않는다** — 이 스펙의 모든 새 규칙은 종료일을 비웠을 때만 켜진다.

## 2. 화면과 인터랙션

"루틴으로 등록" 다이얼로그(R21과 같은 다이얼로그, 종료일 옆 한 줄만 늘어난다):

```
 ┌ 루틴 등록 ─────────────────────── ✕ ┐
 │ 제목 [ 운동                        ] │   ← R21 그대로(제목·메모·카테고리)
 │ 메모 [                             ] │
 │ 카테고리 [ 🏃 운동 ▾ ]               │
 │ 반복 주기 [ 매주 ▾ ]  (매일/매주/매달) │   ← "매일" 신규, 나머지 R21 그대로
 │ 반복 요일  일 월 화 수 목 [금] [토]   │
 │ 시작일 [ 2026-09-20 ]                 │
 │ 종료일 [ 2026-10-04 ]  ☐ 계속 반복    │   ← 신규: 체크하면 종료일 입력 비활성 + 빈값
 │                          [취소][루틴 등록] │
 └────────────────────────────────────────┘
```

관리 화면(신규, 사이드바 "루틴" 진입점 → 다이얼로그, category.md 구조 재사용):

```
 루틴
 │ 🏃 운동         매주 금·토 · 계속        ⋯ │   ← ⋯: 중지·재개·삭제
 │ 📚 독서         매주 화·목 · ~10/4       ⋯ │   ← 종료일 있는 루틴도 목록엔 남는다(기록 겸 관리)
 + 루틴 추가                                    ← 두 번째 진입점: 항목 없이 카테고리부터 고른다
```

투두 화면(todo.md 확장): 루틴에서 나온 투두는 제목 옆 🔁 아이콘(hover "매주 금·토 반복").

### 상태

- **빈 상태(관리 화면)**: "아직 계속 반복되는 루틴이 없어요" + `[+ 루틴 추가]`(종료일 있는 R21 등록은 여기 세지 않는다 — 관리할 것이 없으므로. R5 참고).
- **로딩**: 스켈레톤 2행. **에러**: category.md §2-D와 동일 문구·패턴. R21의 등록 폼 에러 문구·검증(빈 제목, 요일 미선택, 날짜 범위 등)은 전부 그대로 재사용한다.

## 3. 규칙

- R1. 반복 패턴에 `daily`(매일, 신규)를 더한다. `weekly`(요일 다중, R21 기존)·`monthly`(일 다중, 쉼표 구분, R21 기존 파싱 그대로 — 조각 하나라도 무효면 전체 무효)는 그대로. N일 간격 커스텀 주기는 범위 밖(§6).
- R2. 시작일은 필수(R21 그대로). **종료일은 선택**이다 — 비우면(체크박스 "계속 반복") 무기한. 이것이 R21과의 유일한 입력 차이다.
- R3. **즉시 채우기 범위**: 종료일이 있으면 R21 그대로 시작~종료일 전체(상한 없음, 실질 한도는 date-strip 범위). 종료일이 없으면 등록 시점에 **지금 보이는 날짜 범위**(date-strip.md §4가 이미 읽는 범위, 주 또는 월 보기)까지만 즉시 채운다 — 새 조회·새 상수를 만들지 않고 이미 있는 범위를 그대로 쓴다. 그 뒤는 R6가 이어 채운다.
- R4. 즉시 채우기는 R21과 **완전히 같은 절차**를 쓴다: 같은 날짜·카테고리·정규화된 제목이 이미 있으면 건너뛰기(dedup) · 생성 개수 토스트("n개의 할 일을 만들었어요 [되돌리기]") · 6초 되돌리기(이번에 새로 만든 것만 되감는다, R21과 동일). 반복 조건에 맞는 날짜가 전부 이미 등록돼 있으면 R21과 같은 안내("이미 전부 등록돼 있어요").
- R5. **이 등록은 이제 `Routine` 레코드도 함께 남긴다**(R21과의 핵심 차이 — R21은 저장하지 않았다). 종료일이 있는 등록도 레코드를 남기지만(관리 화면에 기록으로 보임), R6가 할 일이 없으므로(이미 다 채웠다) 실질적으로 완료된 채로 보인다 — 별도 상태값을 만들지 않는다(단순함 우선).
- R6. **지연 생성**(무기한 루틴에서만 의미가 있다 — 종료일 있는 루틴은 R3가 이미 끝까지 채웠다): 날짜 스트립·캘린더가 새 날짜 범위를 읽을 때(date-strip.md §4), 그 범위 안에서 이 루틴 패턴에 맞는데 아직 없는 날짜만 조용히 채운다(토스트 없음 — 사용자의 행동은 "날짜 이동"이지 "루틴 만들기"가 아니므로). dedup은 R4와 같은 규칙.
- R7. 루틴 **중지**(관리 화면, `active=false`): 이후 R6 지연 생성을 멈춘다. 이미 만든 인스턴스는 남는다. **재개**하면 다시 R6가 이어진다 — 멈춰 있던 구간을 소급해서 채우지 않는다(지금부터).
- R8. 루틴 규칙(반복 패턴·카테고리 등) 수정은 **그 시점 이후 생성분에만** 적용된다. 이미 만든 인스턴스는 독립 투두라 바뀌지 않는다(수정 즉시 재실행 없음).
- R9. 인스턴스는 실제 `Todo`이고, 만들어진 뒤에는 **완전히 독립적**이다(R21 원칙 그대로 확장) — 그 날짜 것만 고쳐도(제목·메모·카테고리) 다른 날짜·미래 생성분에 영향 없음, 지워도 이후 생성에 영향 없음.
- R10. 루틴 **삭제**(관리 화면, 중지와 별개 메뉴 항목): 과거 인스턴스의 `routineId` 연결은 유지(기록 보존, 🔁 아이콘만 사라짐 — 원본 없음), 이후 생성은 중단.
- R11. 루틴이 가리키는 카테고리가 삭제되면 `categoryId`를 비운다(카테고리 없이 계속 생성). 인스턴스는 category.md R17처럼 "(삭제됨)" 그룹.
- R12. **진입점은 둘**이다: (a) 항목 메뉴 "루틴으로 등록"(R21 그대로, 이번엔 종료일을 비울 수 있을 뿐), (b) 관리 화면의 "+ 루틴 추가"(신규, 항목 없이 카테고리부터 골라 새로 만든다).

## 4. 데이터

- domain: 기존 `RoutineRecurrence`(`{type:'weekly', daysOfWeek}` | `{type:'monthly', daysOfMonth}`, `src/domain/todo/routine.rules.ts`)에 `{type:'daily'}`를 더한다. 즉시 채우기(R3·R4)는 기존 `expandRoutineDates`를 그대로 쓴다. 지연 생성(R6) 판정은 신규 순수 함수 `shouldMaterialize(routine, date) → boolean`(날짜만 입력받는다, 시각 의존 없음).
- 신규 저장 엔티티 `Routine = Meta & { title, memo?, categoryId?: CategoryId, recurrence: RoutineRecurrence, startDate: DateKey, endDate?: DateKey, active: boolean }`. `Todo.routineId?: RoutineId` — 기존 `createRoutine` 스토어 액션(R21 구현)이 만드는 투두에도 이제 이 필드를 채운다. 타입 변경은 필드 추가뿐, 기존 `createRoutine`의 반환(`TodoId[] | false`)은 바뀌지 않는다.
- 레포지토리 `RoutineRepository.list({ includeInactive })`·`upsert(Persistable<Routine>)`. 지연 생성은 date-strip이 이미 하는 `TodoRepository.listByDateRange` 결과에 없는 (routine, date) 쌍만 `TodoRepository.upsert`로 채운다(중복 생성 방지는 `(routineId, date)` 유일 제약 — 계약 테스트).

## 5. 접근성

- "계속 반복" 체크박스: `checkbox` + 체크 시 종료일 `input`에 `disabled` + `aria-describedby`로 "계속 반복돼요" 설명.
- 반복 주기 선택은 R21의 `select`를 그대로 쓴다("매일" 옵션만 추가). 요일 토글·일(day) 입력은 R21 그대로.
- 관리 화면: 목록 `ul > li`, 행 메뉴 `aria-label="운동 루틴 메뉴"`, 상태는 텍스트 병기("계속" / "~10/4" / "중지됨") — 색만으로 구분하지 않는다.
- 🔁 아이콘은 텍스트 대체("루틴: 매주 금·토")가 있다.

## 6. 범위 밖

- N일 간격 커스텀 주기(필요해지면 후속 R로 추가), 인스턴스 일괄 재수정("이후 전체 적용" — 구글 캘린더식 분기, todo.md §6과 동일 이유로 유지), 루틴 알림/리마인더, 루틴별 통계 상세(합산은 stats.md), 다른 사람과 공유하는 루틴, 날짜 없는 반복(보관함 연동은 별도 스펙 필요, product-overview.md §6).
- R3의 "지금 보이는 날짜 범위"만큼만 즉시 채우는 버퍼 크기는 구현 시 실사용으로 조정 가능한 값이지 고정 상수가 아니다.

## 7. 완료 조건

- [ ] **회귀 없음이 전제다** — 기존 R21 테스트(`RoutineDialog.test.tsx`, `todo-routine.test.ts`, 22건)가 이 확장 이후에도 그대로 통과한다(종료일을 채우는 지금 흐름은 한 글자도 안 바뀐다).
- [ ] R1~R12 테스트: 무기한 등록 → 보이는 범위만 즉시 생성 → 날짜 스트립으로 그 밖 날짜 이동 → 그 시점에 지연 생성(R6) → 중지 → 더 생기지 않음 → 재개 → 다시 생김(소급 없음, R7).
- [ ] `(routineId, date)` 중복 생성 방지 계약 테스트(memory·indexeddb).
- [ ] 키보드만으로: 항목 메뉴로 무기한 루틴 등록 → 관리 화면 진입 → 중지 → 재개 → 삭제.
- [ ] 라이트/다크 스크린샷(다이얼로그의 "계속 반복" 체크, 관리 화면, 🔁 배지 투두).
