# 루틴 스펙

- 상태: approved · 관련 ADR: - · 리서치 참조: reference-app-research.md §2.4(루틴 관리), §3-4, §7 데이터 모델(Routine)

## 1. 목표

**이 스펙은 새 기능이 아니라 `todo.md` R21의 확장이다.** R21은 이미 MVP에 있다 — 항목 메뉴 "루틴으로 등록"에서 시작~종료일과 반복 패턴을 고르면 그 범위 전체에 투두를 즉시 한 번에 만든다. 다만 "루틴 자체는 저장하지 않는다"(R21 본문) — 끝을 모르면(예: "매일 운동, 언제까지고") 쓸 수 없고, 반복 정의를 나중에 고치거나 멈추는 방법이 없다.

사용자가 **더 고르는 것**은 하나뿐이다: 종료일을 비우는 것("계속 반복"). 그러려면 이번엔 반복 규칙 자체를 저장해 두고, 날짜를 넘길 때마다 이어서 채운다. 진입점·문구·중복 방지·되돌리기는 R21 그대로 두고 그 위에 얹는다. **종료일을 채우는 지금 흐름(R21)은 한 글자도 바뀌지 않는다** — 이 스펙의 모든 새 규칙은 종료일을 비웠을 때만 켜진다.

그 하나가 실제로 동작하려면 **최소 세 가지가 따라온다**: ① 규칙을 저장할 `Routine` 레코드(R5), ② 저장된 걸 보고 멈출 수 있는 관리 화면(R7·R10, 안 그러면 "계속 반복"을 고른 뒤 되돌릴 방법이 없다), ③ 항목 없이도 새로 만들 수 있는 두 번째 진입점(R12-b, 관리 화면만 있고 거기서 새로 만들 길이 없으면 화면 하나가 헛돈다). 이 셋은 "무기한"이라는 개념이 요구하는 최소 세트이지 별도로 얹는 기능이 아니다 — P2(기능은 더하지 않고 접는다)는 이 셋을 줄이는 게 아니라, 그 밖의 것을 안 만드는 것으로 지킨다(예: 전용 "매일" 반복 유형 — 매주에서 요일 7개를 다 고르면 되므로 만들지 않는다, §6).

## 2. 화면과 인터랙션

"루틴으로 등록" 다이얼로그(R21과 같은 다이얼로그, 종료일 옆 한 줄만 늘어난다):

```
 ┌ 루틴 등록 ─────────────────────── ✕ ┐
 │ 제목 [ 운동                        ] │   ← R21 그대로(제목·메모·카테고리)
 │ 메모 [                             ] │
 │ 카테고리 [ 🏃 운동 ▾ ]               │
 │ 반복 주기 [ 매주 ▾ ]  (매주/매달, R21 그대로) │
 │ 반복 요일  일 월 화 수 목 [금] [토]   │
 │ 시작일 [ 2026-09-20 ]                 │
 │ 종료일 [ 2026-10-04 ]  ☐ 계속 반복    │   ← 신규: 체크하면 종료일 입력 비활성 + 빈값
 │                          [취소][루틴 등록] │
 └────────────────────────────────────────┘
```

관리 화면(신규, 사이드바 "루틴" 진입점 → 다이얼로그, category.md 구조 재사용):

```
 루틴
 │ 🏃 운동         매주 금·토 · 계속        ⋯ │   ← ⋯: 중지·재개·삭제(무기한 루틴만 중지·재개가 있다)
 │ 📚 독서         매주 화·목 · ~10/4       ⋯ │   ← 종료일 있는 루틴은 기록일 뿐(R7-a) — ⋯: 삭제만
 + 루틴 추가                                    ← 두 번째 진입점: 항목 없이 카테고리부터 고른다
```

투두 화면(todo.md 확장): 루틴에서 나온 투두는 제목 옆 🔁 아이콘(hover "매주 금·토 반복").

### 상태

- **빈 상태(관리 화면)**: "아직 계속 반복되는 루틴이 없어요" + `[+ 루틴 추가]`(종료일 있는 R21 등록은 여기 세지 않는다 — 관리할 것이 없으므로. R5 참고).
- **로딩**: 스켈레톤 2행. **에러**: category.md §2-D와 동일 문구·패턴. R21의 등록 폼 에러 문구·검증(빈 제목, 요일 미선택, 날짜 범위 등)은 전부 그대로 재사용한다.

## 3. 규칙

- R1. 반복 패턴은 R21 그대로 `weekly`(요일 다중)·`monthly`(일 다중, 쉼표 구분, 조각 하나라도 무효면 전체 무효)뿐이다. 전용 "매일" 유형, N일 간격 커스텀 주기는 범위 밖(§6).
- R2. 시작일은 필수(R21 그대로). **종료일은 선택**이다 — 비우면(체크박스 "계속 반복") 무기한. 이것이 R21과의 유일한 입력 차이다.
- R3. **즉시 채우기 범위**: 종료일이 있으면 R21 그대로 시작~종료일 전체(상한 없음, 실질 한도는 date-strip 범위). 종료일이 없으면 **시작일부터, 지금 보이는 날짜 범위(date-strip.md §4)의 끝까지**만 즉시 채운다 — 단 시작일이 그 끝보다 뒤면(예: 오늘이 수요일인데 시작일을 다음 주로 고름) 구간이 거꾸로 뒤집히지 않도록 **시작일 당일 하루**만 즉시 채우기 대상으로 본다(`max(보이는 범위 끝, 시작일)`). 새 조회·새 상수를 만들지 않고 이미 있는 범위를 그대로 쓴다. 그 뒤는 R6가 이어 채운다.
- R4. 즉시 채우기는 R21과 **같은 절차**를 쓴다: 같은 날짜·카테고리·정규화된 제목이 이미 있으면 건너뛰기(dedup) · 6초 되돌리기(이번에 새로 만든 것만 되감는다). **종료일이 없을 때는 결과가 0건이어도 오류로 보지 않는다** — R3의 즉시 채우기 구간(예: 수요일에 "월요일만" 등록하면 그 구간엔 월요일이 없다)이 좁아서 못 만든 것일 뿐, 반복 패턴 자체(요일·일 선택)가 무효라서가 아니기 때문이다. 이 경우 토스트는 "n개의 할 일을 만들었어요"(n=0이면 "곧 반복이 시작돼요") — R21의 "이미 전부 등록돼 있어요"·"반복 조건에 맞는 날짜가 없어요" 오류는 **반복 패턴 자체가 무효**(요일·일을 하나도 안 고름)이거나 **종료일이 있는데** 0건일 때만 뜬다(그때는 R3가 다 채웠는데도 0건이라 진짜 이상 상황이므로).
- R5. **이 등록은 이제 `Routine` 레코드도 함께 남긴다**(R21과의 핵심 차이 — R21은 저장하지 않았다). 무기한 등록은 R4대로 즉시 결과가 0건이어도 **항상** 레코드를 저장한다(등록 자체가 실패하지 않는다). 종료일이 있는 등록도 레코드를 남기지만(관리 화면에 기록으로 보임), R6가 할 일이 없으므로(이미 다 채웠다) 실질적으로 완료된 채로 보인다 — 별도 상태값을 만들지 않는다(단순함 우선, R7-a).
- R6. **지연 생성**(무기한 루틴에서만 의미가 있다 — 종료일 있는 루틴은 R3가 이미 끝까지 채웠다): 날짜 스트립·캘린더가 새 날짜 범위를 읽을 때(date-strip.md §4), 그 범위 안에서 이 루틴 패턴에 맞는데 아직 없는 날짜만 조용히 채운다(토스트 없음 — 사용자의 행동은 "날짜 이동"이지 "루틴 만들기"가 아니므로). dedup은 R4와 같은 규칙.
- R7. 루틴 **중지**(관리 화면, `active=false`, **무기한 루틴에만 있는 조작**): 이후 R6 지연 생성을 멈춘다. 이미 만든 인스턴스는 남는다. **재개**하면 다시 R6가 이어진다 — 멈춰 있던 구간을 소급해서 채우지 않는다(지금부터).
- R7-a. **종료일이 있는 루틴은 관리 화면에서 중지·재개 메뉴가 없다**(회색 처리가 아니라 아예 없음) — R3가 등록 즉시 끝까지 다 채워서 R6가 할 일이 없고, 중지해도 멈출 지연 생성이 없기 때문이다. `⋯` 메뉴는 삭제(R10)만 보인다.
- R8. 루틴 규칙(반복 패턴·카테고리 등) 수정은 **그 시점 이후 생성분에만** 적용된다. 이미 만든 인스턴스는 독립 투두라 바뀌지 않는다(수정 즉시 재실행 없음).
- R9. 인스턴스는 실제 `Todo`이고, 만들어진 뒤에는 **완전히 독립적**이다(R21 원칙 그대로 확장) — 그 날짜 것만 고쳐도(제목·메모·카테고리) 다른 날짜·미래 생성분에 영향 없음, 지워도 이후 생성에 영향 없음.
- R10. 루틴 **삭제**(관리 화면, 중지와 별개 메뉴 항목): 과거 인스턴스의 `routineId` 연결은 유지(기록 보존, 🔁 아이콘만 사라짐 — 원본 없음), 이후 생성은 중단.
- R11. 루틴이 가리키는 카테고리가 삭제되면 루틴 레코드는 바뀌지 않는다(`categoryId`를 비우지 않는다 — `Todo.categoryId`가 필수라 "카테고리 없이 생성"은 애초에 성립하지 않는다, §4 정정). 대신 **그 카테고리가 살아 있는 동안만** 지연 생성이 계속된다 — 삭제된 뒤로는 R6가 그 루틴을 건너뛴다(관리 화면은 "카테고리 없음" 텍스트를 병기해 왜 멈췄는지 보여준다). 이미 만든 인스턴스는 category.md R17처럼 "(삭제됨)" 그룹.
- R12. **진입점은 둘**이다: (a) 항목 메뉴 "루틴으로 등록"(R21 그대로, 이번엔 종료일을 비울 수 있을 뿐), (b) 관리 화면의 "+ 루틴 추가"(신규, 항목 없이 카테고리부터 골라 새로 만든다).

## 4. 데이터

- domain: 기존 `RoutineRecurrence`(`{type:'weekly', daysOfWeek}` | `{type:'monthly', daysOfMonth}`, `src/domain/todo/routine.rules.ts`)는 **타입 변경 없음**(daily 유형을 추가하지 않는다, R1). 즉시 채우기(R3·R4)는 기존 `expandRoutineDates`를 그대로 쓰되, 호출부가 R3의 구간 규칙(끝이 시작보다 앞서지 않도록 `max`로 보정한 구간)을 넘긴다. 지연 생성(R6) 판정은 신규 순수 함수 `shouldMaterialize(routine, date) → boolean`(날짜만 입력받는다, 시각 의존 없음).
- 신규 저장 엔티티 `Routine = Meta & { title, memo?, categoryId: CategoryId, recurrence: RoutineRecurrence, startDate: DateKey, endDate?: DateKey, active: boolean, materializedThrough: DateKey }`. `categoryId`는 **필수**다(`Todo.categoryId`가 필수라 "카테고리 없이 등록"은 애초에 성립하지 않는다 — R11 정정 참고). `materializedThrough`는 "이 날짜까지의 슬롯은 전부 생성이 끝났다"를 기록하는 워터마크다(등록 시 `startDate` 전날로 시작). `Todo.routineId?: RoutineId` — 기존 `createRoutine` 스토어 액션(R21 구현)이 만드는 투두에도 이제 이 필드를 채운다. **입력 시그니처가 바뀐다**: 지금은 `endDate: DateKey`가 필수인데 이제 선택이 된다(무기한, R2). `createRoutine`의 반환(`TodoId[] | false`)은 바뀌지 않는다 — 결과 0건도 이제 `false`가 아니라 `[]`로 성공 취급한다(R4).
- 레포지토리 `RoutineRepository.list({ includeInactive })`·`upsert(Persistable<Routine>)`. **중복 생성 방지는 조회가 아니라 워터마크로 한다**(ADR-0017) — "`listByDateRange` 결과에 없는 (routine, date) 쌍만 채운다"는 이전 서술은 소프트 삭제 툼스톤이 조회에서 빠지는 것(ADR-0007)과 부딪혀 지운 인스턴스를 부활시키므로 쓰지 않는다. 실제로는 `planRoutineFill`(`src/domain/routine/routine-fill.ts`)이 `(routine.materializedThrough, through]` 구간만 계획하고, 만든 투두들과 워터마크가 이동한 루틴을 **한 트랜잭션**(`DatasetRepository.write`)으로 함께 커밋한다 — 그래서 `(routineId, date)` 슬롯은 조회 없이도 평생 한 번만 만들어진다(계약 테스트: `routine-fill.contract.ts`, memory·indexeddb).

## 5. 접근성

- "계속 반복" 체크박스: `checkbox` + 체크 시 종료일 `input`에 `disabled` + `aria-describedby`로 "계속 반복돼요" 설명.
- 반복 주기 선택·요일 토글·일(day) 입력은 R21 그대로(변경 없음).
- 관리 화면: 목록 `ul > li`, 행 메뉴 `aria-label="운동 루틴 메뉴"`, 상태는 텍스트 병기("계속" / "~10/4" / "중지됨") — 색만으로 구분하지 않는다.
- 🔁 아이콘은 텍스트 대체("루틴: 매주 금·토")가 있다.

## 6. 범위 밖

- 전용 "매일" 반복 유형(매주에서 요일 7개를 다 고르면 같은 결과가 나온다 — §1), N일 간격 커스텀 주기(필요해지면 후속 R로 추가), 인스턴스 일괄 재수정("이후 전체 적용" — 구글 캘린더식 분기, todo.md §6과 동일 이유로 유지), 루틴 알림/리마인더, 루틴별 통계 상세(합산은 stats.md), 다른 사람과 공유하는 루틴, 날짜 없는 반복(보관함 연동은 별도 스펙 필요, product-overview.md §6).
- R3의 "지금 보이는 날짜 범위"만큼만 즉시 채우는 버퍼 크기는 구현 시 실사용으로 조정 가능한 값이지 고정 상수가 아니다.

## 7. 완료 조건

- [ ] **회귀 없음이 전제다** — 기존 R21 테스트(`RoutineDialog.test.tsx`, `todo-routine.test.ts`, 22건)가 이 확장 이후에도 그대로 통과한다(종료일을 채우는 지금 흐름은 한 글자도 안 바뀐다).
- [ ] R3·R4·R5: 즉시 채우기 구간에 맞는 날짜가 **0건**이어도(예: 수요일에 "월요일만" 무기한 등록) 오류 없이 `Routine`이 저장되는 단위 테스트(회귀 방지 — 이게 이번 라운드에서 잡힌 버그다). 시작일이 보이는 범위 끝보다 뒤인 경우의 구간 보정(`max`)도 별도 테스트.
