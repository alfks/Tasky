# 루틴 스펙

- 상태: draft · 관련 ADR: - · 리서치 참조: reference-app-research.md §2.4(루틴 관리), §3-4, §7 데이터 모델(Routine)

## 1. 목표

매일 하는 일(운동·독서)을 카테고리마다 매번 새로 입력하지 않는다. 반복 규칙을 한 번 정하면, 그 규칙에 맞는 날짜마다 **평범한 투두**로 나타난다 — 루틴에서 나온 투두도 todo.md의 체크·메모·순서·삭제가 그대로 적용된다.

## 2. 화면과 인터랙션

루틴 관리(사이드바 "루틴" 진입점 → 다이얼로그, category.md 구조 재사용):

```
 루틴
 │ 🏃 매일 운동            평일       ⋯ │   ← 반복 요약 텍스트, ⋯: 수정·중지·삭제
 │ 📚 독서                 매주 화·목  ⋯ │
 + 루틴 추가
```

생성/수정 다이얼로그(모달 420px):

```
 ┌ 루틴 만들기 ──────────────────── ✕ ┐
 │ 제목 [ 운동                        ] │
 │ 카테고리 [ 🏃 운동 ▾ ]  (선택)       │
 │ 반복 (●) 매일 ( ) 매주 [월화수목금토일 칩 다중 선택]
 │      ( ) 매월 [ 15 ]일  ( ) N일마다 [ 3 ]일 │
 │ 시작일 [ 2026-09-20 ]  종료일 [ 없음 ▾ ]  │
 │ 미리보기: "9월 20일부터 매주 화·목"        │
 │                          [취소][만들기]   │
 └──────────────────────────────────────────┘
```

투두 화면(todo.md 확장): 루틴에서 나온 투두는 제목 옆 🔁 아이콘(hover "매일 운동 루틴").

### 상태

- **빈 상태**: "아직 루틴이 없어요" + `[첫 루틴 만들기]`.
- **로딩**: 스켈레톤 2행. **에러**: category.md §2-D와 동일 문구·패턴.

## 3. 규칙

- R1. 반복 유형: `daily`(매일) · `weekly`(요일 다중 선택, 1개 이상 필수) · `monthly`(1~31일 지정, 말일이 없는 달은 그 달 마지막 날로) · `custom`(N일 간격, N ∈ 1~90).
- R2. 시작일은 필수, 종료일은 선택(없으면 무기한). 시작일 이전 날짜에는 인스턴스를 만들지 않는다.
- R3. **인스턴스는 실제 `Todo` 레코드다**(가짜 표시가 아니다). 날짜 화면을 열 때 그 날짜에 해당 루틴의 투두가 없으면 그 자리에서 만든다(지연 생성) — 미래를 미리 채우지 않는다(오래 안 쓰는 루틴이 저장소를 채우지 않게).
- R4. 지연 생성은 **보이는 날짜 범위**(date-strip이 이미 읽는 범위, date-strip.md §4)에 대해서만 규칙을 평가한다. 새 조회를 추가하지 않는다.
- R5. 인스턴스 투두는 `routineId`로 원본과 연결되고, 그 외에는 **완전히 독립된 투두**다 — 제목·메모·카테고리를 그 날짜만 고쳐도 같은 루틴의 다른 날짜 인스턴스에 영향 없음, 그 날짜 인스턴스를 지워도 미래 인스턴스는 계속 생긴다(원본 규칙은 그대로).
- R6. 루틴 **중지**(`active=false`): 이후 지연 생성을 멈춘다. 이미 만들어진 과거·오늘 인스턴스는 남는다. 물리 삭제 없음(ADR-0002·0005와 같은 소프트 패턴).
- R7. 루틴 규칙(반복 유형·요일 등) 수정은 **그 시점 이후 새로 생성되는 인스턴스에만** 적용된다. 이미 만들어진 인스턴스는 바뀌지 않는다(R5와 같은 이유 — 인스턴스는 독립 투두).
- R8. 루틴이 가리키는 카테고리가 삭제되면 루틴의 `categoryId`는 비운다(카테고리 없이 계속 생성). 인스턴스는 category.md R17처럼 "(삭제됨)" 그룹.
- R9. 루틴 삭제(완전 삭제, 중지와 별개 메뉴 항목): 과거 인스턴스의 `routineId`는 유지(기록 보존, 🔁 아이콘만 사라짐 — 원본 없음), 향후 생성은 중단.

## 4. 데이터

- domain 신규 `Routine = Meta & { title, categoryId?: CategoryId, repeatType: 'daily'|'weekly'|'monthly'|'custom', repeatDays?: Weekday[], repeatDayOfMonth?: number, repeatInterval?: number, startDate: DateKey, endDate?: DateKey, active: boolean }`. `Todo.routineId?: RoutineId`(연구 §7 모델과 일치). 인스턴스 생성 여부 판정(`shouldMaterialize(routine, date) → boolean`)과 초안 생성(`materializeInstance(routine, date) → TodoDraft`)은 순수 함수 — 날짜만 입력받는다(시각 의존 없음).
- 레포지토리 `RoutineRepository.list({ includeInactive })`·`upsert(Persistable<Routine>)`. 지연 생성은 date-strip이 이미 하는 `TodoRepository.listByDateRange` 결과에 없는 (routine, date) 쌍만 `TodoRepository.upsert`로 채운다(중복 생성 방지는 `(routineId, date)` 유일 제약 — 계약 테스트).

## 5. 접근성

- 요일 칩은 `role=group aria-label="반복 요일"` + 각 칩 `aria-pressed`, 스페이스로 토글.
- 미리보기 문장은 `aria-live="polite"`(반복 설정이 바뀔 때만, 매 키 입력마다 아님 — 300ms 디바운스).
- 🔁 아이콘은 텍스트 대체("루틴: 매일 운동")가 있고 색만으로 구분하지 않는다.

## 6. 범위 밖

- 인스턴스 일괄 수정("이후 전체 적용" — 구글 캘린더식 분기), 루틴 알림/리마인더, 루틴별 통계 상세(합산은 stats.md), 다른 사람과 공유하는 루틴, 날짜 없는 반복(보관함 연동은 별도 스펙 필요, product-overview.md §6).

## 7. 완료 조건

- [ ] R1~R9 테스트. R1 유형별 다음 발생일 계산(월말 보정 포함), R3·R4 지연 생성 범위, R7 규칙 수정이 과거 인스턴스를 바꾸지 않음.
- [ ] `(routineId, date)` 중복 생성 방지 계약 테스트(memory·indexeddb).
- [ ] 키보드만으로 루틴 생성 → 날짜 이동 시 인스턴스 등장 → 체크 → 중지.
- [ ] 라이트/다크 스크린샷(루틴 목록, 생성 다이얼로그, 🔁 아이콘 투두).
