# 다이어리 스펙

- 상태: implemented · 관련 ADR: - · 리서치 참조: reference-app-research.md §2.3(다이어리 화면), §4(시그니처 이모지·스티커), §7 DiaryEntry

## 1. 목표

하루를 마치며 기분 이모지 하나와 짧은 글로 남긴다. 레퍼런스 앱의 스티커·AI 자동 생성은 브랜드 자산을 연상시키거나 비목표이므로(product-overview.md §7) **텍스트 + 이모지**로 좁힌다 — 캐릭터·일러스트 없이도 "오늘 하루" 한 줄은 남길 수 있다.

## 2. 화면과 인터랙션

**카테고리쪽 사이드바**(고정 컬럼 240 · 드로어 둘 다 — app-shell.md §2-A), D-day 섹션 아래·도구 줄 위(사용자 결정 2026-09-29 — 옛 자리는 선택 날짜 패널 하단, 투두 목록 아래였다). 카드는 **선택 날짜**의 기록이다(날짜 스트립 스토어 `selectedDate`, calendar-layout.md R21) — 제목은 접근 이름을 고정하려고 "오늘의 기록" 그대로 두고, 선택 날짜가 오늘이 아니면 제목 아래 `--text-xs` muted 로 그 날짜(`9월 17일 (목)`)를 한 줄 적는다(사이드바는 스트립에서 멀어 카드가 스스로 어느 날인지 말해야 한다. 오늘 판정은 스트립 스토어 `today` — app-shell R12 자정 갱신과 같은 출처). 감수하는 것: 사이드바는 모든 폭에서 드로어가 기본이라 기록 카드가 **한 번의 ☰ 뒤**로 들어간다(고정 컬럼을 켠 사용자만 상시) — 사용자가 명시적으로 요청한 위치이고, 하루의 마무리 글은 "항상 보이는 것" 보다 "찾아가서 쓰는 것" 에 가깝다.

```
 작성 전:                              작성 후 (선택 날짜가 오늘이 아닐 때):
 ┌ 오늘의 기록 ───────────┐            ┌ 오늘의 기록          [수정] ⋯ ┐
 │ 오늘 하루 어땠나요?      │            │ 9월 17일 (목)                  │
 │ [+ 기록하기]             │            │ 😌  "산책하고 나니 개운했다."   │
 └──────────────────────────┘            └────────────────────────────────┘
```

카드 껍질은 컬럼에서만 그린다(app-shell R16 상시 카드 값) — 드로어 안에서는 대화상자가 이미 면이라 벗는다(R18, `DiaryCard` 의 `framed`). 앱에서 `DiaryCard` 의 마운트 지점은 **사이드바 하나**다 — diary 스토어가 전역 단일이라 두 카드가 같이 서면 같은 스토어를 놓고 싸운다.

작성/수정 모달(360px):

```
 ┌ 오늘의 기록 ───────────────── ✕ ┐
 │ 기분 — 😌 😄 😢 😠 😴 🥳       │   ← 제공 목록에서 고른다(category.md R4-a와 동일 원칙)
 │       😐 🤔 😭 🥰 😮 …          │
 │ [ 텍스트 영역, 최대 500자       ] │
 │                     127 / 500    │
 │                    [취소][저장]  │
 └────────────────────────────────────┘
```

### 상태

- **빈 상태**: "오늘 하루 어땠나요?" + `[+ 기록하기]`.
- **로딩**: 카드 자리에 스켈레톤 1줄. **에러**: 저장 실패 시 모달 유지 + `role=alert`(category.md §2-D와 동일 문구 패턴).

## 3. 규칙

- R1. 날짜당 다이어리 **최대 1개**(`date` 유일, 삭제되지 않은 것 기준). 이미 있으면 `[+ 기록하기]` 대신 카드 + `[수정]`.
- R2. 텍스트 0~500자(공백만은 저장하지 않음 — 비어 있으면 "기록 없음" 취급, 이모지만 있어도 저장 가능).
- R3. 기분 이모지는 **제공 목록에서만 고른다**(category.md R4-a와 같은 결정, 자유 입력 아님). 목록은 감정 전용 고정 상수 24개(`src/domain/diary/mood-emoji.ts`) — 카테고리 이모지(활동 의미)와는 다른 축이라 별도 목록을 쓴다. "없음"도 하나의 칸. 이모지 "없음" + 텍스트 없음(R2)은 **저장하지 않는다**(둘 다 비면 `[저장]`이 비활성 — 빈 기록을 만드는 유일한 조합이므로).
- R4. 삭제는 확인 없이 즉시 + 6초 되돌리기 토스트 — **UX는 todo.md R10·R20(이동)의 무확인·즉시·되돌리기 패턴과 같다**(항목 하나짜리 독립 기록이라 파괴성이 낮다고 판단), 데이터를 남기는 방식(물리 삭제 없음)은 소프트 삭제 메커니즘 전반과 같다. 다이어리 카드의 `[삭제]`는 `⋯` 메뉴 안.
- R5. 스티커·이미지·사진 첨부 **없음**(제품 비목표). AI 자동 초안 **없음**(비목표) — 두 항목 모두 리서치 문서의 "프리미엄" 축에서 유래한다는 점도 근거(Tasky는 계정·결제가 없다, P5).
- R6. 날짜 스트립의 `DateCell`(date-strip.md §2-A·R7)에 그날 다이어리가 있으면 기분 이모지를 카테고리 점과 별도 위치(우측 상단 8px)에 작게 표시(선택 항목 — 없어도 R1~R5는 완결). 캘린더(calendar.md)는 별도 그리드가 없으므로(§1) 여기서 다루지 않는다.
- R7. 카드는 앱에서 **한 번에 하나만** 마운트된다(§2 — 사이드바 컬럼 **또는** 드로어). 선택 날짜 패널·1열 본문에는 없다. 선택 날짜가 오늘이 아니면 제목 아래 날짜 한 줄(§2).

## 4. 데이터

- domain 신규 `DiaryEntry = Meta & { date: DateKey, emoji, content: string }`. 유일성(R1)·글자 수(R2)·이모지 목록 검증(R3)은 순수 함수.
- 레포지토리 `DiaryRepository.getByDate(date)`·`upsert(Persistable<DiaryEntry>)`·`list()`(날짜 스트립 점용, R6).

## 5. 접근성

- 작성/수정 모달: 초기 포커스는 이모지 선택(또는 기존 값이 있으면 텍스트 영역), `Esc` 닫기(포커스는 연 지점으로 복귀), 포커스 트랩(app-shell 공통 다이얼로그 규칙과 동일). `Enter` 제출은 없음(텍스트 영역에서 줄바꿈과 충돌하므로 `[저장]` 클릭 또는 `Ctrl/⌘+Enter`).
- 이모지 선택은 `radiogroup`(category.md R4-a와 동일 조작: 방향키, `aria-label`은 감정 이름).
- 텍스트 영역 글자 수는 `aria-live="polite"`(490자부터 남은 수 안내, 매 입력마다 아님).
- 카드는 `section aria-label="오늘의 기록"`(접근 이름 고정, 날짜 부제는 이름에 넣지 않는다) 안의 `article`, 저장 성공 시 포커스는 `[수정]` 버튼으로. 드로어 안에서 연 작성 모달은 드로어 위에 뜨고 `Esc` 는 모달만 닫는다(overlay-stack).

## 6. 범위 밖

- 스티커·캐릭터 이미지, AI 자동 일기, 사진 첨부, 공개 범위·공유(Phase 3 `social.md`), 하루 여러 개 기록, 과거 일기 검색 화면(팔레트로 대체 후보).
