# 포커스 타이머 스펙

- 상태: implemented · 관련 ADR: ADR-0002 · 리서치 참조: reference-app-research.md §2.6(타이머 화면/위젯), §3-7(측정 시간이 할 일에 누적), §9 기회 6

## 1. 목표

할 일 하나를 골라(또는 고르지 않고) 정해진 시간 동안 집중하고, 끝나면 소리와 화면으로 알려 주며, 집중한 시간이 그 할 일에 남는다. 탭을 닫거나 새로고침해도 타이머는 이어진다. 알림 API·마스코트 없이도 "끝났다"가 분명하다.

## 2. 화면과 인터랙션

```
 인사이트 패널 맨 위 슬롯(280px):             실행 중 헤더 칩(패널이 접혀도, 어떤 폭에서도 표시):
 ┌ 집중 ───────────────────────┐              ‹ 2026년 9월 ▾   [⏱ 18:42 장보기]   [오늘] ›
 │        ╭────────╮           │              (클릭 → 패널 열기 / 좁은 화면: 오버레이)
 │        │ 18:42  │  ← 링 120px, 남은 시간   끝났을 때:
 │        ╰────────╯           │              ┌ 집중 25분 끝! ──────────────────┐
 │  📝 장보기            [바꾸기]│              │ 장보기에 25분을 기록했어요        │
 │  [ 25 ] [ 50 ] [ 직접… ] 분  │              │ [5분 더]  [다음 할 일 고르기] [닫기]│
 │        [▶ 시작]              │              └──────────────────────────────────┘
 │  실행 중: [⏸ 일시정지] [■ 중지] │              소리: 짧은 차임 2회(Web Audio 합성음, 파일 없음)
 └─────────────────────────────┘              탭 제목: "⏰ 끝! · Tasky" 깜빡임(1초 간격, 닫을 때까지)
```

- 대기 → `[▶ 시작]` → 실행(링 감소, 1초 갱신) → 일시정지/재개 → 0초 도달 = 완료(패널 카드 + 소리 + 탭 제목) 또는 `[■ 중지]` = 취소(경과 시간은 기록).
- 할 일 선택: 선택 날짜의 **미완료** 투두 목록(활성·종료 카테고리)에서 고르거나 "할 일 없이"; 투두 메뉴 "타이머 시작"으로도 진입(todo.md §2-A).
- 상태: **빈 상태** 오늘 미완료 투두가 없으면 "할 일 없이 집중" 기본. **로딩** 없음(설정 즉시). **에러** 세션 저장 실패 시 타이머는 화면에서 계속 돌고 토스트 "기록을 저장하지 못했어요"; 종료 시 재시도.
- **이 슬롯은 보여줄 것이 있을 때만 인사이트 패널에 선다**(사용자 결정 — 대기 중에는 메인 화면에서 "집중" 섹션 자체가 없다). 실행·일시정지·휴식·완료 카드·정리 카드(R6)·에러 중 하나라도 있으면 나타나고, 전부 없으면(순수 대기) 마운트하지 않는다 — 위 대기 화면(할 일 선택·길이 프리셋)은 그래서 평소에는 보이지 않는다. **시작은 투두 항목 메뉴 "타이머 시작"**(즉시 시작 — 마지막에 쓴 길이·투두 하나를 바로 세션으로 만든다, 길이를 먼저 고르는 화면을 거치지 않는다) **또는 커맨드 팔레트 "타이머 시작"**(같은 방식, `selectedTodoId`·`minutes` 그대로)으로 한다. 헤더 칩(R11)은 이 슬롯과 무관하게 실행·일시정지·휴식 중 항상 보인다.

## 3. 규칙

- R1. 모드: 카운트다운만. 길이 프리셋 25·50분 + 직접 입력 1~180분(정수). 기본 25분. 마지막 사용 길이를 기기별로 기억(localStorage `tasky.timer.v1`).
- R2. 세션은 **저장소 레코드**로 즉시 생성된다(`status=running`). 실행 중 상태는 메모리가 아니라 이 레코드가 원천이며, 새로고침·탭 닫기 후 앱을 열면 레코드를 읽어 **이어서** 표시한다.
- R3. **시간은 항상 시각 기준으로 계산**: `elapsed = min(planned, now − startedAt − pausedTotal − (pausedAt ? now − pausedAt : 0))`. 틱을 누적하지 않는다. 화면 갱신용 1초 인터벌은 표시만 담당하며, 백그라운드 탭에서 인터벌이 지연돼도 값은 어긋나지 않는다(60분 후 오차 ≤ 1초).
- R4. 완료 판정은 매 표시 갱신·`visibilitychange`·앱 시작 시 수행. `elapsed ≥ planned`이면 `status=completed`, `endedAt = startedAt + planned + pausedTotal`(현재 시각이 아님 — 백그라운드에서 지나간 시간이 기록을 부풀리지 않음), `elapsedSeconds = planned`. 이때 주는 신호는 R9(막 끝난 경우)·R9-a(오래 지난 경우)가 나눈다.
- R5. 동시에 실행 중인 세션은 1개. 시작 시 저장소에 `running/paused` 세션이 있으면(다른 탭 포함) 시작을 거부하고 그 세션을 보여 준다.
- R6. 일시정지: `pausedAt` 기록. 재개: `pausedTotal += now − pausedAt`, `pausedAt` 제거. 일시정지 상태로 24시간이 지나면 앱 시작 시 자동 취소(`canceled`, 경과 기록). 이때 패널에 **정리 카드**를 띄운다(`role=status`, 소리·탭 제목 없음): "일시정지한 집중이 24시간이 지나 정리됐어요 · 장보기에 12분을 기록했어요 [닫기]". 사용자가 요청하지 않은 상태 변화이고 경과가 `focusSeconds`에 더해지므로(R8), 숫자가 변한 이유를 설명하지 않고 넘어가지 않는다.
- R7. 중지(취소): `status=canceled`, `endedAt=now`, `elapsedSeconds`는 R3 값. 확인 대화상자 없음(경과가 기록되므로 파괴적이지 않음).
- R8. 완료·취소 시 연결된 투두가 있으면 `Todo.focusSeconds += elapsedSeconds`(캐시). 세션 레코드가 원천이고 `focusSeconds`는 표시용 합계다. 투두가 그 사이 삭제됐으면 세션만 남긴다.
- R9. 완료 신호 세 가지: (a) 패널 카드(닫을 때까지 유지) (b) 차임 2회(Web Audio 합성 — 880Hz·1175Hz 각 120ms, 사이 80ms, gain 0.2 고정. 브라우저 자동재생 정책으로 실패하면 무시) (c) 탭 제목 깜빡임. 소리 끄기 토글은 패널에 두고 R1과 **같은 키** `tasky.timer.v1`에 함께 저장한다(기기별).
- R9-a. **지연 완료**: R4가 앱 시작·재활성화 시점에 완료를 판정했고 `now − endedAt > 2분`이면 (a)만 준다 — 차임도 탭 제목 깜빡임도 없고, 카드 문구는 과거형이다("집중 25분이 끝나 있었어요 · 장보기에 25분을 기록했어요"). 2분 이내면 실행 중 완료와 똑같이 (a)(b)(c) 전부. 근거: (b)(c)는 "지금 막 끝났다"는 **주의 전환** 신호다. 사흘 전 끝난 세션에 소리가 울리면 사용자는 원인을 알 수 없는 소리를 듣게 되고(예측 가능성), 사용자 제스처 없이 앱을 연 직후라 자동재생도 대개 막힌다. 반면 기록(a)은 `focusSeconds`가 늘어난 이유이므로 아무리 오래됐어도 보여 준다. 2분인 이유: 새로고침 왕복(수 초)과 잠깐의 탭 이동(수십 초)은 "지금 끝났다"로 취급해야 실행 중과 동작이 같고, 자리를 비운 사용자에게 뒤늦게 울릴 만큼 길지는 않다.
- R10. `[5분 더]`: 같은 투두로 5분 세션을 새로 시작. `[다음 할 일 고르기]`: 선택 UI로. 완료 카드는 `Esc`로도 닫힌다.
- R11. 헤더 칩은 실행·일시정지 중 항상 보이며(app-shell R15), 클릭 시 패널을 연다. 탭 제목은 실행 중 `"18:42 · 장보기 · Tasky"`(app-shell R9보다 우선).
- R12. 타이머는 달성률·완료 여부에 영향을 주지 않는다(투두 완료는 사용자가 체크). 세션 기록은 백업 파일에 포함(backup.md R2).
- R13. 세션 레코드는 삭제하지 않는다(소프트 삭제 필드는 형식상 유지). 1분 미만 취소 세션도 기록한다(Phase 2 통계에서 필터).

## 4. 데이터

- domain 신규 `FocusSession = Meta & { todoId?: TodoId, categoryId?: CategoryId(시작 시점 스냅샷), date: DateKey(시작 날짜), plannedSeconds, startedAt, pausedAt?, pausedTotalSeconds, endedAt?, elapsedSeconds, status: 'running'|'paused'|'completed'|'canceled' }` — `Meta`(`id`·`createdAt`·`updatedAt`·`rev`·`deletedAt?`)를 예외 없이 갖는다(ADR-0005). R9-a의 신호 등급 판정도 `now` 주입 순수 함수. `Todo.focusSeconds?: number`. 경과·완료 판정(R3·R4)은 `now`를 주입받는 순수 함수. Phase 2 통계(집중 시간 합계·투두별·카테고리별)는 이 레코드만으로 재구성 가능 — `categoryId` 스냅샷은 투두 삭제·카테고리 변경 후에도 집계를 보장한다.
- 레포지토리 `FocusSessionRepository`: `getActive()`(running/paused 1개 또는 `undefined`), `getById`, `listByDate`, `listByTodo`, `listAll`, `upsert(Persistable<FocusSession>)`. 쓰기 메서드는 `upsert` 하나이고 세션 상태 변경은 전부 도메인 `touch`를 거친다(ADR-0007). 백업 경로는 `DatasetRepository`(backup.md §4). 시그니처 TECH_PLAN §6.

## 5. 접근성

- 링 `role="timer" aria-live="off"`(매초 낭독 방지) + 별도 `aria-live="polite"` 영역이 시작·일시정지·완료·5분 단위 남은 시간을 낭독.
- 버튼은 텍스트 라벨 동반(▶/⏸/■ 아이콘만 금지). 헤더 칩 `button aria-label="집중 타이머 18분 42초 남음, 장보기"`.
- 완료 카드는 `role="alertdialog"`, 초기 포커스 `[닫기]`, `Esc` 닫기. 소리는 정보의 유일한 통로가 아니다(R9 세 가지).
- 길이 직접 입력은 `input[type=number] min=1 max=180`, 프리셋은 `radiogroup`.

## 6. 범위 밖

- 알림 API·백그라운드 푸시, 스톱워치(카운트업), 세션 편집·삭제·목록 화면(Phase 2 통계), 소리 선택, 플로팅 창·PiP, 여러 투두 동시.

## 6-A. 뽀모도로 (옵션)

집중 → 휴식을 되풀이하는 방식을 **모드로** 더한다. 기본은 꺼짐이고, 꺼져 있으면 R1~R13 이 그대로 전부다 — 뽀모도로는 기존 단일 집중 세션을 대체하지 않는다.

```
 대기(모드 켜짐):                          휴식 중:
 ┌ 집중 ───────────────────────┐          ┌ 집중 ───────────────────────┐
 │  …기존 대기 화면 그대로…      │          │        ╭────────╮           │
 │  ☑ 뽀모도로로 집중하기        │          │        │  4:32  │  ← 같은 링 │
 │  집중이 끝나면 5분 휴식 ·     │          │        ╰────────╯           │
 │  4번째마다 15분 휴식 ·        │          │  ☕ 짧은 휴식                │
 │  오늘 2번 마쳤어요            │          │  [건너뛰고 집중] [휴식 끝내기]│
 │        [▶ 집중 시작]          │          └─────────────────────────────┘
 └─────────────────────────────┘          휴식 끝: ┌ 짧은 휴식 끝! ─────────┐
                                                   │ 다음 집중을 시작할까요? │
 헤더 칩도 휴식 중 보인다: [☕ 4:32 짧은 휴식]      │ [다음 집중 시작] [나중에]│
                                                   └────────────────────────┘
```

- P1. **모드는 대기 화면의 체크박스 하나**이고 길이·소리와 같은 기기별 레코드(`tasky.timer.v1`)에 함께 저장된다. **고르는 시간은 여전히 집중 길이 하나**(R1 그대로)이고 휴식 길이는 거기서 파생된다 — 짧은 휴식 = 집중의 **1/5**, 긴 휴식 = **3/5**, 각각 1~60분으로 자른다. 25분에서 정확히 5분·15분(고전형)이 나오고, 50분을 고르면 10분·30분이다. 근거: 입력 칸을 셋으로 늘리면 대기 화면이 더 이상 "시간을 정해 주세요" 한 가지 선택이 아니게 된다. 파생된 분 수는 체크박스 아래 한 줄로 **보여 준다**(숨은 규칙을 만들지 않는다).
- P2. 집중이 **완료**되면(R4) 휴식이 이어진다. 4·8·12번째마다 긴 휴식이고 그 사이는 짧은 휴식이다. 휴식은 집중과 **동시에 존재하지 않으며**, 남은 시간은 R3 와 같이 시각으로만 계산한다(틱 누적 없음, 새 인터벌 없음 — 1초 틱에 얹는다). 휴식 중에도 헤더 칩과 탭 제목이 남은 시간을 보여 준다(R11 과 같은 이유).
- P3. **자동 전환은 한 방향뿐이다.** 집중 → 휴식은 자동, **휴식 → 집중은 언제나 사용자가 누른다.** 근거: 집중 세션은 저장소 레코드를 만들고 끝날 때 `Todo.focusSeconds` 에 더해진다(R8) — 자리를 비운 사이 혼자 시작된 집중은 **하지 않은 일을 기록**한다. 휴식은 아무것도 기록하지 않으므로 자동으로 시작해도 잃을 것이 없다. 그래서 자리를 비워도 진행되는 구간은 **최대 하나(휴식)** 이고 거기서 멈춘다. 더해서, 완료를 **2분 넘겨 알아챈 경우**(R9-a 의 `record-only`)에는 휴식조차 시작하지 않는다 — 이미 쉰 시간을 새로 세는 것은 거짓 안내다. 휴식에서 빠져나가는 길은 `[건너뛰고 집중]`(바로 새 집중)과 `[휴식 끝내기]`(대기 화면으로) 둘이다.
- P4. **알림은 기존 어휘 그대로**다: 패널 카드(a) + 차임(b, R9 와 **같은 합성음**, 같은 `soundOff` 토글) + 탭 제목 깜빡임(c, 문구만 `☕ 휴식 끝!`) + 하나뿐인 `aria-live="polite"` 영역의 낭독. **새 알림 수단(브라우저 알림 API·소리 파일)을 들이지 않는다** — 권한·설정·의존이 늘고, 위 넷으로 이미 "끝났다"가 분명하다. 새로고침·탭 닫기에서는 휴식도 이어진다(기기별 레코드 `tasky.pomodoro.v1` 에 시작 시각과 길이를 적는다). 다만 **2분을 넘겨 끝나 있던 휴식은 카드도 소리도 주지 않고 조용히 대기 화면으로 돌아간다** — R9-a 와 갈리는 지점이고, 이유는 휴식이 설명해야 할 숫자(기록)를 남기지 않기 때문이다.
- P5. **오늘 끝낸 뽀모도로 수**를 세어 대기 화면에 보여 준다(긴 휴식 주기의 근거이기도 하다). 날짜별이고 기기별 레코드에 산다 — **저장소 스키마는 건드리지 않는다**(ADR 없이 저장소 구조를 바꾸지 않는다는 규칙). 집중 시간의 원천은 여전히 세션 레코드이고 Phase 2 통계는 그것으로 재구성한다. 중지(R7)·24시간 만료(R6)는 한 개로 세지 않는다.
- P6. 모드를 끄면 돌던 휴식도 함께 걷는다. 휴식 중 완료 카드는 `[5분 더]`·`[다음 할 일 고르기]` 를 내밀지 않는다(두 화면이 서로 다른 다음 걸음을 가리키지 않게).
