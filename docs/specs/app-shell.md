# 앱 셸 / 레이아웃 스펙

- 상태: approved · 관련 ADR: ADR-0001, ADR-0003 · 리서치 참조: reference-app-research.md §2.1, §9 기회 1, 과제 3·5

## 1. 목표

데스크탑 넓은 화면을 3컬럼(카테고리 사이드바 · 오늘의 투두 · 인사이트 패널)으로 써서, 레퍼런스 앱에서 헤더에 몰려 답답하던 정보를 옆으로 펼친다. 창이 좁아지면 정해진 순서로 접히고, 어떤 폭에서도 핵심 루프(날짜 → 투두 → 체크)는 한 화면에서 끝난다.

## 2. 화면과 인터랙션

#### 2-A-1. 면과 고도 (elevation) — 이 앱의 면은 세 층뿐이다

T-25 실측: 화면에 보이는 카드 중 그림자를 가진 것이 **0개**였고, 투두 그룹 카드와 페이지 배경의 명도비는 **1.042 : 1**(다크 1.084 : 1)이었다. 카드와 배경을 가르는 신호가 4% 명도차 하나뿐이면, 정지 상태의 앱은 "감성 다이어리"가 아니라 아직 안 그려진 대시보드로 읽힌다. 리서치 §6 은 이 앱 계열의 인상을 "은은한 드롭섀도우로 카드 부유감"으로 적는다.

| 층            | 무엇                                                                                       | 값(토큰만 쓴다)                                                                  |
| ------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 0 — 캔버스    | 페이지 배경, 컬럼 래퍼, 컬럼의 머리·발(사이드바 앱 이름, 메인 고정 영역, 인사이트 하단 줄) | `--color-bg`. 배경·보더·그림자 없음                                              |
| 1 — 상시 카드 | 투두 그룹, 인사이트 세 섹션, 사이드바 목록·도구, 메인의 빈 상태·에러 안내 카드             | `--color-surface` + `1px solid --color-border` + `--radius-xl` + **`--elev-sm`** |
| 2 — 오버레이  | 대화상자·드로어·팝오버·토스트·상단 배너                                                    | 같은 면 + **`--elev-md`**                                                        |

- R16~R18 이 이 표를 규칙으로 고정한다. **새 그림자 값을 만들지 않는다** — `--elev-sm`/`--elev-md` 두 단계가 전부다(값과 다크 갈래의 단일 소스는 `src/styles/tokens.css`, 색 규정은 theme.md).
- **보더와 그림자를 함께 건다.** 다크에서 `--elev-sm` 은 거의 보이지 않으므로(검정 위의 검정) 경계를 실제로 만드는 것은 1px 보더다. 라이트에서는 반대로 그림자가 부유감을 만든다. 둘 중 하나만 걸면 한쪽 테마에서 이 티켓 이전 상태로 돌아간다.
- **"토큰을 걸었다"로 끝내지 않는다 — 찍힌 픽셀로 확인한다.** T-40 이 `--elev-sm` 을 카드에 걸었지만 실제 그림자는 **2px 띠 · 1.102:1** 이라 같은 카드의 보더(1.192:1)보다 약했고, 화면에서 떠 보이는 면은 팔레트·토스트(`--elev-md`) 둘뿐이었다(FEEL_REPORT §9-1 #1). 고도는 **알파가 아니라 퍼짐**으로 만들고, 다크에서는 그림자의 천장(1.136:1)을 인정하고 경계를 보더에 맡긴다 — 값과 근거의 단일 소스는 theme.md **R21·R22** 다. 이 표를 손대는 티켓은 `tests/feel/density-and-surface.mjs` 로 **띠 두께와 명도비를 다시 재서** 보고한다.
- 라운드는 카드 층에서 `--radius-xl`(20px) 하나로 통일한다 — 리서치 §6 의 "12~20px" 구간 위쪽.

#### 2-A-2. 컬럼의 경계와 밀도

- **컬럼 자체에는 면을 주지 않는다.** 세 컬럼 래퍼(`nav`·`main`·`aside`)는 캔버스로 두고, **컬럼을 가르는 것은 그 안에 놓인 카드의 가장자리**다. 컬럼에 배경을 깔면 (ㄱ) 인사이트·타이머 카드가 같은 `--color-surface` 위에 얹혀 사라지고, (ㄴ) 메인까지 면을 주면 화면 전체가 한 장이 되어 24px 간격만 남는다 — 지금과 같은 문제가 한 겹 위로 올라갈 뿐이다. 컬럼 간격은 R2 대로 `--space-6`.
- 그래서 **세 컬럼이 같은 문법을 쓴다**: 컬럼 = 캔버스 레일 + 그 위의 카드. 사이드바가 맨 텍스트이고 인사이트만 카드이던 불일치는 사이드바 목록·도구를 카드로 올려 없앤다.
- **카드는 내용 높이만큼만 차지한다(R16).** 컬럼을 채우려고 늘리지 않는다. 컬럼 바닥에 붙어야 하는 블록(인사이트 하단 줄, 드로어 안의 도구 줄)은 `mt-auto` 로 내려보내되 그 자체는 내용 높이다 — **단 그 블록이 카드일 때는 붙이지 않는다**(바로 아래 사이드바 항).
- **남는 세로 공백은 채우지 않는다.** 투두 3건 기준 메인 스크롤 영역의 공백은 1440 에서 약 60%, 1280~~768 에서 약 54% 다. 하루 3~~5건이 이 앱의 보통 상태이므로 이 비율은 **결함이 아니라 여백**이고, 정보를 더 얹어 메우지 않는다 — 레퍼런스 앱이 "헤더 정보 과다로 답답하다"는 평을 받은 것이 정확히 그 반대 방향의 실패다(리서치 §6·§9 과제 3). 공백이 "비어 보이는" 문제는 **면으로** 푼다: 카드가 가장자리(보더 + 고도)를 가지면 그 아래 공간은 미완성이 아니라 배경으로 읽힌다.
- **남는 공백은 컬럼의 꼬리에 모은다 — 카드와 카드 사이에 가두지 않는다(R20).** 위 항은 **메인**의 이야기이고, 사이드바에는 다른 문제가 있었다: 도구 줄을 `mt-auto` 로 바닥에 붙이자 목록 카드와 도구 카드 **사이**에 **538px 짜리 빈 띠**가 갇혔다(1440, 투두 3건 기준. 사이드바 높이 794px 중 잉크는 244px — FEEL_REPORT §9-2 A). 위아래가 전부 면으로 막힌 공백은 "여백" 이 아니라 **레이아웃이 끝나지 않은 자리**로 읽힌다 — 마지막 카드 아래로 열려 있는 메인의 꼬리 공백과는 다른 물건이다.
  - 그래서 **사이드바도 정보를 새로 지어 채우지 않는다**(메인과 같은 이유 — 레퍼런스 앱의 실패는 정보 과다 쪽이었다). 채우는 대신 **배치로 푼다**: 카드는 위에서부터 쌓이고, 남는 공간은 마지막 카드 아래에 모인다. 도구 줄(R12)은 목록 카드 바로 아래에 붙는다. 실측은 **갇힌 띠 538px → 0 · 꼬리 526px**(1280: 438 → 0 · 426)이고 **공백 총량(69.3%)은 일부러 그대로 둔다** — 줄여야 할 것은 비율이 아니라 갇힘이었다.
  - 카드로 채우는 쪽(목록 카드를 컬럼 높이만큼 늘리기)은 쓰지 않는다. 카테고리 서넛 아래로 **빈 흰 기둥**이 서서, 고치려던 "비어 보임" 이 더 크게 돌아온다(R16 과 같은 이유).
  - **예외는 드로어**다(< 1024px). 거기서 도구 줄은 카드가 아니라 대화상자의 발(캔버스 + 1px 구분선, R17)이라 공백을 가두지 않고, 오버레이의 바닥에 있는 편이 손가락에 가깝다 — `mt-auto` 를 유지한다.
- 밀도의 수치 규정은 공백 비율이 아니라 **면의 치수**에 건다: 카드 안쪽 여백 ≥ `--space-3`, 카드 사이 간격 `--space-3`~`--space-4`, 메인 내용 최대 폭 760px(R2).

### 2-C. 상태

- **빈 상태(카테고리 0개)**: 메인에 "카테고리를 만들면 할 일을 적을 수 있어요" + `[첫 카테고리 만들기]`(category.md). 사이드바에도 같은 버튼.
- **빈 상태(카테고리 있음, 그날 투두 0개)**: 각 활성 그룹 헤더 + `+ 할 일 추가` 행만. 스트립 아래 한 줄(muted)은 **선택 날짜가 오늘인지 과거인지 미래인지에 따라 갈린다**(R19). 날짜를 옮겨 다니는 것이 이 앱의 핵심 동작이라(date-strip R4) 한 문장을 모든 날짜에 쓰면 화면이 거짓말을 한다.
  - 오늘: "오늘은 비어 있어요. 하나 적어 볼까요?"
  - 미래: "이날은 아직 비어 있어요. 미리 적어 둘까요?" — 지금 하자고 부르지 않고 미리 적어 두자고 권한다.
  - 과거: "이날은 비어 있었어요. 지금 적어 둬도 괜찮아요." — "하나 적어 볼까요?"는 지나간 날엔 재촉으로 읽히고, 그날 아무것도 하지 않은 사람을 나무라는 말이 된다. 과거형으로 사실만 말하고, 뒤늦게 적는 것도 괜찮다고만 덧붙인다(지난 날짜에도 투두는 그대로 추가된다 — 길을 막지는 않는다).
  - 오늘 판정의 출처는 날짜 스트립 스토어 하나다(R12 자정 갱신). 이 문구를 그리는 자리에서 시계를 다시 읽지 않는다.
- **로딩**: 저장소 열기 + 첫 조회가 100ms를 넘기면 메인에 스켈레톤(그룹 헤더 1 + 행 3). 100ms 미만이면 그리지 않는다.
- **에러(저장소 열기 실패)**: 메인 전체를 안내 카드로 교체 — "이 브라우저에서는 저장 공간을 열 수 없어요(사생활 보호 모드일 수 있어요)" + `[메모리 모드로 계속]`. 선택 시 상단 상시 배너 "지금 적는 내용은 새로고침하면 사라져요" + 백업 내보내기 버튼.
- **에러(개별 액션 실패)**: 토스트(에러 색) "저장하지 못했어요. 다시 시도해 주세요". 낙관적 갱신은 롤백.

## 3. 규칙

- R1. 랜드마크: 사이드바 `nav`(aria-label "카테고리"), 메인 `main`, 인사이트 `aside`(aria-label "오늘 요약"). 각 1개.
- R2. 폭: 사이드바 240px, 인사이트 280px 고정, 메인 내용 최대 760px 가운데 정렬, 컬럼 간격 `--space-6`.
- R3. 메인 상단 고정 영역(월 표시 + 타이머 칩 + 날짜 스트립 + 달성률 요약) 높이 ≤ 160px(1280×800). 투두 목록만 세로 스크롤.
- R4. 브레이크포인트 1280 / 1024 / 768, 붕괴 순서 §2-B. 1024px 이상에서 가로 스크롤바가 생기면 결함.
- R5. 사이드바·인사이트 접힘 상태는 기기별 기억(localStorage `tasky.ui.v1`), 백업에 포함되지 않음.
- R6. 인사이트 `[접기]`는 1280px 이상에서도 동작(P2). 접힌 상태는 헤더 "◯ 60%" 버튼으로 대체. 인사이트 패널의 섹션 순서는 고정: 집중 → 달성률 → 카테고리별 → 단축키.
- R7. 드로어·오버레이는 `Esc`, 바깥 클릭, 닫기 버튼으로 닫힌다. 열릴 때 포커스는 첫 포커스 가능 요소로, 닫히면 열었던 버튼으로 복귀.
- R8. 토스트: 하단 중앙, 동시에 1개, 액션 있는 토스트 6초·없는 토스트 3초 후 자동 닫힘, hover/포커스 중 타이머 정지. 액션 버튼은 Tab 도달 가능. 예외: 타이머 완료 카드는 토스트가 아니라 패널 카드(timer.md R9).
- R9. 문서 제목: 타이머 실행 중 `"18:42 · 장보기 · Tasky"`(timer.md R11), 아니면 `"9월 17일 (목) · 3/5 · Tasky"`, 투두 0개면 `"9월 17일 (목) · Tasky"`.
- R10. 첫 포커스 가능 요소는 "본문으로 건너뛰기" 링크(포커스 시 표시) → 날짜 스트립.
- R11. 최소 폭 400px까지 잘림·겹침 없이 렌더한다.
- R12. 사이드바 도구 줄: 테마 토글(☾) · 설정(⚙: 테마 모드·강조색) · 백업/복원(⇅). 상단에는 앱 이름만. 그 외 진입점을 사이드바에 추가하지 않는다. **컬럼일 때는 목록 카드 바로 아래**(스크롤 영역 밖이라 목록이 길어져도 밀려나지 않는다), **드로어일 때는 바닥**(§2-A-2 · R20).
- R13. 스켈레톤·오버레이·토스트 애니메이션은 `prefers-reduced-motion: reduce`에서 0ms.
- R14. **파괴적 확인 대화상자 공통 규칙**(투두 삭제 todo R13, 카테고리 삭제 category R10~R16이 공유): `role="alertdialog"` + `aria-labelledby`(제목)·`aria-describedby`(본문), 포커스 트랩, `aria-modal`. 초기 포커스는 **비파괴 요소**(`[취소]`, 또는 선택지가 있으면 기본 선택 라디오). 파괴 버튼(`[삭제]`, `--color-danger`)은 초기 포커스·기본 제출 대상이 아니다. `Esc`·바깥 클릭·✕ = 취소. `Enter`는 포커스가 버튼에 있을 때 그 버튼만 실행(폼 암묵 제출 금지, 텍스트 입력의 Enter 무시). `isComposing` 또는 `keyCode 229`인 키 이벤트는 무시. 닫히면 열었던 요소로 포커스 복귀 — 그 요소가 확인의 **결과로 사라졌으면**(삭제 성공 시의 카테고리 행·투두 `⋯` 버튼: 주 경로다) 같은 목록의 다음 형제, 없으면 이전 형제, 그마저 없으면 목록 컨테이너(`tabindex=-1`)로 옮기고 그 목록의 빈 상태 문구를 낭독한다. 포커스가 `body`로 떨어지는 경우는 없다. 단순형(제목·본문·취소·파괴 버튼)은 공용 프리미티브 1개로, 선택지가 있는 형은 같은 규칙을 지키는 기능 전용 대화상자로 만든다.
- R15. **타이머 칩**: 세션이 `running/paused`이면 메인 헤더에 칩(남은 시간 + 투두 제목 20자 말줄임)이 모든 폭·패널 상태에서 표시된다. 없으면 렌더하지 않는다(자리 차지 없음).
- R16. **면과 고도**: §2-A-1 의 세 층만 쓴다. 상시 카드(투두 그룹 · 인사이트 세 섹션 · 사이드바 목록·도구 · 메인의 빈 상태/에러 안내)는 `--color-surface` + 1px `--color-border` + `--radius-xl` + `--elev-sm` 을 **함께** 갖는다. 오버레이는 `--elev-md`. 새 그림자 값을 만들지 않는다. 카드는 내용 높이만큼만 차지하고, 컬럼 높이를 채우려고 늘리지 않는다.
- R17. **컬럼 경계**: 컬럼 래퍼(`nav`·`main`·`aside`)에는 배경·보더·그림자를 주지 않는다. 컬럼을 가르는 것은 카드의 가장자리와 R2 의 `--space-6` 간격이다. 컬럼의 머리·발(앱 이름, 메인 고정 영역, 인사이트 하단 줄)은 캔버스에 남는다.
- R18. **면을 두 번 겹치지 않는다**: 이미 면을 가진 것(오버레이·카드) 안에서는 같은 면을 다시 그리지 않는다. 드로어 안의 사이드바가 카드 껍질을 쓰지 않는 이유가 이것이다.
- R19. **빈 상태 문구는 선택 날짜의 시제를 따른다**(§2-C 세 문장). 오늘 판정은 날짜 스트립 스토어의 `today` 하나에서만 온다.
- R20. **빈 공간은 컬럼의 꼬리에 모은다.** 카드와 카드 **사이**에 갇힌 빈 띠를 만들지 않는다 — 카드는 위에서부터 쌓고, 바닥에 붙이는 것은 캔버스인 발뿐이다(인사이트 하단 줄, 드로어의 도구 줄). 공백 비율 자체는 줄이지 않는다(§2-A-2). 근거·실측은 §2-A-2.

## 4. 데이터

- domain 타입 변경 없음. UI 선호는 localStorage. 저장소 열기 실패 시 in-memory 구현 대체 주입(TECH_PLAN §10).

## 5. 접근성

- Tab 순서: 건너뛰기 → 사이드바(상단 → 목록 → 종료됨 → 하단 도구) → 메인(월 표시 → 타이머 칩 → 스트립 → 오늘 → 그룹/투두) → 인사이트(집중 → 달성률 → …).
- 드로어/오버레이 포커스 트랩 + `aria-modal="true"`. 토스트 컨테이너 `role="status" aria-live="polite"`, 에러 토스트 `role="alert"`.
- 접기/펼치기 `aria-expanded` + `aria-controls`. 메모리 모드 배너 `role="alert"` 1회.

## 6. 범위 밖

- 사이드바 폭 조절, 패널 순서 변경, 다중 창 실시간 동기화(1.5), 우측 패널의 캘린더·통계 위젯(Phase 2, 슬롯만), 라우트 추가(MVP `/` 단일, ADR-0001), 플로팅 타이머 창.
