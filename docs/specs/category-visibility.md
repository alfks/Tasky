# 카테고리 공개범위 스펙

- 상태: approved · 관련 ADR: [ADR-0024](../decisions/ADR-0024-category-visibility.md)

## 1. 목표

카테고리를 나만 보기·친구만·모두 공개로 나눈다. 원래 할 일과 메모는 개인 자료로 유지하고, 카테고리 이름·색·이모지와 직접 확인해 공유한 기록 사본만 선택한 사람들에게 보여 준다.
기존 카테고리는 나만 보기이며 기존 친구 공유는 친구 범위를 유지한다. 로그인하지 않은 방문자도 모두 공개인 카테고리와 그 공유 기록을 읽을 수 있다.

## 2. 화면과 인터랙션

카테고리 만들기·수정에서 `공개범위` 선택: `[나만 보기] [친구만] [모두 공개]`.
설명: `카테고리 이름과 직접 공유한 기록만 보여요. 원래 할 일과 메모는 공개되지 않아요.`
목록과 공유 미리보기에 마지막으로 확인된 공개범위를 글자로 표시한다. 서버 범위를 확인하지 못했다면 확인 중으로 안내하고 공유를 막는다.
연결 정보가 없는 카테고리는 `공유 연결 없음`으로 표시한다. 나만 보기 기본 선택은 이 기기의 설정이며 이전 서버 사본이 비공개라는 뜻이 아니다. 카테고리 목록·수정·삭제와 백업/가져오기 안내에서 같은 구분을 지킨다.
안내: `이 기기의 연결 정보가 없습니다. 이전 공유 상태는 공유 카테고리 관리에서 확인하세요.`
넓히기 전 카테고리 미리보기·볼 수 있는 사람·이미 공유한 기록 수를 보여 주고 명시적으로 확인받는다.
모두 공개: `로그인하지 않은 사람도 볼 수 있어요. 이미 저장하거나 캡처한 내용은 회수할 수 없어요.`
친구만: `현재 친구와 앞으로 추가할 친구가 볼 수 있어요.`
좁히기는 서버 완료 뒤에 성공을 알린다. 실패·오프라인에는 이전 확인 범위를 유지하며 재시도할 수 있다.
공유된 카테고리의 이름·색·이모지를 고칠 때도 공개될 내용을 확인한 뒤 저장한다.
삭제 전 공유 카테고리를 서버에서 철회한다. 서버 철회가 필요한 삭제는 인터넷 연결이 없으면 완료했다고 표시하지 않는다.
`친구 → 피드`의 `[친구] [모두 공개]`로 범위를 고르고, 별도 공개 화면은 로그인 없이 읽는다. 로그인하면 응원할 수 있다.
차단 안내: `이 계정에서는 서로의 기록을 숨겨요. 모두 공개인 기록은 로그아웃하면 볼 수 있어요.`
친구 관리의 `[공유 카테고리 관리]`에서 내 서버 카테고리를 수동으로 불러온다. 현재 범위·공유 사본 수와 이 기기의 연결 여부를 보여 준다. 연결이 없으면 `다른 기기에서 만든 항목일 수 있어요`라고 안내한다. 다음 페이지는 사용자가 불러오며 미확인 페이지를 없는 항목으로 판정하지 않는다.
수동 연결은 연결 없는 개인 카테고리와 살아 있는 내 서버 카테고리를 직접 고른 뒤 양쪽 이름·서버 범위·사본 수를 확인한다. 안내: `이 기기 카테고리를 이 공유 카테고리에 연결합니다. 기존 공유 기록의 공개범위는 현재 서버 설정을 유지하며, 개인 할 일은 자동으로 공유되지 않습니다.` 연결은 개인 표식만 바꾸며 이름·기록·서버 공개범위를 바꾸지 않는다.
연결 확인 직전 서버 상태가 달라졌으면 새 범위를 보여 주고 다시 확인받는다. 이후 표시도 마지막 확인 값이며 다른 기기의 동시 변경까지 고정했다고 안내하지 않는다.
미확정 요청은 `확인 필요`로 표시하고 `[같은 요청 다시 확인]`과 `[나중에 확인]`을 제공한다. 확인은 원래 요청 그대로 수동 재시도하며 공개 범위 입력을 잠근다. 나중에 확인하면 창을 닫되 서버에서 이미 공개되었을 수 있음을 알리고 같은 계정에서 다시 확인할 수 있다. 창이 닫혔다고 요청이 취소되었다고 안내하지 않는다.

## 3. 규칙

- R1. 누락된 공개범위와 기존 카테고리의 기본값은 나만 보기다. 범위를 바꾸어도 원래 할 일·메모·통계는 자동 공개하지 않는다.
- R2. 공유는 사용자가 한 건을 고른 뒤 문장·날짜·카테고리·범위를 확인한 별도 사본이다. 나만 보기 카테고리에서 다른 사람에게 공유하려면 범위를 별도 확인 절차로 바꾼다.
- R3. 공개된 카테고리 자료는 이름·색·이모지만이다. 개인 카테고리/할 일 식별자와 메모·달성률·백업·동기화 정보는 보내지 않는다.
- R4. 나만 보기는 소유자, 친구만은 소유자와 현재 수락된 친구, 모두 공개는 모든 방문자가 볼 수 있다. 요청 중·거절·취소는 친구가 아니다.
- R5. 범위를 넓히면 해당 카테고리의 기존 공유 사본도 넓은 범위로 보인다. 그 수와 영향을 확인 전에 알린다.
- R6. 범위를 좁히거나 삭제하면 다음 서버 읽기·검증·응원에서 즉시 새 범위를 적용한다. 이미 전달된 자료의 완전 회수는 보장하지 않는다.
- R7. 범위와 공개 메타데이터는 소유자가 온라인에서만 바꾼다. 실패·응답 소실은 같은 요청으로 확인하고 오래된 버전은 새 상태를 읽고 다시 결정한다.
- R8. 오프라인에서 공개 변경을 자동 전송 대기열에 쌓지 않는다. 서버 확인 전에는 공개/철회가 성공했다고 표시하지 않는다.
- R9. 원래 할 일의 수정·삭제·완료 취소는 공유 사본을 바꾸지 않는다. 공유는 내 공유에서 개별 삭제한다.
- R10. 공개 카테고리 삭제는 먼저 서버 철회 후 개인 삭제를 수행한다. 남은 사본은 소유자의 관리에서 삭제할 수 있다.
- R11. 백업 복원·가져오기는 원격 공개를 생성·복원·확대하지 않는다. 저장된 연결 정보는 소유권과 현재 서버 범위를 다시 확인한 뒤 사용한다.
- R12. 차단은 인증된 화면에서 양방향 읽기·응원을 막는다. 모두 공개 자료를 로그아웃 상태에서 읽는 것까지 막지는 않는다.
- R13. 모두 공개의 응원은 로그인한 비친구도 할 수 있으며 자기 글에는 할 수 없다. 반응자 목록은 공개하지 않는다.
- R14. 기능 off에서는 친구/공개 콘텐츠를 숨기되 자신의 목록·철회·삭제 관리가 가능하다. read-only는 읽기와 철회만 허용한다.
- R15. 없는/접근할 수 없는 카테고리는 같은 안내를 사용한다. 비공개 카테고리 존재·관계·차단 목록을 누설하지 않는다.
- R16. 복원·새로고침 뒤 연결이 없어도 이전 서버 공유를 자동 철회하거나 비공개라고 표시하지 않는다. 서버 관리에서 수동으로 확인하고 연결/철회한다. 이름으로 자동 연결하지 않는다.
- R17. 제출한 공개범위 요청의 완료를 모르면 같은 계정에서 창을 닫았다 열어도 동일 요청으로 확인한다. 일시 인증 오류에는 보관 내용을 숨기고 같은 계정의 인증 재확인 뒤 복구한다. 명시적 로그아웃·계정 삭제·다른 계정 확인 때는 지운다. 자동 재전송하지 않는다.
- R18. 연결/변경 중 개인 자료가 복원·동기화·수정되면 오래된 결과로 덮어쓰지 않는다. 미확정 요청이 있는 카테고리·이미 연결된 대상·철회된 서버 카테고리는 연결하지 않는다. 연결되지 않은 내 서버 항목은 다른 기기의 자료일 수 있어 자동 철회하지 않는다.
- R19. 서버 철회는 기존 공유 기록과 다른 기기의 연결에도 영향을 줌을 명시 확인한다. 오래된 버전은 새 상태를 보여 주고 다시 결정하며 불명확한 결과는 같은 요청으로 확인한다. 성공 후 정확히 일치하는 이 기기의 연결만 정리한다.
- R20. 기능 off에서도 연결 정보만으로 서버 비공개를 주장하지 않는다. 새 공개를 시작하지 않으며 미확정 공개 요청은 기능을 다시 켠 뒤 명시적으로 확인한다. 기존 내 서버 항목의 확인·철회는 수동으로 제공한다.

## 4. 데이터

개인 카테고리는 공개범위·별도 공개 식별자·확인한 버전을 선택적으로 보관한다. 공개 카테고리와 공유 사본은 온라인 서버 계약이며 개인 동기화·백업에 본문을 넣지 않는다.
정확한 API·저장 계약·보존·권한 매트릭스는 [상세 설계](../category-visibility-design.md)가 단일 소스다.

## 5. 접근성

공개범위는 라벨이 있는 라디오/선택 상자다. 확인 창은 초기 비파괴 포커스·Esc 취소·포커스 복귀를 지킨다. 상태와 범위는 색/아이콘과 글자를 함께 쓴다.
공유 확인은 명시적 버튼만 제출하며 Enter와 한글 조합 Enter가 게시하지 않는다. 처리 결과는 정중한 낭독, 오류는 입력 옆에서 안내한다.
좁은 화면·확대·다크·강제 색·움직임 감소에서 모든 행동을 완료할 수 있다.

## 6. 범위 밖

원래 할 일 전체 공개, 자동 공유, 사람 검색, 댓글·DM·팔로우·일괄 공유·공유 편집. 공개 모집과 운영 활성화는 기존 Phase 3 출시 게이트를 통과한 뒤 별도 판정한다.

## 7. 완료 조건

- [ ] 소유자·친구·비친구·양방향 차단·익명에서 세 범위의 읽기·응원·변경을 검증한다.
- [ ] 범위 축소·삭제·계정 삭제·오래된 버전·응답 소실·백업 복원에서 공개가 되살아나지 않는다.
- [ ] 공개범위 확인·실패·오프라인·키보드·한글 조합·좁은 화면을 검증한다.
- [ ] 응답 소실 후 닫기/재열기·같은 계정 인증 복구·로그아웃/계정 변경·수동 연결·철회·불완전 목록·복원 경합을 검증한다.
- [ ] 가져오기 뒤 중립 연결 표시·이전 서버 공개 유지·이름 자동 연결 없음·연결 시 개인 표식만 변경을 검증한다.
