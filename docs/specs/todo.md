# 투두 스펙

- 상태: implemented · 관련 ADR: ADR-0002, ADR-0003 · 리서치 참조: reference-app-research.md §2.1, §3-1, §3-5, §6(완료 스타일·체크 애니메이션), §7 Todo

## 1. 목표

선택한 날짜의 할 일을 카테고리별로 모아 보여주고, **입력 → 체크 → 정리**가 각각 한 동작으로 끝난다. 각 그룹 끝의 인라인 입력으로 연속 입력이 되고, 체크하면 취소선과 함께 **그룹 아래로 내려가** 남은 일이 위에 모인다. 삭제는 확인 한 번을 거친다.

## 2. 화면과 인터랙션

### 2-A. 그룹과 항목 (메인 컬럼, 데스크탑)

```
 ▾ ● 📝 todo                                      2/3   ← 그룹 헤더: 접기 토글 + 색 점 + 이모지 + 이름, 우측 완료/전체(R22)
 ┌──────────────────────────────────────────────────┐
 │ ⠿ ○ 장보기                              ⏱25분 ⋯ │   ← 미완료 블록: order 순. ⏱ 집중 시간 칩(timer.md)
 │      우유, 달걀, 두부                              │   ← 메모 1줄 요약(muted, 말줄임)
 │ ⠿ ○ 방 청소                                    ⋯ │
 │   + 할 일 추가                                    │   ← 입력 행 (미완료 블록 바로 아래)
 │ ─────────────── 완료 1 ───────────────           │   ← 구분선(완료 항목이 있을 때만)
 │   ◉ ~~물 2L 마시기~~                           ⋯ │   ← 완료 블록: 체크 채움(카테고리 색)+취소선+muted, 핸들 없음
 └──────────────────────────────────────────────────┘
 입력 행:  │ ○ [ 할 일을 입력하고 Enter                ]  Esc 닫기 │
 편집 패널(항목 클릭/Enter, 그 자리에서 펼침):
 │ 제목 [ 장보기 ]  메모 [ 우유, 달걀, 두부 (textarea 3~8줄) ]  카테고리 [ 📝 todo ▾ ]  날짜 [ 2026-09-17 ]  [삭제] [취소] [저장] │
 ⋯ 메뉴: 수정 · 메모 추가 · 타이머 시작 · 내일로 · 날짜 바꾸기… · 루틴으로 등록(R21) · 삭제
 삭제 확인(app-shell R14): "'장보기'를 삭제할까요?" / "삭제한 할 일은 목록에서 사라져요." [취소] [삭제]
```

### 2-B. 좁은 화면 (< 768px)

- 동일 구조. 핸들·`⋯` 항상 표시. 편집 패널은 하단 시트(전폭). 하단 고정 `[+ 할 일]`은 첫 활성 카테고리 입력 행을 열고 스크롤.
- **행 밀도**: 좁은 화면에서 행 세로 패딩·터치 하한·카드 안쪽 여백·그룹 간 여백이 줄어 한 화면에 더 많은 항목이 보인다(사용자 결정, theme.md §3-D R32 — 값의 단일 소스는 그 절이다). WCAG 2.5.8(AA) 최소 24×24 는 유지한다. 데스크탑 밀도는 바뀌지 않는다.

### 2-C. 상태

- **빈 상태**: 그룹에 항목이 없으면 `+ 할 일 추가` 행만(app-shell §2-C 문구 병행). **로딩**: app-shell 규칙.
- **에러**: 액션 실패 시 낙관적 변경 롤백 + 토스트 "저장하지 못했어요. 다시 시도해 주세요". 입력 행 텍스트 유지.
- **검증 오류**: 제목 비었음 "할 일을 입력해 주세요"; 100자 초과 "100자까지 쓸 수 있어요"(제출 시 표시).

## 3. 규칙

- R1. 제목은 앞뒤 공백 제거 후 1~~100자, 줄바꿈 불가(붙여넣기 줄바꿈은 공백). R2. 메모 0~~500자, 줄바꿈 허용, 목록에서는 첫 줄만 1줄 말줄임.
- R3. 입력 행 `Enter` = 저장 후 **입력 행 유지**(연속 입력), `Esc` = 닫기. 텍스트가 있는 채로 포커스가 빠지면 저장, 비면 닫기.
  앞 저장이 도는 중에 온 제출도 **버리지 않고 줄 세운다** — 사용자가 친 것은 하나도 사라지지 않는다. 입력칸은 **제출하는 순간** 비워 다음 문장을 바로 받고(비운 뒤 새 글자 없이 다시 `Enter` 를 눌러도 아무 일도 일어나지 않는다), 저장에 실패하면 그 문장을 되돌린다 — 단 그 사이 새로 친 글자가 있으면 그쪽을 지킨다.
- R4. 한글 IME 조합 중(`isComposing`)의 `Enter`는 무시. 조합 종료 후 `Enter`만 저장.
- R5. 새 투두: `date` = 선택 날짜, `categoryId` = 그 그룹(활성 카테고리만), `order` = 그룹(같은 날짜·카테고리) 최대 + 1, `done=false`.
- R6. 완료 토글: 체크박스 클릭 또는 항목 포커스 `Space`. 낙관적 갱신(50ms 안 반영), 실패 시 롤백. 완료 시 `doneAt` 기록, 해제 시 제거. `order`는 토글로 바뀌지 않는다.
- R7. **완료 항목 위치**: 그룹 안에서 [미완료 블록: `order` 오름차순] → 입력 행 → 구분선 "완료 n" → [완료 블록: `doneAt` 내림차순(방금 완료한 것이 구분선 바로 아래)]. 전체 목록 기준이 아니라 **카테고리 그룹 안에서만** 내려간다. 체크 해제하면 보존된 `order`에 따라 미완료 블록의 원래 자리로 돌아간다.
- R8. **이동 모션**: 체크 → 체크 애니메이션(`--motion-fast`) → 400ms 대기 → 완료 블록으로 이동(FLIP, `--motion-base`, 이동 중 다른 항목은 자리를 밀어 올림). 대기 중 같은 그룹에서 추가 토글이 있으면 함께 이동한다. 대기 중 항목은 제자리에서 취소선 상태로 보인다. reduced-motion: 대기 없이 즉시 재배치, 모션 없음. 해제 시 같은 규칙으로 되돌아간다.
- R9. 완료 표시: 체크박스 카테고리 색 채움 + 흰 체크, 제목 취소선 + `--color-muted`, 핸들 숨김.
- R10. 날짜 이동: (a) 메뉴 "내일로" (b) "날짜 바꾸기…"(네이티브 날짜 입력) (c) 편집 패널 날짜 (d) 스트립 셀에 드래그(미완료만). 결과: `date` 변경, `order` = 대상 그룹 끝, 카테고리·`done` 유지. 토스트 "9월 18일로 옮겼어요 [되돌리기]"(6초).
- R11. **순서 변경은 미완료 항목만**, 같은 날짜·같은 카테고리 안에서. 드래그 핸들 또는 `Alt+↑/↓`(행 포커스·손잡이 포커스 둘 다에서 동작, WCAG 2.5.7) — 항목 메뉴에는 두지 않는다(사용자 결정: 세 번째 중복 경로였다). 계산: 그룹 전체(완료 포함)를 `order`로 정렬한 수열에서 항목을 대상 이웃 앞/뒤로 옮긴 뒤 **전체를 0..n-1로 재매김**해 한 번에 저장 — 완료 항목의 상대 위치가 보존되어 해제 시 자연스러운 자리로 돌아간다. 완료 항목은 드래그·키 이동 대상이 아니며 드롭 대상도 아니다. **순서 변경으로 받는 드롭은 같은 그룹에서 출발한 것뿐이다** — 다른 카테고리에서 온 드래그는 항목 위라도 R20 의 이동이다.
- R12. 카테고리 변경 경로는 셋: 편집 패널 · 항목 메뉴 `다른 카테고리로 옮기기` · 다른 카테고리 그룹으로 드래그(R20). 선택지는 **활성 카테고리만**이고, 결과는 항상 **대상 그룹 끝**이다.
- R13. **삭제는 확인 대화상자 필수**(app-shell R14): 메뉴 "삭제", 편집 패널 `[삭제]`, 항목 포커스 `Delete`/`Backspace` 모두 대화상자를 연다. 확인 후 소프트 삭제 + 토스트 "삭제했어요"(액션 없음, 3초). **되돌리기 토스트는 두지 않는다** — 확인이 사용자의 명시적 선택이고 안전망이 둘이면 소음이며, 데이터는 소프트 삭제로 남아 Phase 2 휴지통으로 복구 가능하다.
- R14. 편집: 제목 클릭 또는 포커스 `Enter`. 제목 `Enter` 저장, 메모 `Mod+Enter` 저장, `Esc` 취소(확인 없음). 동시에 열리는 편집 패널 1개.
- R15. 그룹 정렬: 활성 카테고리 `order` 오름차순 → 종료 카테고리(그날 투두 있을 때, category R8) → 삭제된 카테고리의 남은 완료 투두(category R17). 항목 정렬은 R7, 동률은 `createdAt` 오름차순.
- R16. 삭제된 카테고리의 투두는 읽기 전용(체크 해제·편집·순서·드래그 불가), 메뉴 `다른 카테고리로 옮기기`·`삭제`만.
- R17. 목록은 선택 날짜의 투두만 메모리에 둔다. 한 날짜 200개(완료 100 포함)에서 토글→이동 시작 50ms, 재정렬 계산 ≤ 5ms(TECH_PLAN §8).
- R18. 모든 쓰기는 도메인 `touch()`를 거쳐 `updatedAt`·`rev`를 함께 갱신하고(ADR-0005), 물리 삭제는 없다. R19. 메모가 있으면 메모 아이콘(`aria-label="메모 있음"`), `focusSeconds > 0`이면 `⏱ n분` 칩(timer.md).
- R20. **카테고리 간 드래그**: 항목을 다른 카테고리의 **그룹 섹션**에 떨어뜨리면 그 카테고리로 옮긴다(헤더·빈 자리·항목 위 어디든 같다). 결과는 R12 그대로 — `categoryId` 변경, `order` = 대상 그룹 끝, 날짜·`done` 유지. 토스트 "운동 카테고리로 옮겼어요 [되돌리기]"(되돌리기는 원래 그룹 **끝**으로).
  - **두 제스처의 경계는 "같은 카테고리인가" 하나다.** 같은 그룹이면 순서 변경(R11), 다른 카테고리면 **위치와 무관하게** 이동이다. 남의 그룹의 항목 위를 "그 앞/뒤로 끼우기" 로 읽지 않는 이유: (1) 한 지점에서 두 뜻이 갈리면 사용자는 떨어뜨리기 전에 결과를 예측할 수 없고, (2) 대상 그룹의 자리는 이미 R12 가 "그룹 끝" 으로 정해 두었다 — 드래그만 다른 규칙을 쓰면 같은 일에 규칙이 둘이 된다.
  - **받는 그룹은 활성 카테고리 그룹뿐이다.** 종료된 카테고리·삭제된 카테고리(R16) 그룹은 드롭을 받지 않는다 — 메뉴 `다른 카테고리로 옮기기` 의 선택지와 **같은 집합**이어야 한다(R12).
  - 받을 수 있는 그룹은 커서가 올라온 동안 **점선 테두리**로 알린다. 날짜 셀이 투두를 받을 때 쓰는 표시(date-strip R13)와 같은 언어다.
  - 키보드 대안은 새로 만들지 않는다 — 같은 일을 하는 항목 메뉴 `다른 카테고리로 옮기기`·편집 패널의 카테고리 선택이 이미 있다(§5, WCAG 2.5.7).
- R21. **루틴(반복) 등록**: 항목 메뉴 "루틴으로 등록" 다이얼로그에서 제목·메모(기본값은 그 항목의 값, 수정 가능)·카테고리·시작일·종료일(둘 다 필수)과 반복 패턴(매주: 요일 여러 개 토글 / 매달: 일 여러 개, 쉼표로 구분)을 고르면, 시작~~종료일(포함) 범위 안에서 패턴에 맞는 날짜마다 같은 카테고리·제목·메모의 투두를 새로 만든다(제목·메모 검증은 R1·R2와 동일). **기간에 인위적인 상한은 없다** — 실질적인 한도는 시작·종료일 자체가 받는 날짜 범위(아래 date-strip 1970~~2099)뿐이다. 그만큼 한 번에 많이 만들 수 있어 아래처럼 되돌리기를 함께 준다.
  - **루틴 자체는 저장하지 않는다.** 만들어진 각 투두는 그 뒤로 서로 독립된 평범한 투두라 하나씩 편집·삭제된다 — 반복 정의를 나중에 통째로 바꾸거나(예: 요일 추가) 취소하는 기능은 없다. **Phase 2 `routine.md`가 이 승격을 정의한다**(종료일을 비우면 무기한으로 계속 이어 만드는 저장형 확장) — 그 문서가 구현되기 전까지는 이 R21(종료일 필수, 즉시 일괄 생성)이 실제 동작이고, 구현된 뒤에도 종료일을 채우는 지금 흐름은 그대로 남는다(routine.md R3·R4).
  - **중복 방지**: 같은 날짜·카테고리에 이미 같은 제목의 투두가 있으면 그 날짜는 건너뛴다(제목 비교는 정규화 후 정확히 일치할 때만이다 — 대소문자·띄어쓰기가 다르면 중복으로 보지 않는다). 다이얼로그를 연 항목 자신이 속한 날짜도 이 규칙으로 자연히 제외된다(등록 대상 항목을 그 날짜에 또 만들지 않는다). **반복 조건에 맞는 날짜는 있었지만 전부 이미 등록돼 있었던 경우**(예: 자기 요일 하나만 골라 그 항목 자신의 날짜만 걸리는 경우)는 "이미 전부 등록돼 있어요"를 다이얼로그 안에 보이고 닫지 않는다 — 토스트로 "0개의 할 일을 만들었어요"를 내지 않는다.
  - 등록 결과(1개 이상 만들었을 때)는 토스트로 알린다: "n개의 할 일을 만들었어요 [되돌리기]"(R10·R20 과 같은 토스트 언어) — 되돌리기는 방금 만든 항목 **전부**를 소프트 삭제한다(R13). 만든 투두 대부분은 지금 보는 날짜 밖이므로(R17), 되돌리기는 메모리가 아니라 저장소에서 직접 찾아 지운다(R10 되돌리기가 떠난 투두를 다시 부르는 것과 같은 이유). 반복 조건에 맞는 날짜가 하나도 없으면 "이 기간에는 반복 조건에 맞는 날짜가 없어요"를 다이얼로그 안에 보인다.
  - 시작일·종료일 입력은 date-strip 이 다루는 날짜 범위(date-strip.md R6, 1970-01-01~~2099-12-31) 밖을 받지 않는다 — 그 밖의 날짜에 만들어진 투두는 날짜 스트립으로 다시 찾아갈 수 없다. 네이티브 날짜 입력의 `min`/`max` 는 표시 힌트일 뿐이라, 그 범위 검증은 실제 제출 시점에도 한 번 더 한다. **종료일이 시작일보다 이른 경우**와 **순서는 맞지만 범위 밖인 경우**는 서로 다른 문구를 쓴다(전자 "종료일은 시작일과 같거나 이후여야 해요", 후자 "1970-01-01~~2099-12-31 사이 날짜만 골라 주세요") — 뭉치면 범위만 벗어난 사용자가 멀쩡한 종료일을 고치려 헤맨다.
- R22. **그룹 접기/펼치기**: 그룹 헤더 왼쪽의 토글로 그룹의 미완료·입력 행·완료 블록 전체를 접었다 펼쳤다 한다(`aria-expanded`). 완료/전체 카운트는 접힌 채로도 보인다 — 접힌 이유가 "이 카테고리는 지금 안 봐도 된다" 지 "진행 상황을 모르겠다" 가 아니라서다. 기본은 **펼침**(새 카테고리·처음 켜는 기기 전부 펼친 채 시작). 접힘 상태는 카테고리마다 따로 기억하고 **기기별로 localStorage 에만 저장**한다(app-shell R5 의 `sidebarPinned`·`insightCollapsed` 와 같은 이유 — 백업·동기화 대상이 아니다). 드래그(R20)는 접힌 채로도 그대로 받는다 — 섹션 자체는 그대로 있고 목록만 숨어서다.

## 4. 데이터

- domain `Todo`에 `memo?: string`, `doneAt?: string`, `focusSeconds?: number` 추가(TECH_PLAN §5). 검증·생성·토글·그룹 정렬(R7)·재매김(R11)은 순수 함수.
- 레포지토리 `TodoRepository`: `getById`, `listByDate`, `listByDateRange`, `listByCategory`, `listAll`, `search`, `upsert(Persistable<Todo>)`. **쓰기 메서드는 `upsert` 하나**이고 삭제(R13)·복구는 도메인 `markDeleted`/`touch` 결과를 `upsert` 하는 것으로 한다(ADR-0007). 시그니처 TECH_PLAN §6.

## 5. 접근성

- 그룹 `section` + `h2`, 목록 `ul > li`. 체크박스는 실제 `input[type=checkbox]`, 라벨 = 제목. 완료 구분선은 `h3` 수준 텍스트 "완료 n".
- 항목 행 `tabindex=0`; 행 포커스 키: `Space` 토글, `Enter` 편집, `Delete` 삭제 대화상자, `Alt+↑/↓` 순서(미완료만). 완료 항목에서 `Alt+↑/↓`는 무시하고 낭독 "완료된 항목은 순서를 바꿀 수 없어요".
- 항목이 완료 블록으로 이동해도 **포커스는 그 항목에 남는다**(DOM 이동 후 포커스 복원). 이동 후 `aria-live="polite"`로 "완료됨, 아래로 이동"을 1회 낭독.
- 메뉴 `role="menu"`, `↑/↓`, `Esc` 닫기·포커스 복귀. 드래그 기능 전부 키보드·메뉴 대안(WCAG 2.5.7): 순서 변경은 `Alt+↑/↓`(R11), 날짜 이동은 `내일로`·`날짜 바꾸기…`, 카테고리 이동(R20)은 메뉴 `다른 카테고리로 옮기기`·편집 패널.
- 입력 행 `aria-label="todo에 할 일 추가"`, 편집 패널 `role="group" aria-label="장보기 편집"`.
- 접기 토글(R22)은 `aria-expanded` + `aria-controls`(목록 `<ul>` 가리킴), 접근 이름은 다음에 누르면 할 동작을 말한다("todo 접기" / "todo 펼치기") — 지금 상태가 아니라 다음 동작을 말하는 쪽이 스크린리더 사용자에게 더 명확하다.

## 6. 범위 밖

- 날짜 없는 투두, 하위 항목, 시간·알림, 태그, 첨부, 다중 선택 일괄 편집(1.5), 사이드바 카테고리 행으로의 드래그(후속), 검색(shortcuts.md), 삭제 되돌리기·휴지통(Phase 2).
- 루틴(R21)의 **일괄 재편집·취소**(만든 뒤에 반복 정의를 바꾸거나 전체를 취소하는 것 — 등록 직후 토스트의 되돌리기와는 다르다), 반복 종료 조건을 "횟수"로 지정, 루틴 목록/관리 화면 — 전부 `routine.md`(Phase 2)가 정의한다.
