  (`src/styles/tokens.css`). **아무 카드도 쓰지 않는다.**
- 투두 그룹 카드(728×179): `background #ffffff`, `border-radius 20px`, **`border 0px`, `box-shadow none`**.
  페이지 배경 `#fafafc` 대비 **명도비 1.042 : 1**. 다크에서도 `#1c1c22` vs `#141418` = **1.084 : 1**.
  → 카드와 배경을 가르는 신호가 **4% 명도차 하나뿐**이다.
- 인사이트 섹션 카드 3개(280×308·189·90): `border-radius 20px` + 1px `--color-border`
  (`#e6e6ec`, 배경 대비 **1.192 : 1**; 다크 `#2e2e38` vs `#141418` = **1.368 : 1**), 그림자 없음.
- 정리: 라운드는 리서치대로 크지만(20px), **부유감을 만드는 그림자가 어디에도 걸려 있지 않다.**
  → **고칠 곳**: `src/styles/tokens.css` 의 `--elev-*` 를 실제로 쓰도록 하는 것은 **테마(T-11) 소유가 아니라
  각 카드 컴포넌트** — `src/features/shell/components/ShellInsights.tsx`(`CARD_CLASS`),
  `src/features/todo/components/TodoGroupSection.tsx`. **횡단 변경이라 새 티켓이 필요하다**(스펙 근거:
  theme.md §3-D 그림자 토큰 + 리서치 §6). 이 티켓에서는 코드를 건드리지 않았다.

### 7-C. 어긋남 ② — 컬럼 경계가 시각적으로 존재하지 않는다

| 컬럼          | 크기(1440×900) | 배경     | 보더 | 그림자 | 라운드 |
| ------------- | -------------- | -------- | ---- | ------ | ------ |
| 사이드바 래퍼 | 240×794        | **투명** | 0px  | none   | 0px    |
| 메인          | 840×794        | **투명** | 0px  | none   | 0px    |
| 인사이트      | 280×794        | **투명** | 0px  | none   | 0px    |

- 세 컬럼을 나누는 시각 신호는 `gap: var(--space-6)` = **24px 빈 공간 하나**뿐이다.
- 사이드바 카테고리 행(240×36)도 `background` 없음 · `border-radius 0px` · padding 0 — 인사이트 쪽만
  카드이고 사이드바는 맨 텍스트다. 같은 화면 안에서 면의 문법이 두 가지다.
- → **고칠 곳**: `docs/specs/app-shell.md` §2-A·R2 에 컬럼 면(배경/보더)에 대한 규정이 **없다**.
  스펙 보강 + `AppShell.tsx`/`ShellSidebar.tsx` 변경이 함께 필요하다 → **새 티켓**.

### 7-D. 어긋남 ③ — 메인의 죽은 여백

투두 3건(1건 완료) 기준, 메인 스크롤 영역의 세로 공백:

| 뷰포트   | 스크롤 영역 | 콘텐츠 | 공백      | 비율      |
| -------- | ----------- | ------ | --------- | --------- |
| 1440×900 | 642px       | 252px  | **390px** | **60.7%** |
| 1280×800 | 542px       | 252px  | 290px     | 53.5%     |
| 1024×800 | 542px       | 252px  | 290px     | 53.5%     |
| 768×800  | 542px       | 252px  | 290px     | 53.5%     |
| 400×800  | 479px       | 252px  | 227px     | 47.4%     |

- 티켓이 적어 둔 "716px 중 251px(63% 공백)" 은 **재현된다**(1440에서 642 중 252 = 60.7%). 항목 수를
  늘리면 당연히 줄어들지만, **하루 3~5건이 이 앱의 보통 상태**다.
- 메인 내용은 `max-w-760px` 로 가운데 정렬되어 840px 컬럼 안에서 좌우로도 40px씩 남는다(app-shell R2 규정대로).
- **사이드바·인사이트 컬럼 내부의 공백 비율은 측정하지 못했다.** 두 컬럼은 `flex` 로 높이를 꽉 채우도록
  잡혀 있어 "자식 경계" 방식으로는 공백이 항상 0으로 나온다. 티켓의 "사이드바 746px 중 실사용 ~120px",
  "인사이트 하단 273px 공백" 은 **이 패스에서 검증하지 못했다** — 스크린샷상으로는 그렇게 보이지만
  수치를 재지 않았으므로 확인했다고 적지 않는다.

### 7-E. 달성률 중복 — 링은 하나로 줄었고, **숫자가 여섯 곳**이다

- **티켓의 관측(링 2개, 두 링 거리 ~160px)은 더 이상 재현되지 않는다.** 1440·1280 에서 `svg[role="img"]`
  링은 **1개**(인사이트 패널, x=1161 y=469, `aria-label="오늘 달성률 33퍼센트, 3개 중 1개 완료"`).
  헤더는 숫자 한 줄만 낸다. T-20 자체 리뷰에서 이미 고쳐졌다(`ShellHeader.tsx` 주석에 경위가 있다).
- 그러나 **같은 값이 텍스트로 6곳**에 동시에 보인다 (1440·1280, 3건 중 1건 완료):

  | 위치                 | 문구    | 좌표       |
  | -------------------- | ------- | ---------- |
  | 사이드바 카테고리 행 | `1/3`   | (194,164)  |
  | 헤더                 | `1 / 3` | (1037,100) |
  | 메인 그룹 헤더       | `1/3`   | (1026,272) |
  | 인사이트 달성률      | `33%`   | (1297,499) |
  | 인사이트 달성률      | `1 / 3` | (1297,539) |
  | 인사이트 카테고리별  | `1/3`   | (1389,675) |

  1024 에서 3곳(`1/3`, `33%`, `1/3`), 768·400 에서 2곳으로 준다.

- 접근성 쪽은 이미 정리돼 있다: 달성률을 읽는 `aria-live` 영역은 헤더에 **하나**뿐이다(`ShellHeader.tsx` §5).
  남은 것은 **시각적 중복**이다. → 판단 필요: 여섯 개 중 몇 개를 남길지는 스펙 결정 사항이므로
  **`docs/specs/app-shell.md` + `completion-rate.md` 소유 티켓**에서 정해야 한다 → **새 티켓**.

### 7-F. 고정 영역 — 티켓의 "160px, 여유 0" 은 옛 값이다

- 1440 / 1280 / 1024 / 768 / 400 **전부 152px**. app-shell R3 상한 160px(1280×800 규정) 대비 **여유 8px**.
- R3 이 규정하는 1280×800 조합에서도 152px 이고, 그 폭에서는 인사이트가 컬럼으로 서 있다(브레이크포인트
  `wide` = 1280 이상, 실측으로 1279 에서 사라지고 1280 에서 나타난다).

### 7-G. 그 밖에 수치로 잡힌 것

- **첫 방문의 상단 알림이 82px**(400px 폭에서 92px)을 차지한다("이 브라우저가 저장 공간을 보장하지
  않아요. 백업을 권해요"). 닫으면 새로고침 후 다시 뜨지 않는다(실측: spacer 높이 0). 결함은 아니지만
  **첫 화면의 첫인상이 저장 공간 경고**라는 사실은 기록해 둔다(pwa.md 소유).
- **완료 항목의 색**: 라이트 `#6f6f7a` + `line-through`(다크 `#a0a0aa`). todo R9 가 정한 `--color-muted` 대로다.
  리서치 §6 은 완료를 `#C7C7CC` 로 적었다 — 흰 카드 대비 **1.684 : 1**(지금 값은 **4.964 : 1**).
  지금 화면의 완료 항목은 리서치가 그린 것보다 **훨씬 진해서 "끝난 일" 로 물러나 보이지 않는다.**
  다만 리서치 값을 그대로 쓰면 WCAG 4.5:1 을 못 맞춘다 — 스펙(todo R9)이 의도적으로 갈랐을 수 있으나
  그 판단 기록을 찾지 못했다. → **판정 보류, `docs/specs/todo.md` 소유 티켓에서 확인 필요.**
- 보조 텍스트 `--color-muted` `#6f6f7a` vs 리서치 `#8E8E96`(흰 배경 대비 3.251:1). 같은 이유로 보류.
- 리서치가 말하는 감성 요소 중 **마스코트·스티커·체크 애니메이션의 "색이 채워지는 보상감"** 은
  지금 화면에 없다. 다만 이는 1차 MVP 범위 밖이거나 미구현 기능이므로 "어긋남" 이 아니라 **미착수**로 적는다.

### 7-H. 어긋남 ④ — **상태의 언어가 컴포넌트마다 다르다** (`tests/feel/state-language.mjs`)

토큰이 통일돼 있어도 "선택됨 / 호버 / 포커스 / 비활성" 을 **무엇으로 말하는가** 가 갈리면 화면이 한
제품으로 읽히지 않는다. 그리고 이 불일치는 **어느 컴포넌트의 R 규칙에도 걸리지 않는다** — 각자는
자기 규칙을 지켰기 때문이다. 그래서 가로로 훑었다. 1440×900, 라이트·다크 양쪽.

**(1) 선택됨 — 세 가지 언어가 공존한다**

| 묶음                                    | 선택 신호                                                                                     | 선택 vs 비선택 명도비                    |
| --------------------------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 날짜 스트립 셀                          | 배경색 + 글자색 + 보더 + 자식 표식                                                            | 라이트 **1.77 : 1** · 다크 **7.678 : 1** |
| 강조색 스와치 / 카테고리 색 스와치      | **자식 표식만**(안쪽 `span` 에 `✓` + `border-2 border-text`, 비선택은 `border border-border`) | 버튼 자체는 **1.000 : 1**                |
| 타이머 시간(25분/50분/직접) · 소리 알림 | **브라우저 기본 라디오·체크박스**(아래 (4))                                                   | —                                        |

- 스와치의 "1.000:1" 은 **결함이 아니다.** 표식이 자식 `span` 에 그려진다(`ColorSwatchGroup.tsx`:
  `isSelected ? 'border-2 border-text' : 'border border-border'` + `✓`). 첫 측정에서 버튼만 보고
  "선택 신호 없음" 으로 읽었다가 컴포넌트를 열어 보고 바로잡았다 — 그 오측 방지를 위해 프로브가
  자식 한 겹을 함께 본다.
- **다만 같은 "선택" 이 라이트에서 1.77:1(날짜) 과 사실상 0(스와치, 형태로만) 로 갈린다.** 날짜는
  "강조색으로 꽉 채운 칸", 스와치는 "체크 문자 + 굵은 테두리" 다. 둘 다 접근성 요건은 만족하지만
  **시각 언어는 하나가 아니다.**

**(2) 호버 — 이 앱의 주 조작 대상만 호버에 반응하지 않는다**

| 요소                          | 기본 → 호버                           | 변화     |
| ----------------------------- | ------------------------------------- | -------- |
| 날짜 셀                       | 투명 → `#f3f3f7`(`--color-surface-2`) | ✓        |
| 사이드바 카테고리 행          | 투명 → `#f3f3f7`                      | ✓        |
| 투두 행 `⋯` 메뉴              | 투명 → `#f3f3f7`                      | ✓        |
| `+ 할 일 추가`                | 투명 → `#f3f3f7`                      | ✓        |
| 인사이트 `집중 시작`(primary) | opacity 1 → 0.9                       | ✓        |
| **투두 행 제목 버튼**         | 투명 → 투명                           | **없음** |
| **투두 행(`li`) 전체**        | 투명 → 투명                           | **없음** |

- 투두 제목은 클릭하면 편집이 열리는 **버튼**인데(todo R14) 호버 피드백이 전혀 없고, 행 전체도
  마찬가지다. 화면에서 가장 많이 가리키는 대상이 유일하게 "누를 수 있음" 을 말하지 않는다.
- 리서치 §2.1 의 데스크탑 대응 제안은 "롱프레스 → **hover 시 노출되는 인라인 액션 아이콘**" 이고,
  `docs/specs/todo.md` §2-A 도 같은 그림이다. 지금은 `⋯` 가 항상 떠 있고 행은 호버에 무반응이다.
  → **`src/features/todo/components/` 소유 티켓(T-15)** 에서 판단할 사안.

**(3) 포커스 — 링 자체는 통일돼 있다(오측 정정)**

- 전이가 끝난 뒤 값은 **전부 `2px solid var(--color-focus)` / offset 2px** (라이트 `#4a7bd0`,
  다크 `#8fb6ff`). 22칸 Tab 궤적에서 확인.
- **첫 측정에서 "포커스 링 색이 5가지" 라고 읽었는데, 그것은 오측이었다.** 대부분의 버튼이
  `transition-colors` 를 달고 있고 그 전이 대상에 `outline-color` 가 포함돼 있어, 포커스 직후에
  읽으면 중간값(`currentColor` 쪽 `#2b2b33`)이 잡힌다. 프로브를 300ms 뒤에 읽도록 고쳐 정정했다.
  다만 **관찰 자체는 남는다**: 대부분의 버튼은 포커스 링이 `--motion-fast`(150ms) 동안 **서서히
  나타나고**, `transition: all 0s` 인 투두 행·사이드바 버튼은 **즉시** 나타난다. 같은 포커스가
  두 가지 속도로 등장한다. (심각도 Nit — 수치로는 같은 색·같은 두께다.)
- **앱 포커스 링이 아예 없는 요소 3종(실측)**: `⇅ 백업/복원` 버튼
  (`src/features/backup/components/BackupLauncher.tsx`:68 — `hover:bg-surface-2` 는 있고
  `focus-visible:outline-*` 이 없다) 과 타이머 패널의 네이티브 라디오·체크박스. 이들은
  **브라우저 기본 링 `1px auto`** 로 떨어진다.

**(4) 네이티브 컨트롤이 공용 프리미티브와 섞여 있다 — 한 화면에 체크 UI 가 세 가지**

`nativeControlCensus` 실측(1440, 라이트·다크 동일): 네이티브로 그려지는 폼 컨트롤 **5개**.

| 컨트롤               | 크기      | 앱 포커스 링 | 위치                                 |
| -------------------- | --------- | ------------ | ------------------------------------ |
| `select`             | 246×36    | 있음         | 인사이트 "집중할 할 일"              |
| `input[radio]` ×3    | **13×13** | **없음**     | 인사이트 "집중 시간"(25분/50분/직접) |
| `input[checkbox]` ×1 | **13×13** | **없음**     | 인사이트 "끝났을 때 소리로 알리기"   |

- 같은 화면에서 체크/라디오가 **세 가지 모습**이다:
  ① 투두 체크박스 — 공용 `Checkbox`, **22×22**(`--control-checkbox-size`), 원형, 카테고리 색 채움
  ② 색 스와치 — `ColorSwatchGroup`, **32×32**(`--control-hit-min`), 원형, `✓` + 굵은 테두리
  ③ 타이머 라디오·체크박스 — **13×13 브라우저 기본**, OS 기본 파랑, 사각
- 출처: `src/features/timer/components/TimerSetup.tsx` 75·88·109행이 `<input type="radio|checkbox">`
  를 아무 클래스 없이 그대로 쓴다(같은 파일 59·102행의 `select`·숫자 입력에는 토큰 스타일이 붙어 있다).
- 리서치 §6 은 "체크박스도 **원형 또는 둥근 사각형**" 이라고 적었다. 13×13 네이티브 사각 체크박스는
  거기서 벗어나는 유일한 지점이며, "감성" 톤이 한 패널에서만 끊긴다.

**(5) 인사이트 3섹션의 시각 언어는 지금 통일돼 있다(확인만)**

셸 리뷰 라운드 1 이전에는 `집중` 만 카드였다는 지적이 있었다. **현재 실측**: 세 섹션 모두
`border-radius 20px` + `1px solid var(--color-border)` + `background var(--color-surface)`
(라이트 `#ffffff` / 다크 `#1c1c22`). 네 번째 요소는 카드가 아니라 하단 버튼 줄이며 의도된 것이다.
→ **통일돼 있다.** 다만 §7-B 대로 **셋 다 그림자가 없다.**

  150ms 를 두면 40/40 이다. 원인이 계측 도구 쪽 입력 경합(Playwright `fill` ↔ React 제어 입력)인지
  앱 쪽 연속 입력 유실인지는 **이 패스에서 가리지 않았다.** 재현 조건만 적어 둔다.

**(D) 여전히 측정하지 않은 것**: 실제 레퍼런스 앱 화면과의 1:1 대조(§0-1, 원리적으로 불가) ·
GPU 환경의 프레임 드랍(§0-2) · 실기기/터치/다른 브라우저 엔진 · 체크 토글의 앱 내부 지연만
분리한 값(§4 의 R6 보류는 그대로).

### 9-3. §8 결론은 아직 참인가

§8 은 이렇게 끝난다 — _"어긋난 것은 **면·밀도·상태의 언어** 셋이다 … 이 셋을 고치기 전까지는
'감성 다이어리' 가 아니라 여백 큰 대시보드로 읽힌다."_

**판정: 셋 중 하나(상태의 언어)는 거짓이 되었고, 나머지 둘은 참이다. 따라서 결론 문장도 아직 참이다.**

- **상태의 언어 — 거짓이 되었다.** #4(네이티브 컨트롤 5→1)와 #9(선택됨 잉크 링 `2px #2b2b33` 가
  날짜 셀·색 스와치·타이머·팔레트 넷에서 동일)가 실측으로 해결됐다. 한 화면에 체크 UI 가 세 가지이던
  상태는 끝났다. 남은 갈래는 호버(#6)·포커스 등장 속도(#10)·백업 버튼 링(#5)이고, 이들은 "언어가
  다르다" 보다 **"한 컴포넌트가 빠졌다"** 에 가깝다.
- **면 — 아직 참이다.** 카드가 `--elev-sm` 을 쓰기 시작했지만 찍은 픽셀의 그림자는 **2px 띠·1.102:1**
  이고, 같은 카드의 1px 보더(**1.192:1**)가 더 강한 신호다. 즉 지금 카드를 카드로 보이게 하는 것은
  **그림자가 아니라 보더**다. 이 앱에서 실제로 떠 보이는 면은 팔레트와 토스트(`--elev-md`) 둘뿐이다.
  컬럼 셋은 여전히 무면이다(#2).
- **밀도 — 아무도 건드리지 않았다.** 메인 공백 60.7% → **60.5%**. 0.2%p 는 항목 하나 높이의 오차이지
  변화가 아니다. 새로 잰 사이드바는 **69.3%** 로 메인보다 더 비어 있고, 그 공백은 **538px 짜리 한 덩어리**다.
  §8 이 "셋 중 밀도만 아무도 안 건드렸다" 고 적은 지점은 T-60 시점에도 글자 그대로 참이다.

**한 줄로**: 지금 화면은 **"상태의 말투는 하나로 정리된, 여백 큰 대시보드"** 다. 남은 두 축은 **면**과
**밀도**다(메인 60.5% · 사이드바 69.3%).

> **정정(T-63).** 이 문단은 원래 "그것은 **스펙에 규정이 없어서** 남아 있다 — `app-shell.md` §2-A 에
> 밀도 규정이 없다는 §8 의 진단도 그대로 참이다" 라고 적었다. **거짓이다.** `app-shell.md` §2-A-2 는
> 제목부터 "컬럼의 경계와 **밀도**" 이고, T-40 이 `8c8d84d` 에서 넣었다. 거기에는 "남는 세로 공백은
> 채우지 않는다 … 공백이 '비어 보이는' 문제는 **면으로** 푼다" 는 규정과 밀도의 수치 규정(카드 안쪽
> 여백·카드 간격·내용 최대 폭)이 이미 있다. 그러므로 남아 있던 것은 **규정의 부재**가 아니라
> **처방의 용량**이었다 — 스펙이 "면으로 푼다" 고 했는데 그 면이 2px 띠에서 멈춰 있었다(§9-1 #1).
> 위 §9 의 **측정값은 그대로 참이고 손대지 않았다**; 틀린 것은 이 결론 문장뿐이다. 후속은 §9-5.
