# 토큰 효율 전략

모든 규칙은 "하지 마라"가 아니라 **"대신 이렇게 하라"** 로 적는다. 숫자는 하드 리밋이다.

## 1. 계층적 컨텍스트 로딩

| 단계             | 읽는 것                                        | 상한         |
| ---------------- | ---------------------------------------------- | ------------ |
| L0 세션 시작     | `CLAUDE.md`                                    | 250줄        |
| L1 역할 확정     | 역할에 해당하는 컨벤션 1개(CLAUDE.md §3 표)    | 문서당 300줄 |
| L2 디렉토리 진입 | **그 디렉토리** `AGENTS.md` 1개                | 60줄         |
| L3 파일 작업     | 대상 파일(300줄 이하면 전문, 초과면 Grep→범위) | —            |

- 상위 디렉토리 `AGENTS.md`를 연쇄로 읽지 않는다. `src/features/todo/`를 만질 때 `src/AGENTS.md`는 읽지 않고 `src/features/AGENTS.md`만 읽는다(각 `AGENTS.md`는 자기 디렉토리에 필요한 것을 자족적으로 담는다).
- 티켓의 `reads:`가 L1·L2를 지정한다. 거기 없는 문서는 필요하다고 판단될 때 **한 번만**, 이유를 응답에 한 줄 남기고 읽는다.

## 2. 파일 길이 가이드와 분할 규칙

| 대상                 | 상한      | 초과 시                                                        |
| -------------------- | --------- | -------------------------------------------------------------- |
| `CLAUDE.md`          | 250줄     | 내용을 컨벤션 문서로 이동, 링크만 남김                         |
| 디렉토리 `AGENTS.md` | 60줄      | 하위 디렉토리로 분리 + 각자 `AGENTS.md`                        |
| 루트 `AGENTS.md`     | 120줄     | 상세를 `agent-collaboration.md`로 이동                         |
| 컨벤션/설계 문서     | 400줄     | `<name>/` 디렉토리로 쪼개고 `index.md`(목차 + 한 줄 요약)      |
| 리서치 문서          | 제한 없음 | 반드시 `## N.` 섹션 헤더 + 상단 목차 → 섹션 grep으로 부분 읽기 |
| 소스 파일            | 300줄     | 분할 + `index.ts`                                              |
| 컴포넌트             | 200줄     | 하위 컴포넌트 추출                                             |
| 테스트 파일          | 300줄     | 시나리오별 파일 분리                                           |
| 티켓                 | 60줄      | 티켓 분할                                                      |
| 핸드오프             | 40줄      | 상세는 PR 본문으로                                             |

## 3. 탐색 순서 (중복 탐색 방지)

1. **맵 먼저**: `docs/DIRECTORY_MAP.md` 표에서 디렉토리 확정 (`find`·`ls -R` 금지).
2. **Glob**: `src/features/todo/**/*.ts` 로 파일 목록.
3. **Grep**: 심볼명·문자열로 위치 확정 (`-n`, 필요하면 `-C 3`).
4. **범위 Read**: `offset/limit`로 해당 함수만.
5. 같은 세션에서 **읽은 파일을 다시 읽지 않는다**. 수정 후 "확인용 재읽기" 금지(Edit 결과가 곧 검증). 검증은 `pnpm typecheck`/테스트로.
6. 디렉토리 구조를 알고 싶으면 `tree`가 아니라 `DIRECTORY_MAP.md`. 맵이 현실과 다르면 맵을 고치는 `docs` 티켓을 제안.

## 4. 읽지 말아야 할 것

`node_modules/` · `.next/` · `out/` · `dist/` · `coverage/` · `pnpm-lock.yaml` · `*.min.*` · `public/icons/*` · `.git/` 내부 · `playwright-report/` · `*.map` · 바이너리 · `docs/research/*` 전문(섹션만) · 다른 워크트리(`.worktrees/<other>/`)의 소스 · 자기 티켓 `reads:`에 없는 `AGENTS.md`

`git log`는 `--oneline -n 20`, `git diff`는 `--stat` 먼저 → 필요한 파일만 `git diff -- <path>`.

## 5. 명령 출력 다이어트

```bash
pnpm test -- --reporter=dot 2>&1 | tail -30       # 실패만 본다
pnpm lint 2>&1 | grep -E 'error|warning' | head -40
pnpm typecheck 2>&1 | head -40
git diff --stat main...HEAD
git diff main...HEAD -- src/features/todo/       # 파일 범위 지정
gh pr view <n> --json title,labels,statusCheckRollup --jq '…'
```

- 항상 `| head -N` 또는 `| tail -N`. 로그 전문 출력 금지.
- `ls -la` 대신 `ls`. `cat` 대신 범위 Read.
- 빌드 성공 로그는 마지막 5줄이면 충분.

## 6. 에이전트 응답 포맷 제약

| 역할                        | 최종 응답 상한                | 형식                                                          |
| --------------------------- | ----------------------------- | ------------------------------------------------------------- |
| 구현                        | 15줄                          | PR URL, 핸드오프 경로, 변경 요약 3줄, 미완 1줄, 검증 명령 1줄 |
| 리뷰                        | 항목 수 제한 없음, 항목당 2줄 | agent-collaboration.md §4.2 템플릿                            |
| 리서치                      | 10줄 + 파일 경로              | 파일이 본체                                                   |
| 오케스트레이터(사용자 보고) | 20줄                          | 티켓 상태표 + 결정 요청                                       |

공통: 읽은 파일 나열 금지, 코드 전문 재인용 금지(파일:줄로 지칭), 사과·전제·계획 서술 금지, 결과부터.

## 7. 스크래치패드 / 로컬 파일 핸드오프

- 에이전트 간 정보 전달은 **파일 경로**로. 티켓 → `.worktrees/tickets/`, 핸드오프 → `.worktrees/handoffs/`, 리뷰 보고 → `.worktrees/reviews/T-<n>-round<N>-<persona>.md`.
- 대화 메시지에 문서 본문을 복붙하지 않는다. 받는 쪽이 필요한 절만 읽는다.
- 임시 스크립트·중간 산출물은 스크래치패드 디렉토리. 레포에 `tmp*`, `*.draft.md` 남기지 않는다(.gitignore가 막는다).

## 8. 리뷰 시 diff만 읽기

```bash
git fetch origin <branch>
git diff --stat main...origin/<branch>
git diff main...origin/<branch> -- <페르소나 관심 경로>
```

- 백엔드 리뷰어: `src/domain src/repositories src/infra` 만. 프론트엔드: `src/app src/components src/features src/styles`. 사용자 관점: `src/features src/app` + 스크린샷. 접근성: `*.tsx`.
- 변경 함수의 호출자를 알아야 하면 `Grep '<함수명>('` 로 위치만 확인, 호출자 파일 전문 읽기 금지.

## 9. 캐시 친화적 작업 순서

- 세션 초반에 **고정 순서**로 큰 문서를 읽는다: `CLAUDE.md` → (역할 컨벤션) → (디렉토리 AGENTS.md). 이 접두가 안정되면 프롬프트 캐시 히트가 커진다. 중간에 큰 문서를 끼워 넣지 않는다.
- 자주 바뀌는 것(diff, 테스트 출력)은 뒤에서 읽는다.
- 같은 도구 호출을 같은 인자로 반복하지 않는다(결과를 스크래치패드에 저장).
- 병렬 가능한 도구 호출(여러 파일 Read, 여러 Grep)은 한 턴에 묶어 보낸다.

## 10. 서브에이전트 위임 기준

- 위임 O: 페르소나 리뷰(병렬), 리서치, 대규모 탐색("X를 쓰는 곳 전부"), 독립 티켓 구현.
- 위임 X: 3파일 이하 수정, 이미 컨텍스트에 있는 내용 요약.
- 위임 시 프롬프트에 **티켓/핸드오프 경로 + 응답 상한 줄 수**를 반드시 넣는다. 결과는 요약만 받고 원문은 파일로.

## 11. 문서 작성 시 중복 금지

- 같은 규칙을 두 문서에 쓰지 않는다. 한 곳에 쓰고 링크. 요약이 필요하면 3줄 이내 + 링크.
- 새 문서를 만들기 전에 `Grep -i '<핵심어>' docs/` 로 기존 문서 확인.
- 모든 문서 첫 줄은 `<!-- 읽기 조건: … -->`. 읽기 조건이 없는 문서는 리뷰 Major.

## 12. 체크리스트 (오케스트레이터가 티켓 발행 전)

- [ ] `reads:`가 L1 1개 + L2 최대 3개 이내인가
- [ ] 티켓 본문이 60줄 이하인가, 리서치 본문을 복붙하지 않았는가
- [ ] 구현자에게 응답 상한(15줄)을 명시했는가
- [ ] 리뷰어에게 diff 경로 범위와 페르소나를 명시했는가
