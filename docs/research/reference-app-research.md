## 1. 서비스 개요

**레퍼런스 앱**은 개인 할 일/루틴/일기 관리 기능에 지인과의 소셜 상호작용(팔로우, 피드, 응원 스티커)을 결합한 한국의 생산성 앱입니다.

- **개발사**: 소규모 스타트업 팀이 개발. Flutter를 초기부터 채택한 크로스플랫폼 사례로 개발자 커뮤니티에서 자주 언급되며, Firebase 기반 백엔드로 서버 비용을 최적화한 것으로 알려짐.
- **플랫폼**: iOS, Android, macOS, Windows, Web, Apple Watch(컴플리케이션/전용 앱)까지 전 플랫폼 동기화 지원.
- **이용자 규모**: "300만 MZ세대가 선택한 앱"이라는 마케팅 문구가 반복 확인됨. iOS 앱스토어 평점 4.8/5(약 10만 개 리뷰 언급).
- **수상/인지도**: 2025 포브스코리아 '한국인이 사랑한 모바일앱 200' 생산성 부문 15위 선정.
- **타겟 사용자**: 갓생(계획적으로 알차게 사는 삶) 트렌드를 따르는 2030 여성 비중이 높은 MZ세대. 다이어리 꾸미기(다꾸) 문화, 스터디플래너 세대의 디지털 이전 수요.
- **핵심 가치 제안**:
  1. 할 일을 "예쁘게" 기록하는 감성적 UX (색상, 이모지, 스티커, 캐릭터)
  2. 할 일 → 루틴 → 일기(다이어리)로 이어지는 하루 기록의 선순환
  3. 친구와 서로의 계획/성취를 공유하고 응원하는 소셜 동기부여 (SNS형 습관 형성)
  4. AI를 활용한 할 일 추천 및 일기 자동 생성으로 "기록의 허들"을 낮춤
- **인기 이유(감성/꾸미기 요소)**:
  - 카테고리별 색상 지정으로 달력이 알록달록하게 꾸며지는 시각적 성취감 (다꾸/스터디플래너 감성의 디지털화)
  - 귀여운 뭉게구름 모양 마스코트 캐릭터(디자이너가 키우는 강아지에서 모티프, 흰 바탕에 검은 선의 심플한 라인아트)와 계란 모양의 캐릭터 스티커
  - 완료 시 체크 애니메이션, 하루 마무리 이모지 선택 등 소소한 보상감
  - 친구가 내 할 일 완료에 스티커/이모지로 반응해주는 사회적 인정 요소

## 2. 화면(GUI) 구조 목록 (추정 포함)

App Store 설명과 리뷰들을 종합하면, 하단 탭 내비게이션 기반의 모바일 앱이며 대략 아래와 같은 화면들로 구성되는 것으로 추정됩니다. (탭 개수·순서는 스니펫에서 정확히 확인되지 않아 `(추정)` 표시)

### 2.1 홈/투두 화면 (Today / 오늘 할 일) — 메인 화면

- **목적**: 특정 날짜의 할 일·루틴을 확인하고 체크하는 핵심 화면
- **주요 UI 컴포넌트**:
  - 상단 헤더: 날짜 표시 + 좌우 화살표(또는 스와이프)로 날짜 이동. 리뷰에 따르면 업데이트 후 "헤더가 화면의 2/5를 차지해 답답하다"는 불만이 있을 정도로 헤더 영역에 정보(달성률, 요약 통계 등)가 많이 들어감.
  - 카테고리별로 그룹핑된 할 일 리스트 (카테고리별 색상 태그/라벨)
  - 체크박스 형태 완료 토글 (탭 시 체크 + 취소선 처리, 체크 애니메이션)
  - 하단 FAB(+) 버튼: 할 일 추가 바텀시트 오픈
  - 잠금화면 위젯: 오늘 할 일을 위젯에서 바로 체크 가능 (홈 화면을 열지 않고도 완료 처리)
- **인터랙션 / 데스크탑 대응 제안**:
  - 좌우 스와이프(모바일) → 날짜 이동 → 데스크탑: 좌우 화살표 키보드 단축키, 또는 미니 캘린더 클릭
  - 할 일 롱프레스(수정/삭제 메뉴) → 데스크탑: 우클릭 컨텍스트 메뉴, 또는 hover 시 노출되는 인라인 액션 아이콘
  - 할 일 좌우 스와이프(완료/삭제/보관 등 퀵액션) → 데스크탑: hover 액션 버튼 or 키보드 단축키(예: `Cmd+Del`로 삭제)
  - 드래그로 할 일 순서 변경/다른 날짜로 이동(추정) → 데스크탑: 네이티브 드래그앤드롭, 다중 컬럼 간 드래그(예: 날짜 컬럼 간 이동)

### 2.2 캘린더 화면 (월간/주간 뷰)

- **목적**: 한 달/한 주 단위로 일정·할 일 분포를 한눈에 파악, 특정 날짜로 빠르게 이동
- **주요 UI 컴포넌트**: 월간 그리드, 날짜 셀 내 카테고리 색상 점/바(dot indicator), 오늘 날짜 하이라이트, 월간 요약(그 달의 활동량·달성률 등, "먼슬리 기능"으로 언급됨)
- **인터랙션**: 날짜 탭 → 해당 날짜 홈 화면으로 이동 / 데스크탑에서는 사이드바에 상시 노출되는 미니 캘린더 + 메인 영역에 주간/월간 그리드를 동시에 보여주는 레이아웃 제안

### 2.3 다이어리(일기) 화면

- **목적**: 하루를 기록하는 일기 작성 및 열람
- **주요 UI 컴포넌트**:
  - 시그니처 이모지 선택 (하루 기분을 대표하는 이모지 1개 선택)
  - 텍스트 작성 영역 + 스티커 삽입 기능(캐릭터 스티커, 감정 스티커 등)
  - AI 일기 자동 생성 버튼(프리미엄): 그날 기록된 할 일들을 분석해 일기 초안을 자동 작성 → 사용자가 편집 가능
  - 과거 일기를 날짜별/월별로 모아보는 다이어리 리스트(캘린더형 or 타임라인형, 추정)
- **인터랙션**: 이모지/스티커 피커(모바일 바텀시트) → 데스크탑: 이모지 피커 팝오버, 스티커 사이드 패널

### 2.4 루틴 관리 화면

- **목적**: 반복되는 할 일(루틴)을 등록·관리
- **주요 UI 컴포넌트**: 루틴 생성 폼(시작일/종료일, 반복 주기 - 매일/매주 특정 요일/매월/커스텀 주기), 루틴 목록, 루틴별 달성 스트릭(연속 달성일수, 추정)
- **인터랙션**: 반복 규칙 설정 UI(요일 다중 선택 칩 등) → 데스크탑에서도 동일한 패턴 재사용 가능, 키보드로 요일 토글

### 2.5 보관함(백로그) / 노트 화면

- **목적**: 날짜가 정해지지 않은 "나중에 할 일"을 모아두는 공간, 자유 메모(노트) 작성
- **주요 UI 컴포넌트**: 날짜 미지정 할 일 리스트, 노트 리스트(자유 텍스트 메모)
- **인터랙션**: 보관함 항목을 특정 날짜로 드래그/할당 → 데스크탑에서 보관함 패널과 캘린더 간 드래그앤드롭으로 자연스럽게 확장 가능 (데스크탑의 강점이 될 영역)

### 2.6 타이머(포커스) 화면 / 위젯

- **목적**: 특정 할 일에 집중한 시간을 측정(뽀모도로 유사 개념 추정), 측정 시간이 해당 할 일에 자동 저장
- **주요 UI 컴포넌트**: 타이머 시작/정지 버튼, 진행 중인 할 일 표시, 누적 시간 표시
- **인터랙션**: 데스크탑에서는 탭 전환/포커스 유지가 쉬우므로 상시 떠 있는 미니 타이머 위젯(플로팅) 또는 브라우저 탭 타이틀에 남은 시간 표시 제안

### 2.7 통계/리포트 화면 (프리미엄)

- **목적**: 달성률, 카테고리별 활동량, 월간 활동 요약 등을 시각화
- **주요 UI 컴포넌트**: 달성률 차트(원형/막대, 추정), 카테고리별 완료 비율, 월간 캘린더 히트맵(추정), 엑셀 다운로드 버튼
- **비고**: 프리미엄 전용 기능으로, "달성률 통계, 내 할일 검색, 엑셀 다운로드, AI일기 작성" 등이 유료 묶음으로 언급됨

### 2.8 검색 화면

- **목적**: 과거 할 일/일기 검색 (프리미엄 기능으로 언급)
- **인터랙션**: 데스크탑에서는 전역 검색(Cmd/Ctrl+K 커맨드 팔레트 패턴)으로 대체 가능 — 데스크탑 UX 개선 포인트

### 2.9 (SNS, Phase 2) 친구/피드 화면

- **목적**: 팔로우한 친구들의 할 일 완료·일기 소식을 모아보고 반응(좋아요, 이모지, 스티커)
- **주요 UI 컴포넌트**: 피드 리스트(친구별 카드), 좌우 스와이프로 친구 간 피드 전환, 반응 보내기 버튼(긍정 이모지·스티커로 제한)
- **인터랙션**: 좌우 스와이프 → 다음 친구 피드 (틴더/스토리 형태 추정) — Phase 2에서 데스크탑 구현 시 좌우 화살표 키 or 탭 전환으로 대체 가능

### 2.10 (SNS, Phase 2) 친구 추가 / 공유 설정 화면

- **목적**: 이메일 기반 친구 추가, 할 일/일기의 공개 범위(전체공개/친구공개/비공개 등) 세분화 설정
- **비고**: "개인의 할 일은 사적인 영역이라 공유 범위를 디테일하게 세분화"했다는 설계 철학이 확인됨 — Tasky Phase 2 설계 시 참고할 만한 프라이버시 모델

### 2.11 마이페이지 / 설정 화면

- **목적**: 프로필, 카테고리 관리, 테마(다크모드), 알림 설정, 프리미엄 구독 관리, 백업/로그인 계정 관리
- **주요 UI 컴포넌트(추정)**: 프로필 카드, 설정 리스트(메뉴형), 다크모드 토글, 구독 관리 진입점

## 3. 핵심 기능 (Main)

1. **할 일(Todo) CRUD**
   - 카테고리를 만들고 할 일을 추가, 할 일마다 색상(카테고리 색상 상속 또는 개별 지정) 설정 → 캘린더/리스트가 색으로 시각화됨
   - 특정 날짜에 귀속되는 할 일 / 날짜 미지정(보관함) 할 일 두 가지 유형
   - 체크 한 번으로 완료 처리, 취소 시 재탭으로 완료 해제
2. **날짜 이동/캘린더 뷰**
   - 좌우 스와이프 또는 화살표로 하루 단위 이동
   - 월간/주간 캘린더에서 특정 날짜로 점프
3. **카테고리 관리**
   - 카테고리 생성/수정/삭제, 카테고리별 색상 지정
   - 카테고리 단위로 할 일이 그룹핑되어 표시
4. **루틴(반복 일정)**
   - 시작일/종료일 지정, 매일/매주(요일 선택)/매월 등 반복 주기 상세 설정
   - 루틴은 설정된 주기에 따라 자동으로 각 날짜에 할 일로 생성되는 구조로 추정
5. **완료 처리 및 달성률**
   - 체크박스 UI로 완료 처리, 위젯/워치에서도 완료 처리 가능
   - 일별/월별 달성률(완료율) 계산 (프리미엄에서 통계로 시각화)
6. **AI 기반 추천 및 자동화**
   - 과거 기록 기반 할 일 추천
   - 완료된 할 일 기반 일기 자동 생성(프리미엄)
7. **타이머(집중 시간 측정)**
   - 할 일별 타이머 실행, 측정 시간이 해당 할 일에 자동 저장/누적

## 4. 서브 기능 (Sub)

## 6. 디자인 시스템 추정

> 스크린샷을 직접 보지 못했으므로 아래는 텍스트 설명·마스코트 설명·리뷰의 감성 표현을 토대로 한 **추정**입니다. 실제 구현 전 앱을 설치해 정밀 색상 추출(스포이드)을 권장합니다.

- **전반적 톤앤매너**: 파스텔·화이트 베이스의 밝고 가벼운 감성, "다꾸(다이어리 꾸미기)" 문화를 계승한 부드럽고 귀여운(cute) 톤. 마스코트는 흰 바탕에 검은 라인아트로 단순화된 뭉게구름 캐릭터 — 미니멀하면서 친근한 느낌.
- **컬러 팔레트 (추정 HEX 후보)**:
  - 배경(라이트): `#FFFFFF` / `#FAFAFC` (오프화이트)
  - 배경(다크): `#121212` ~ `#1A1A1E`
  - 주요 브랜드 포인트(마스코트/포인트 컬러 후보): 하늘색 계열 `#7CC6FF`~`#5FA8E0` (구름 캐릭터 연상), 또는 연보라 `#B9A6F5`
  - 카테고리 색상 팔레트(다양한 파스텔 색상 제공 추정): `#FF8FA3`(코랄핑크), `#FFC978`(파스텔오렌지), `#FFEB99`(파스텔옐로), `#A8E6B0`(민트그린), `#8FD3E8`(스카이블루), `#B5A8F0`(라벤더), `#D8B8E8`(연보라핑크)
  - 텍스트: 본문 `#2B2B33`(다크그레이, 순블랙 대신 부드럽게), 보조 텍스트 `#8E8E96`
  - 완료 상태: 취소선 + 저채도 회색(`#C7C7CC`) 처리로 "끝난 일"임을 시각적으로 표현
- **타이포그래피**: 둥근 느낌의 산세리프(한글 - Pretendard, Apple SD산돌고딕Neo 계열 추정), 굵기 대비를 활용한 헤더(날짜, 카테고리명)는 세미볼드~볼드, 본문은 레귤러
- **라운드/여백/그림자**: 카드·버튼 모서리 radius가 큰 편(12~20px 추정)으로 부드러운 인상, 체크박스도 원형 또는 둥근 사각형, 카드 간 여백을 넉넉히 주어 답답하지 않게(단, 최근 업데이트에서 헤더 정보 과다로 "답답하다"는 리뷰가 있어 정보 밀도 조절이 중요한 학습 포인트), 은은한 드롭섀도우로 카드 부유감 표현
- **아이콘 스타일**: 라인 아이콘 + 일부 필컬러 일러스트(마스코트 캐릭터, 스티커)를 혼합. 귀엽고 손그림 느낌의 일러스트가 포인트 요소로 사용됨(다이어리 스티커 등)
- **모션/피드백**: 체크 시 마이크로 애니메이션(체크마크, 색상 채움), 완료율 상승 시 시각적 보상(색이 채워지는 프로그레스 등, 추정)

**Tasky 적용 제안**: SNS를 걷어낸 만큼, 레퍼런스 앱의 "감성/꾸미기" 요소(카테고리 색상, 이모지, 스티커, 마스코트)는 오히려 차별화 포인트로 강화할 여지가 큽니다. 데스크탑에서는 카드형 UI보다 밀도 높은 리스트+캘린더 하이브리드 레이아웃이 적합하되, 파스텔 컬러와 라운드 코너, 체크 애니메이션 등 감성 요소는 유지하는 것을 권장합니다.

**레퍼런스 앱만의 차별점**:
1. "계획 관리 + SNS"를 결합해, 할 일 완료 자체를 사회적으로 인정받는 경험으로 설계한 유일에 가까운 포지션 (친구가 서로의 계획표를 보고 응원).
2. 감성적 다이어리/스티커/캐릭터를 통해 단순 도구가 아니라 "기록하는 즐거움"을 주는 라이프스타일 앱으로 포지셔닝.
3. AI로 "할 일 → 일기" 변환이라는, 기록의 허들을 낮추는 독자적 기능.
4. 마이루틴 대비 루틴의 세밀한 정렬/형광펜 기능은 약하지만, 소셜+다이어리 결합은 마이루틴에 없는 강점.
5. 챌린저스 같은 금전적 강제 동기부여 대신, 긍정적 반응(좋아요/스티커)이라는 부드러운 사회적 동기부여를 택함.

**Tasky 시사점**: SNS를 뺀 1차 범위에서는 "감성적 기록 경험"(카테고리 색상, 이모지, 다이어리, AI 보조)과 "체계적 루틴 관리"(마이루틴 벤치마킹 요소인 정렬/세분화)를 결합하는 것이 레퍼런스 앱 대비 차별화 겸 보완 포인트가 될 수 있습니다.

## 9. 데스크탑 웹으로 옮길 때의 기회/과제

### 기회 (데스크탑이 모바일보다 나을 수 있는 지점)
1. **멀티 컬럼 레이아웃**: 모바일은 하루/한 화면 단위 표시가 불가피하지만, 데스크탑은 사이드바(카테고리/보관함) + 메인(일간·주간 리스트) + 우측 패널(캘린더 미니뷰, 타이머, 통계)을 동시에 노출 가능. 리뷰에서 지적된 "헤더가 공간을 너무 차지해 답답하다"는 모바일 제약을 데스크탑 넓은 화면으로 자연스럽게 해소.
2. **드래그앤드롭 강화**: 보관함↔날짜, 날짜↔날짜, 루틴 순서 변경, 카테고리 순서 변경 등을 모바일의 롱프레스+드래그보다 훨씬 정교하고 빠르게 처리 가능 (다중 선택 드래그도 가능).
3. **키보드 단축키**: 할 일 추가(`N`/`Enter`), 완료 토글(`Space`), 날짜 이동(`←`/`→`), 전역 검색(`Cmd/Ctrl+K`), 카테고리 전환(`1`~`9`) 등 파워유저용 단축키 체계 도입 — 모바일에서는 구조적으로 불가능한 영역.
4. **커맨드 팔레트형 검색**: 모바일에서 프리미엄으로 제한됐던 검색을, 데스크탑에서는 전역 커맨드 팔레트로 격상해 "할 일 추가/이동/검색"을 통합 처리.
5. **대시보드형 통계**: 좁은 모바일 화면에서 압축됐던 통계(달성률, 카테고리별 비율)를 데스크탑에서는 위젯형 대시보드로 상시 노출 가능.
6. **멀티태스킹**: 타이머를 브라우저 탭 타이틀/파비콘에 표시하거나, 별도 팝업 미니 윈도우로 띄워 다른 작업과 병행 가능.
7. **일괄 편집**: 여러 할 일을 다중 선택(Shift/Ctrl+클릭)해 카테고리 일괄 변경, 날짜 일괄 이동 등 모바일에서 번거로운 작업을 간소화.

### 과제 (모바일 UX를 데스크탑으로 옮길 때 주의할 점)
1. **터치 제스처의 대체 설계**: 스와이프(좌우 이동, 퀵 액션), 롱프레스(컨텍스트 메뉴), 핀치 등은 마우스+키보드 환경에 맞게 각각 클릭/hover/우클릭/단축키로 재설계해야 함. 기계적으로 1:1 치환하면 어색함.
2. **감성 요소의 과잉 방지**: 모바일에서 매력 포인트였던 이모지/스티커/캐릭터가 넓은 데스크탑 화면에서는 자칫 유치하거나 산만해 보일 수 있음 — 정보 밀도와 감성 요소의 균형(예: 업무용 뷰는 미니멀, 다이어리 뷰만 감성적으로) 필요.
3. **정보 과다 문제 재발 방지**: 레퍼런스 앱 리뷰에서 지속적으로 지적된 "업데이트마다 헤더/기능이 늘어나 답답하다"는 문제는 데스크탑에서도 반복될 수 있음 — 위젯화/패널 접기 기능으로 사용자가 정보 밀도를 직접 조절하게 해야 함.
4. **오프라인/동기화**: 데스크탑 웹은 새로고침·다중 탭 사용이 잦으므로, 실시간 동기화 및 충돌 해결(다른 기기에서 동시 수정 시) 로직이 모바일 대비 더 중요해짐.
5. **반응형 대응**: 데스크탑 웹이라도 창 크기 축소, 태블릿 크기 등 다양한 뷰포트 대응 필요 (사이드바 접힘 등).
6. **접근성**: 마우스 전용이 아닌 키보드만으로도 전체 플로우(할 일 추가~완료~날짜 이동)가 가능하도록 설계해야 파워유저 만족도 확보.
7. **알림/위젯 부재 보완**: 모바일의 잠금화면 위젯, 워치 컴플리케이션 같은 "즉시 체크" 경험을 데스크탑에서는 브라우저 알림, 시스템 트레이 아이콘, PWA 배지 등으로 보완할 방법을 검토해야 함.
