# docs/research/ — AGENTS

## 목적
레퍼런스 앱 및 경쟁 서비스에 대한 조사 결과. **스펙의 근거**이지 스펙이 아니다.

## 여기 있는 것
- `reference-app-research.md`: 레퍼런스 앱 화면 구조·기능·디자인·데이터 모델 추정(369줄, `## 0.`~`## 11.` 섹션). 2차 자료 기반이므로 `(추정)` 표시 항목은 검증 전까지 스펙에 그대로 옮기지 않는다.

## 규칙
1. **읽기 전용.** 기존 문서 수정은 `docs/research-update-*` 티켓으로만. 구현 티켓에서 수정 금지.
2. 전문을 Read하지 않는다. `grep -n '^## ' docs/research/<file>.md`로 목차 → 필요한 섹션만 범위 Read.
3. 새 리서치 문서: 첫 줄 읽기 조건, 상단 목차, `## N.` 섹션 헤더, 조사일자·방법·한계 절 필수. 길이 제한 없음(섹션 구조가 대신한다).
4. 제품명 금지 규칙 최우선. 출처 URL에 제품명이 들어가면 URL도 싣지 않는다(출처 유형만 기재).
5. 스크린샷/이미지는 넣지 않는다(저작권·제품명 노출). 텍스트로 기술.
6. 리서치 결론을 코드 주석에 인용할 때는 "레퍼런스 앱 동작 참고" 한 줄만.

## 검증
```bash
bash scripts/check-forbidden-words.sh
grep -n '^## ' docs/research/*.md | head -30
```

## 자주 하는 실수
- 스펙 티켓에 리서치 본문을 복붙 → 섹션 헤더 인용으로.
- `(추정)` 항목을 확정 요구사항으로 옮김.
