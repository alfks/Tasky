# ADR-0021: 방문 수 계측 — Cloudflare Web Analytics 비콘을 `index.html` 에 직접 싣는다

- 상태: accepted
- 날짜: 2026-09-23
- 관련: `index.html`(비콘), `.env.example` §8(토큰 참고), `public/privacy.html` 2절, README "데이터와 프라이버시",
  ADR-0013(정적 자산 배포) · ADR-0015(로그인 필수 — 로그인 화면도 방문에 포함)

## 맥락

앱이 얼마나 열리는지(로그인 전 화면 포함), 어디서 오는지, 얼마나 빨리 뜨는지를 볼 수단이 없었다. 로그인이
필수라(ADR-0015) 서버 로그만으로는 로그인 화면에서 떠난 방문을 셀 수 없고, `workers.dev` 배포에는 Cloudflare
존(zone) 단위 트래픽 분석이 붙지 않는다. 개인 식별 정보·지속 식별자를 새로 만들지 않는 방법이어야 한다.

## 결정

**Cloudflare Web Analytics 비콘(`static.cloudflareinsights.com/beacon.min.js`)을 루트 `index.html` 의 `<head>` 에
싣는다.** 토큰은 페이지 소스에 그대로 노출되는 공개 값이라 `index.html` 에 하드코딩한다(비밀 아님).

- 쿠키·로컬 식별자 없이 익명 페이지뷰(경로·리퍼러·user agent·로딩 타이밍)만 보낸다 — 방침이 약속한
  "지속 식별자 없음"을 지킨다.
- `index.html` 은 `AuthGate` 보다 앞이라 로그인 여부와 무관하게 모든 방문이 잡힌다.
- 구현 코드 없음, 번들 예산(`scripts/check-dist.mjs`) 밖의 외부 스크립트 한 줄이라 앱 코드를 건드리지 않는다.
- **정직하게 적어 둔다: 구현(비콘 추가)과 이 ADR 이 같은 PR 에 실렸다.** `docs/decisions/AGENTS.md` 규칙 3 의
  "코드 변경과 분리" 예외로, 방침 문서 수정과 함께 한 묶음이어야 배포본과 공개 문서가 어긋나는 순간이 없다.

## 대안과 기각 이유

| 대안                                | 기각 이유                                                                                    |
| ----------------------------------- | -------------------------------------------------------------------------------------------- |
| 아무것도 안 한다                    | 방문 수·로딩 속도를 볼 근거가 없다. 로그인 전 이탈은 서버 로그에도 남지 않는다               |
| Cloudflare 존 트래픽 분석           | `workers.dev` 서브도메인에는 제공되지 않는다. 커스텀 도메인을 붙이면 재검토(아래 트리거)     |
| Worker + D1 에 자체 카운터          | 스키마·엔드포인트·IP 처리 방침을 새로 만들어야 한다. 셀프 구현이 개인정보 면에서 더 무겁다   |
| Vite `import.meta.env` 로 토큰 치환 | 토큰은 비밀이 아니라 얻는 게 없고, dev/e2e 에서 비콘을 끄는 용도라면 후속(아래)으로 충분하다 |

## 결과

- 좋은 점: 개인 식별 없이 방문 수·리퍼러·성능을 본다. 코드·스키마·번들 변경 0.
- 감수하는 점:
  - 번들 예산 밖의 **외부 런타임 스크립트** 하나가 생겼다(첫 로드에 요청 1개 추가, 실패해도 앱은 영향 없음 — `defer`).
  - `pnpm dev`·e2e(`localhost`) 트래픽도 같은 토큰으로 잡힌다 → **후속: 환경 기반 주입**(프로덕션 빌드에서만 싣기).
  - 오프라인 PWA 세션은 비콘이 못 나가 **과소 집계**된다.
  - 공개 문서를 같이 고쳤다: `public/privacy.html`(새 2절·시행일 2026-09-23)·README.

## 지켜야 할 규칙 (검증 가능한 문장 — 리뷰 판정 근거)

1. 비콘은 루트 `index.html` 에만 있다. `public/privacy.html` 에는 넣지 않는다(`public/AGENTS.md` 규칙 6).
2. 비콘이 보내는 항목이 바뀌면 `public/privacy.html` 2절과 시행일을 같은 PR 에서 고친다.
3. **CSP 를 도입하면** `script-src` 에 `https://static.cloudflareinsights.com`, `connect-src` 에
   `https://cloudflareinsights.com` 을 허용한다 — 빠지면 비콘이 조용히 죽는다.
4. 토큰을 `.env`·시크릿으로 옮기지 않는다(공개 값). 바꾸면 `.env.example` §8 의 참고 항목도 맞춘다.

## 재검토 트리거

- 커스텀 도메인을 붙여 존 단위 분석이 가능해질 때.
- 사용자별·기기별 지표(리텐션 등)가 필요해질 때 — 그때는 이 비콘으로는 안 되고 방침을 먼저 바꿔야 한다.
- CSP 도입 시(규칙 3).
