# ADR-0025: 온라인 전용 화면의 선택 로드

- 상태: accepted
- 날짜: 2026-09-30
- 관련: [ADR-0013](ADR-0013-plain-vite-react-and-lazy-dexie.md) 결정 8·규칙 7의 동적 chunk preload 및 전체 JS 최초 전송 간주 중 신규 온라인 진입점만 부분 대체, [공개범위 설계](../category-visibility-design.md)

## 맥락

친구·공개 feed·공개범위 편집은 온라인 전용이며 필요할 때 진입한다. 모든 동적 chunk를 미리 읽으면 지연 import에도 초기 전송 비용이 발생한다. 기존 개인 앱의 성능·오프라인 계약을 유지하면서 새 화면을 선택 로드한다.

## 결정

1. 승인된 social/public/category-audience 소스 진입점을 온라인 선택 화면으로 명시한다. emitted 파일명 패턴으로 제외하지 않는다.
2. Rollup imports/dynamicImports 그래프에서 기존 개인 진입점과 개인 동적 기능의 필수 의존성을 계산한다. 새 선택 진입점에서만 필요한 chunk를 선택으로 분류한다.
3. 개인 기능과 공유하거나 분류를 입증하지 못한 chunk는 필수다. 선택 모듈을 개인 진입점에서 정적으로 참조하면 필수로 승격한다.
4. 기존 개인 기능의 preload·PWA 오프라인 의존성은 유지한다. 선택 chunk만 초기 modulepreload에서 제외한다.
5. 최초 네트워크 측정은 실제 HTML script/modulepreload와 필수 정적 의존성 합이다. entry 167,500 B와 network 221,000 B 상한을 유지한다.
6. 전체 JS와 선택 진입점별 추가 전송량도 별도로 보고한다. 첫 진입 숫자에서 제외했다고 전체 크기를 숨기지 않는다.
7. 검사기는 그래프 분류의 완전성·승인된 선택 진입점의 도달성·필수 asset의 참조를 검사한다. 새 의존성은 추가하지 않는다.

## 검증

필수 chunk 누락·미분류 asset·선택 기능의 의도하지 않은 초기 참조를 부정 사례로 검증한다. 콜드 브라우저에서 개인 첫 진입에 선택 chunk 요청이 없고 화면 진입 시 추가 요청이 발생함을 확인한다. 기존 개인 기능과 PWA 오프라인 동작은 별도로 확인한다. 검증하지 않은 결과는 통과로 기록하지 않는다.

## 대안

예산 상향은 초기 회귀를 가리므로 채택하지 않는다. 파일명 제외는 공유 chunk를 잘못 분류할 수 있어 채택하지 않는다. 모든 기존 동적 preload 삭제는 개인 기능 계약을 바꾸므로 채택하지 않는다.

## 결과

선택 화면의 첫 진입에는 추가 로딩과 실패 재시도가 생긴다. 온라인 전용 화면에 로딩·오류 UI를 제공하고 개인 화면은 계속 사용할 수 있게 한다.
