# ADR-0026: 구버전 설정 동기화는 기존 프로필을 보존한다

- 상태: accepted
- 날짜: 2026-10-01
- 관련: ADR-0023(혼합 버전 감수·Worker 무변경 규칙 부분 대체), profile.md

## 맥락

사용자가 빌드·재배포 뒤 프로필이 사라진다고 보고했다. 캐시된 구버전 클라이언트는
프로필 필드를 모르는 화이트리스트로 설정 행을 읽고, 테마 등을 저장할 때 프로필 없는
더 최신 행을 올릴 수 있다. 기존 로우 단위 LWW는 이 요청으로 서버 프로필까지 지운다.

## 결정

1. 새 HTTP 클라이언트는 동기화 요청에 `settingsProfileVersion: 1`을 붙인다.
   `setProfile`은 설정 행에 `profileVersion: 1`도 저장한다. 두 표식이 모두 있을 때만
   필드 생략을 명시적인 삭제로 본다. 업데이트 전 대기 중이던 구버전 쓰기도 보존된다.
2. 요청·행 표식 중 하나라도 없는 요청(또는 지원하지 않는 표식)은 설정 행의 누락된 프로필 필드만
   서버의 현재 행에서 보존한다. 요청에 들어온 유효한 프로필 값은 반영하며 행 표식도 보존한다.
3. 보존은 D1의 같은 `ON CONFLICT DO UPDATE` 문 안에서 한다. 별도 SELECT 뒤 병합하면
   그 사이 저장된 다른 기기의 프로필을 낡은 값으로 덮을 수 있다. LWW·시각 클램프·seq·사용자 격리는 유지한다.
4. 삭제된 설정 행을 되살리거나 툼스톤을 쓸 때는 프로필을 보존하지 않는다.
   개인 프로필은 계속 같은 Settings 행에만 저장한다. DB·백업 스키마 변경은 없다.
5. 업데이트 후 첫 동기화는 `includeOwnSettings: true`로 자기 기기의 설정 행도 다시 받는다.
   수신 완료 표식은 기기별 `SyncState.settingsProfileVersion`에만 저장하고 서버 커서는 뒤로 돌리지 않는다.
6. Worker와 클라이언트를 함께 배포해야 한다. 이미 지워진 프로필의 자동 복구는 제공하지 않는다.
   표식이 없는 구버전에서 프로필을 지우려면 새 버전으로 갱신해야 한다.

## 대안과 기각 이유

- 모든 요청에서 프로필 보존: 새 버전의 의도적인 이름·소개·사진 삭제도 막는다.
- PWA 강제 갱신만 적용: 갱신 전 열린 탭·다른 기기가 서버 값을 지우는 경로가 남는다.
- 별도 프로필 테이블: 기존 백업·동기화·DB 마이그레이션을 모두 변경해야 한다.

## 검증

실 D1에서 프로필 저장 → 표식 없는 구버전 테마 쓰기 → 다른 기기 풀의 세 필드 유지,
새 버전의 필드별·전체 삭제, 구버전의 유효한 프로필 편집, stale·계정 격리를 검사한다.
HTTP 테스트는 요청에 표식이 포함되는지 확인한다.
