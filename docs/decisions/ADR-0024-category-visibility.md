# ADR-0024: 명시적 카테고리 사본과 세 단계 공개범위

- 상태: accepted
- 날짜: 2026-09-30
- 관련: ADR-0022 결정 1·2·5의 카테고리/친구 전용 제한을 부분 대체, ADR-0015 개인 앱 로그인 필수는 유지

## 맥락

사용자는 Phase 3 전체 구현에 더해 나만·친구만·모두가 보는 카테고리를 요청했다.
기존 개인 sync 원본을 공개하면 메모·개인 식별자·백업 복원과 권한 LWW가 엉켜 철회 계약을 지킬 수 없다.

## 결정

1. 원본은 개인 전용이며 별도 서버 카테고리 사본에 이름·색·이모지·공개범위만 저장한다. 공유 기록은 여전히 직접 확인한 불변 문장·날짜 사본이다.
2. 개인 카테고리에는 선택적 `visibility`·`socialCategoryId`·`socialCategoryVersion`을 둔다. 누락은 private. 이 값은 서버 소유권/현재 버전 확인을 대신하지 못하고 가져오기로 원격 공개를 생성하지 않는다.
3. 서버 카테고리는 opaque id·actor 소유권·version을 갖는다. 소유자 id는 세션에서 구하며 업데이트/철회는 CAS·멱등 command·단일 D1 batch로 확인한다.
4. post에 nullable 공개 category id를 추가한다. null인 기존 사본만 기존 friends 규칙을 적용한다. category의 현재 범위를 SQL 읽기·응원마다 적용하며 삭제된 category는 legacy로 취급하지 않는다.
5. private은 소유자만, friends는 현재 수락 친구와 소유자, public은 비로그인 방문자도 읽는다. 범위 확대는 기존 사본 수와 메타데이터를 명시 확인하고 축소는 서버 완료 전 성공으로 표시하지 않는다.
6. 공개 읽기 GET과 `/public` 화면만 인증 예외다. 잘못된 인증은 익명으로 낮추지 않는다. 쓰기는 기존 인증/Origin/CSRF/한도 계약을 유지한다. 인증된 공개 읽기·응원에는 양방향 차단을 적용한다.
7. 공개 반응은 로그인한 비친구도 가능하되 자기 글 응원은 금지한다. 로그아웃한 공개 읽기는 차단으로 막을 수 없음을 안내한다.
8. 공개 자료도 no-store·온라인 메모리·권한 검증을 지킨다. category 삭제는 서버 철회 후 원본 삭제, 계정 삭제 batch는 category까지 함께 정리한다.
9. 개인 category 필드는 비인덱스이므로 Dexie 버전업 없이 whitelist와 백업/동기화 계약을 함께 확장한다. 서버 D1은 additive migration으로 변경한다.
10. 서버 기본 off와 기존 운영 게이트는 유지한다. 공개 모집·신고/중재·실운영 증거를 구현 완료와 혼동하지 않는다.

## 대안과 기각 이유

- 원래 category/todo의 visibility로 개인 데이터를 직접 공개: 필드 누출·원본 변경·개인 백업의 자동 재공개 위험 때문에 기각.
- post마다 audience를 복사: 카테고리 범위 축소 시 이미 공유한 사본의 권한이 남아 즉시 철회 계약을 만족하지 못하므로 기각.
- 모두 공개에도 로그인 요구: 누구나 볼 수 있다는 사용자 요구에 맞지 않으므로 기각.

## 결과

[제품 스펙](../specs/category-visibility.md)·[기술 계약](../category-visibility-design.md)을 구현 전에 확정한다. 새로운 런타임 의존성은 없다.
공개 범위는 넓어지지만 개인 메모/투두 공개는 자동화하지 않는다. 이미 본 자료·캡처는 회수할 수 없다.
