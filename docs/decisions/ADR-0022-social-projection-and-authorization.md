# ADR-0022: 개인 동기화와 공유 사본·서버 권한 분리

- 상태: partially superseded by [ADR-0024](ADR-0024-category-visibility.md) (결정 1·2·5의 친구/카테고리 제한만, 나머지 유지)
- 날짜: 2026-09-28
- 관련: ADR-0005·0007·0009(개인 저장 계약), ADR-0015·0018·0019·0020(인증·동기화·삭제)
- 구현: 예정. 이 결정의 승인은 기능 출시나 운영 검증 완료를 뜻하지 않는다.

## 맥락

Phase 2의 `entities(sub,tbl,id)`·LWW·아웃박스는 한 사람의 기기 사이에서 개인 자료를 맞춘다.
Phase 3는 다른 계정에게 최소 정보만 공개하고 관계/차단/삭제를 즉시 서버에서 판정해야 한다.
기존 원본을 친구에게 복제하면 메모·다이어리 등 비공개 필드 유출과 철회 이후 오프라인 재생 위험이 생긴다.

## 결정

1. 공유는 사용자가 미리보기에서 확인한 문장·기록 날짜의 별도 서버 사본이다. 원본 id/메모/카테고리는 전송하지 않고 자동 공개·자동 갱신하지 않는다.
2. 첫 범위는 초대·상호 수락한 친구·시간순 피드·단일 응원·차단이다. 현재와 앞으로 추가할 친구에게 기존 공유도 보인다. 원본 삭제와 공유 삭제의 차이를 항상 고지한다.
3. `social_profiles`는 구글 sub와 다른 opaque id를 쓰고 이메일·구글 이름/사진을 자동 공개하지 않는다. 계정 삭제 후 동일 sub 재가입은 새로운 소셜 id다.
4. 소셜은 서버 command·CAS/version·멱등 receipt를 사용한다. 개인 `Meta`·`Persistable`·LWW·`/api/sync`·Dexie v4·개인 백업에 포함하지 않는다. ADR-0005/0007의 개인 엔티티 계약은 유지한다.
5. 읽기·쓰기 SQL마다 현재 sid·계정·profile 생존과 양방향 block/친구 권한을 함께 검사한다. actor-bound 별도 저장소를 두고 개인 `forUser` 격리를 넓히지 않는다.
6. 승인 결과 receipt와 효과는 조건부 SQL을 모은 한 D1 batch로 처리한다. 사전 SELECT 뒤 무조건 쓰지 않는다. receipt는 결과/id만 보관하고 민감 응답 본문을 재생하지 않는다.
7. D1 primary를 사용하고 소셜 읽기에 replica를 도입하지 않는다. 온라인 메모리만 표시하며 offline/hidden에는 가리고 복귀·주기 검증으로 권한을 다시 확인한다.
8. 계정 삭제 batch에 소셜 종속 데이터의 명시 삭제를 넣는다. 기존 sessions 지연 삭제·410·재가입 세션 폐기는 유지한다. 소셜 정리가 없는 서버로 롤백하지 않는다.

## 대안과 기각 이유

| 대안                                               | 기각 이유                                                                                               |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Todo.visibility 추가 후 개인 sync로 친구 자료 전달 | 기존 개인 데이터 whitelist/seq/backup을 바꾸고 원본 필드 유출·권한 LWW·오프라인 회수 문제를 만든다      |
| 원본 id와 실시간 연결한 projection                 | 원본 수정/완료취소/삭제/백업과 서버 소셜의 교차 트랜잭션이 필요하며 최초 공유 확인 이후 내용이 달라진다 |
| 전체 공개·팔로우·댓글 동시 출시                    | 탐색·신고/중재·검색·알림·악용 대응까지 필요해 현재 인증/동기화 운영 검증 수준을 넘어선다                |
| 별도 실시간 DB/상시 연결                           | 현 Worker/D1과 중복된 인증·운영 경로를 더한다. 작은 친구 범위에서는 조회·검증 주기로 시작 가능하다      |

## 결과

- 개인 기록의 흐름을 유지하면서 공유 사본에 필요한 필드와 권한을 감사할 수 있다. 새 런타임 의존성은 요구하지 않는다.
- 원본 수정·삭제가 사본에 전파되지 않으므로 명확한 미리보기와 자신의 전체 공유 관리가 필수다.
- 이미 본 내용/캡처/철회 전 승인된 응답의 완전 회수는 불가능하다. 새 서버 읽기 차단과 온라인 화면의 주기 검증을 보장한다.
- 온라인 전용 소셜·별도 권한 테스트·계정 삭제 비용·읽기 limiter 비용을 감수한다.
- 기술 계약은 [social-design.md](../social-design.md), 단계·릴리스 차단 조건은 [구현 계획](../phase3-implementation-plan.md)에 둔다.

## 재검토 조건

공개 모집, 일부 친구 선택, 원본과 자동 연동, 댓글/신고, 오프라인 소셜, 수천 친구, D1 삭제/조회 예산 실패는 새 ADR과 제품 스펙 개정을 먼저 요구한다.
