# ADR-0004: 멀티 에이전트 협업 규칙

- 상태: accepted
- 날짜: 2026-09-15
- 관련: CLAUDE.md, AGENTS.md, docs/conventions/\*

## 맥락

opus/fable/sonnet 여러 에이전트가 병렬로 구현·리뷰한다. 사람(alfks)이 유일한 저작자이자 최종 승인자다. 컨텍스트 토큰이 비용이며, 레퍼런스 앱 제품명은 어떤 기록에도 남아선 안 된다.

## 결정

1. **author 고정**: 모든 커밋 author = `alfks <millie020524@gmail.com>`, AI 트레일러·서명 금지. 훅 + CI로 강제.
2. **워크트리 격리**: 병렬 작업은 `.worktrees/<name>/`에서만. 로컬 보드·티켓·핸드오프도 `.worktrees/`(gitignore)에 둔다.
3. **브랜치 규칙**: `<type>/<kebab-name>`, 에이전트 이름 브랜치 금지. squash merge only, 리베이스 동기화.
4. **맵 + 디렉토리별 AGENTS.md**: 규칙은 해당 디렉토리에만, 60줄 이하, 필요할 때만 읽는다. `CLAUDE.md` ≤ 250줄.
5. **리뷰 루프**: 페르소나 병렬 리뷰, 중복 제거 후 (Blocker+Major) ≤ 3 이면 종료·머지, 최대 3라운드.
6. **파일 소유권 락**: 티켓 `owns:`로 선언, 동시 티켓 간 서로소.
7. **금지어**: 레퍼런스 앱 제품명 전면 금지, 조각 조립 정규식으로 훅·CI 검사.

## 대안과 기각 이유

| 대안                         | 기각 이유                                   |
| ---------------------------- | ------------------------------------------- |
| 단일 워킹트리 + 브랜치 전환  | 병렬 에이전트가 서로의 미커밋 변경을 덮어씀 |
| 트래킹 파일로 작업 보드 관리 | 보드 갱신 커밋이 병렬 브랜치마다 충돌       |
| 루트에 모든 규칙 집중        | 매 세션 수천 토큰 낭비, 무관한 규칙 노출    |
| 리뷰 "전원 approve"까지 반복 | 수렴 보장 없음, Nit 논쟁으로 지연           |

## 결과

- 좋은 점: 커밋 이력이 사람 명의로 일관, 충돌 최소화, 세션당 컨텍스트 예측 가능, 리뷰 종료가 기계적으로 판정됨.
- 감수하는 점: 스크립트/훅 유지비, 티켓 작성 부담(오케스트레이터), `.worktrees/` 로컬 상태가 백업되지 않음.

## 지켜야 할 규칙

1. 이 ADR의 결정을 바꾸려면 새 ADR + CLAUDE.md·AGENTS.md·해당 컨벤션 문서·스크립트를 같은 PR에서 갱신.
2. `scripts/check-*.sh`가 실패하는 PR은 리뷰를 시작하지 않는다.
